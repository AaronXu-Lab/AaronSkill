# 交互式流程画布工作流

本文为执行事实源，`workflow.svg` 为面向人的可视化投影。目标是在同一画布中并列操作真实 Modal、Sheet、Dialog，审查流程及分支，并用评论迭代可复用组件。适用于多弹层业务设计，不限定连接器或技术栈。

## 选择执行范围

沿用完整会话中的范围和授权。先读取项目约定、现有画布就绪记录及相关路由；不要以目录存在推断环境可用。

- **仅初始化环境**：进入 [初始化模块](../references/initialization.md)，完成就绪记录与基础交互验收后交付，不自动设计业务。
- **新建或扩展业务画布**：快速核实当前环境能力；满足需求则跳过初始化，仅在缺失或失效时进入初始化模块补齐。随后执行下列业务阶段。
- **局部评论修改**：沿稳定节点 ID 定位相关组件、场景和入口，只读受影响资料；扩展状态、路由或隔离机制时才扩大检查。
- **应用到业务**：先核实用户是否已明确要求迁移，再进入 [评论与迁移模块](../references/iteration-and-migration.md)。画布认可本身不构成迁移授权。

## 1. 建立业务事实与覆盖模型

读取 [流程建模](../references/modeling.md)。从实际路由、触发按钮、调用方、组件和条件追踪可达链路，记录正在使用、不可达旧代码及尚待核实的内容。不得仅凭画布枚举或文件名认定业务已覆盖。

产出入口—场景—组件—节点—边的覆盖表；每项标明证据、变更类别（新增、修改、复用）和期望行为。只纳入实际存在或本次明确要求的新状态，区分事实与提议。缺失事实时继续独立可做部分；仅阻塞依赖该事实的设计，不虚构分支。

## 2. 在就绪环境中实现与设计

读取 [组件预览与场景设计](../references/component-design.md)。节点挂载实际组件，用场景参数和隔离适配承载不同状态；入口、判断、结果可用语义节点，无实际 UI 的节点不伪造弹窗。优先复用设计系统与已审阅组件。

实现覆盖模型中的交互与状态，校准内容高度、字段语义、步骤与操作结果。项目 Fake/演示规则适用时读取并使用可用的 aw-design-fake；中文 UI 文案适用时读取并使用可用的 aw-wording-reviewer。缺少这些 Skill 时沿项目现有规则执行同等范围的隔离或文案检查，报告未使用专门审查；不能建立可靠无副作用预览则停止运行该场景。

画布实现和验证属于设计请求范围；除非用户要求阶段评审，完成第一版后继续自查与修复，不等待默认确认。

## 3. 评论驱动迭代

读取 [评论与迁移](../references/iteration-and-migration.md)。将评论绑定到稳定节点、场景和组件；修改后回读对应节点及其上下游，记录处理状态与证据。没有原生评论能力时可用项目内结构化记录承载，不强制安装协作服务。

将新增发现回填覆盖表，逐个核对实际业务场景和入口；不能只完成评论列表便宣布业务覆盖完成。

## 4. 验证与设计交付

按 [验收矩阵](../references/verification.md) 执行受影响范围的浏览器交互检查及项目适用的类型、lint、构建或测试。新环境需完整基础验收，成熟环境局部设计只回归受影响能力。必要检查失败时修复并重验；若受环境、事实或权限阻塞，交付可用部分及明确未通过项，不宣称完成。

交付画布与预览入口、覆盖表、组件复用关系、评论状态和检查证据，说明未覆盖与未验证项。收尾清理本次验证创建的临时文件、命名浏览器会话和进程；保留正式画布、评论和验收证据。

## 5. 按授权迁移并验收

若用户未要求应用到业务，设计交付即完成当前范围。若明确要求迁移，复用已审阅组件接入实际入口，按迁移模块处理状态编排与业务适配，再核对覆盖表和验收矩阵。迁移中发现新的生产副作用或范围外操作时仅暂停该动作，明确所需授权；完整会话已授权的内容不重复询问。

最终交付区分“画布设计已验证”与“业务入口已接入并验证”。画布通过不能替代真实入口验收。
