# 画布呈现规范

实现或调整画布外壳、节点卡片、目录、视口控件与图例时读取。生成新画布时先复制 [canvas-kit](../assets/canvas-kit/)，再填流程数据：视觉以其 HTML 标准件为准（可直接用浏览器打开逐项对照），逻辑以 `reference/` 为参考，按[执行工作流](workflow.md#0-前置核实可复用的画布能力)复用项目现有技术栈与版本。项目有设计系统时，把 kit 的 `--ck-*` token 映射到项目 token，并用其组件实现同等效果。可读性以默认打开后的截图判断，不以代码结构判断。

## 流程与方向

- 每条流程有明确入口，首个节点位于分区左上，读者无需追线即可看出主路径从左到右推进。无入边的节点必须是另一入口并带入口标记，不能孤立摆放。
- 流程层级和颗粒度按 [流程建模](modeling.md#图与组件的映射)：最多两级，以业务段落为单位，同一页面的多种结果合成场景切换。

## 目录

- 流程导航用左侧目录，复用项目设计系统的侧边栏组件，按其 Gallery 或文档站侧栏的组合方式搭建；不自写树、分段控件和底部按钮区。
- 面板配方与设计系统的侧栏一致：凹陷底色、大圆角、无描边，投影只用最淡一档；头部按钮的位置和左右边距与侧栏规范对齐。
- 目录浮在画布上，不挤占布局，可以整体收起：头部左侧为“收起目录”，收起后在同一位置出现“展开目录”；面板保持挂载并设为不可交互，平移淡出。收起或展开后画布重新适配视口。
- 分组标题（如“流程”“连线”）可收起。有子流程的顶层流程是一个可折叠分组（文件夹图标 + 数量），父流程本身作为分组里的第一项，与子流程同级缩进。当前流程用底色标出，不能只改文字颜色。
- 当前位置只由目录选中态表达，不再用标签页或画布内面包屑重复；回父流程通过目录。
- 目录只放导航和预览入口：头部右侧只有“单独预览”；不放返回业务页、画布说明这类内容。筛选组的默认项放第一位，例如连线筛选为“全部 / 主路径 / 仅异常分支”。

## 画布与视口

- 画布底色用中性淡灰（约 #fafafa），不用偏蓝的灰；主题缺少中性灰 token 时，在设计系统中补充。
- 点阵用画布库自带的背景组件，随平移缩放；点阵要轻，例如间距约 27 个画布单位、点色约 6% 黑。不用固定的 CSS 背景图。
- 视口与布局操作统一放在右下角控件组：放大、缩小、适配全图（Shift+1）、缩放到选中卡片（Shift+2，未选中时置灰）、重置布局（无手动调整时置灰）。快捷键参考 Figma，写在按钮提示里；节点内不放“放大”按钮。
- 默认视口完整适配当前流程，先让读者看清结构；页面内容通过“缩放到选中卡片”阅读。全图字号只作参考值并记录在验收数据中，不作为拆分流程或缩小卡片标题的理由。
- 画布根节点不设高于设计系统浮层（Dialog、Popover 等）的 z-index，用 `isolation: isolate` 隔离内部层级，保证卡片里打开的 Dialog 在画布之上。
- 图例、控件组、目录互不重叠，也不盖住节点；适配视图时为它们预留边距。

## 页面卡片

卡片分为顶栏、预览、底栏三段，上下平衡：

- **顶栏**：标题约 16px、单行，放不下时截断并在悬停时显示全名。右侧是次要图标按钮：有说明时 info 在左，“重置场景”在右。
- **说明**：不在卡片里展开；点 info 打开 Dialog，只有一个“知道了”按钮。
- **重置场景**：通知预览页回到节点场景，不重新载入预览；预览下方不放状态行。
- **预览区**：中性浅灰底，预览本身透明，不垫白底、不套内框。卡片宽度随预览内容撑开（至少约 240px），宽页面不能溢出卡片；顶栏和底栏不参与撑宽，长标题照样截断。预览里不显示全局演示或调试入口（如演示模拟浮动按钮）。
- **底栏**：场景切换（描边小按钮）和出口。
- **描边与入口**：卡片描边用最浅一档线色。入口标记是卡片外上方的一枚白底小旗，带强调色圆点，如“入口 · 忘记密码”，不占卡片主体。
- **拖动命中区**：标题栏用于拖动时，内部按钮等控件必须排除在拖动捕获之外，否则控件要点两次。
- **视觉权重**：页面卡片 > 判断节点 > 引用节点 > 说明节点。

## 出口

- 只列有去向的返回、取消和关闭；页面里一眼能懂的原地操作（重新发送、刷新状态、联系管理员）不列，也不加说明。
- 出口不画常驻线，做成底栏里的小控件。去向在当前流程时，悬停临时画一条强调色虚线，从本卡片左侧接到目标卡片右侧，目标描虚线框，其余连线淡化；去向在其他流程时，悬停用提示说明“回到 {流程} 的「{页面}」”。

## 判断、引用与说明节点

- 判断节点没有预览，判断依据直接写在标题下，不放进 info；只写分流的时机与依据，不重复出边标签已经写明的去向，避免把节点撑高、破坏连线指标。
- 引用节点和说明节点压缩为单行，尺寸明显小于页面卡片；说明正文默认折叠。
- 单行节点不能为了入边端口被撑高：有多条不同条件的入边时，第一条从左侧基线进入，其余从底边进入。不同标签的入边不合并到同一端口，否则会形成带两个标签的合并主干和过近的平行线。

## 连线与标签

- 每条边有清晰箭头，线宽与对比度在点阵上可辨；标签有底色，贴在所属线段上、靠近目标的末段，不在拐点或交汇处堆叠。
- 主路径与分支标签使用同一套样式，只用字重或颜色区分层级，例如主路径加粗深色、分支灰色、异常分支红色。
- 拖动节点后不重新计算路线，只在布局路线上平移首末段：首点随源节点偏移，第二点只沿首段方向跟随（横段改 y、竖段改 x）；末点随目标节点偏移，倒数第二点同理；中间拐点不动；原本是直线（2 点）的在中点补两个拐点保持正交；标签框随目标偏移。扇出主干、同条件汇入的末段、端口位置与进入方向和标签位置因此都保持；不要退回阶梯线或节点边中点重新连线。本来没有标签的合并边，拖动后也不补标签。

## 图例与验收数据

- 图例只占一行、只解释图形，分为“节点”“连线”两组，用细竖线分隔，可以收起。卡片上自带文字的标记（入口、返回）不进图例；快捷键写在控件的按钮提示里。
- 连线指标和全图字号等验收数据不在界面上展示，写在画板根节点的 `data-checks` 等属性上供脚本读取。

## 加载

- 节点未渲染完成时显示标题和骨架，不显示空白框；在收到预览的首次尺寸上报后再撤掉骨架。
- 想加快加载时，优先让预览使用轻量的独立入口页，避免每个预览都启动整个应用。不要用父级 `visibility: hidden` 保留已访问流程的节点：画布库可能在节点上写行内 `visibility`，导致其他流程的卡片透出来。
