# 实际组件预览与场景设计

实现或调整节点或平铺条目内容时读取。环境层的隔离和拖拽机制见初始化模块，此处只定义业务组件与场景质量。节点卡片的外壳（顶栏、预览区、底栏的场景切换；出口和入口小旗仅流程模式适用）以 [canvas-kit](../assets/canvas-kit/) 为视觉与交互标准，规则见 [画布呈现规范](canvas-presentation.md)；项目有设计系统时用其组件与 token 实现同等效果。卡片预览里不显示全局演示或调试入口。

## 复用与演示边界

执行[共享展示契约](workflow.md#从初始化建立同一套展示代码)：节点和实际页面直接引用同一展示组件与样式，通过 props、适配器或依赖注入切换真实数据与隔离场景。新增布局、字段、文案及视觉状态写在共享展示层，不能在预览适配器中重写同一表单或用预览专属 CSS 覆盖来掩盖差异。实际入口的请求与导航留在业务控制器；无实际对应的新设计使用唯一展示实现并记录待接入，不提前接通业务副作用。

真实交互预览的输入、选择、按钮禁用/校验、菜单、帮助链接、关闭和重新打开均要可操作。演示结果由确定的场景输入驱动，重开是否清空/保留由业务语义决定；用明确重置恢复初始场景，不能让前次预览污染其他节点。

遵守项目 Fake/演示开关与共享数据约定；适用且可用时使用 aw-design-fake。对认证 SDK、网络 client、表单 action、导航和回调逐项确认隔离，阻断真实授权、凭证提交、账号修改及业务写入。使用合成数据，不从现有会话读取秘密充当 fixture。检查演示关闭状态。文档链接可保留真实安全地址；授权按钮不能因名字像链接就放行真实授权。

## 每个场景单独设计

- 字段含义、标签、必填标识、帮助说明、默认值、校验时机和报错位置依据当前场景，不统一套同一表单。
- URL 用合适输入与格式校验，密码用隐藏输入及项目允许的显隐控件，多行内容用文本域，枚举用选择组件；不要把 token、URL、JSON、说明文本全部当作普通单行字符串。
- 核对文档链接目标、外链反馈、主次按钮、危险/取消操作、加载与不可用原因及最终结果说明。中文文案适用且可用时使用 aw-wording-reviewer，沿用当前修改授权。
- 弹窗随内容自然增高；达到视口/项目上限后仅内容区纵向滚动，标题和操作区保持可见。检查容器最小尺寸、长文本换行、选择菜单、校验信息和窄视口，避免横向溢出及嵌套双滚动。不要用固定高度裁掉真实内容来整理画布。

## 预览视口与稳定尺寸

两种模式使用 iframe 或独立视口时均适用。尺寸桥接需区分“原组件内容边界”“预览渲染视口”和“外部缩略图尺度”，不能把内容矩形直接当作响应式视口。

- 初始 iframe 宽度依据原组件声明宽度、min-width 和实际响应式约束，加上该断点的左右留白；高度同样考虑上下留白、标题、操作区及最大高度规则。先给出不压缩声明宽度的渲染视口，再测量；平铺卡片槽位不足时扩大槽位，保留流程单行并允许横向平移，外部统一缩放，不把渲染视口压窄。
- 检查组件实际 CSS/样式：固定 px、百分比、`vw/vh`、`calc`、断点留白、max-height、Sheet 锚定及过渡。仅当容器无视口依赖时才可直接使用内容尺寸；需回算时按同一响应式规则求得视口。例如内容宽度为视口的 90% 时应除以 0.9，不能每次加固定 24px 后反复收缩。这是规则示例，不是所有弹层的比例。
- 避免“测量被当前 iframe 压缩的内容 → 缩小 iframe → 再测量”的反馈循环。尺寸桥接用受控测量壳、声明尺寸或经验证的求解/限界方案，校验 origin、source、有限正尺寸及实例；遇到不收敛保留最后安全视口、报告缺口，不能反复抖动或用最小值遮掩裁切。参考 kit 的原始内容尺寸桥接只适用无视口依赖的壳，响应式弹层必须适配。
- 首次尺寸消息只证明收到测量，不证明完成。等待字体、内容与进入动画就绪，对 iframe 视口和组件矩形的宽、高连续采样确认稳定；可从 3 次采样、每次间隔 150ms、容差 1px 起调，稳定窗口必须覆盖已知过渡。设定有界超时；超时、不停缩小或来回振荡均记为失败。动态场景切换、校验增高、重置、窄/宽视口后重新等待，不无限阻塞其他条目。
- 稳定后验证声明宽度未在初始视口被压缩、内容完整、底部操作可见/可滚动到并可点击、滚动归属正确、Sheet 未裁切，重复进入/重置仍保持尺寸。分别记录视口尺寸、内容尺寸和外部缩放；瞬时几何通过或截一张图不足以通过此项。

## 多步骤与授权能力（仅相应业务读取此节）

多 Step Circle 可承载授权、连接或其他分步任务；步骤数量、名称、解释、等待态、完成依据和退出语义由每个业务对象实际能力决定。将能力证据映射到场景配置，不用一个泛化 OAuth 模板覆盖所有对象，也不把点击下一步视为真实服务完成。

二维码只在确有支持依据的分支出现；源案例把二维码放在 Circle 上方，这是条件成立时的布局参考，不是所有 OAuth 的功能承诺。预览二维码使用无授权作用的演示内容。未知能力标为待核实，不默认为支持；不支持时使用其实际授权路径。
