# 设计平铺建模与比较

收集、对齐或并列比较真实页面、Dialog、Sheet 等设计时读取。此模式以条目清单和比较集合为事实源，不以流程图为事实源；业务关系需要另外进入 [流程建模](modeling.md)。

## 盘点与覆盖

从实际组件导出、调用方、动态注册及相关路由盘点；引用可达只证明源码链路，不能证明组件已可操作。定义扫描、收集与排除范围，记录未进入引用链、工具弹窗及尚未核实项，避免把一个入口的结果说成整个项目。旧代码不自动删除。

清单至少包含：

| 类型/业务模块/行 ID | 稳定条目 ID / 场景 ID | 组件及源码位置 | 实际调用方/引用证据 | 当前/提议/旧代码 | 预览能力及缺口 | 独立查看入口 | 交互验证状态/证据 |
| --- | --- | --- | --- | --- | --- | --- | --- |

- **源码记录 `source-only`**：可查看组件定义、引用证据、场景说明和缺口；没有可操作原组件预览时清楚标明原因。不显示假表单、截图或代表组件冒充它的真实交互，不提供无效重置。
- **真实交互预览 `interactive`**：引用原展示组件和样式、注入隔离场景，可独立操作、重置及直达。具备此能力仍不等于交互已经验证，验证状态另列。
- 分别报告“收集条目数”“可操作原组件预览条目数”“已验证条目/场景数”，注明各自分母、扫描范围与排除项。源码定义、引用可达、场景和预览实例不能混用计数单位；一个组件有多个场景时维持组件—场景映射。
- 所有已收集条目必须逐项可查看，包括源码记录。可分页、搜索、按需挂载或虚拟化，模块目录和清单仍保留完整集合、计数及稳定定位；代表场景只是样本，写明筛选条件及未预览列表，不能以少量样本替代全部收集条目。

## 模型与场景

平铺集合包含稳定 ID、国际化标题、组件类型 Section Group、业务模块和行列表。类型组下是直接的模块项，不是弹层实例；每个模块含相关步骤/场景行，每行明确条目 ID 顺序、顺序证据及核实状态。条目包含组件 ID、场景 ID、所属模块、来源与可达证据、能力判别及验证状态；真实预览额外定义目标场景、声明/最小视口尺寸与响应式规则，源码记录额外定义缺口。参考 [tiles.ts](../assets/canvas-kit/reference/tiles.ts) 与 [tiles.example.ts](../assets/canvas-kit/reference/tiles.example.ts)。

模型不含业务边、入口旗、判断、流程出口、图层级或泳道。这里的“一个流程一行”是平铺比较中的一组相关步骤/场景：在有源码调用、业务定义或本次明确设计依据时，组件按真实前后关系从左到右排列；顺序本身不自动生成连线。没有依据不虚构步骤，独立场景可单卡成行，待核实顺序明确标为“顺序待核实”，不能把扫描顺序当作业务先后。原组件自己的取消、关闭、提交按钮继续在隔离适配器中工作，不添加卡片级“回到另一条目”流程出口。

同一类型组内用业务模块组织（例如文件空间、知识库、自动任务），模块项直接进入模块的行视图；按明确模块/行顺序排列，排序依据可追溯。条目 ID 不使用标题、位置或目录序号，重排、筛选、切语言后仍可定位。比较实际存在的长内容、错误、加载、尺寸或布局变体时，可作为有说明的比较行并列；若使用场景切换，每个场景有明确标签、清单行及逐项查看入口，切换不能让覆盖消失。流程模式合并场景的惯例不限制平铺并列比较。

## 布局与比较尺度

- 使用有序行列平铺或等价行布局，以卡片实测尺寸计算槽位。打开一个模块后，每个流程/相关场景组独占一行，从左到右排列，行从上到下阅读；独立场景可单卡成行。列宽至少容纳该列最大卡片，行高容纳该行最大卡片，不自动换行把同一流程拆成多行，不用瀑布流打散同行比较基准。参考 `layoutTiles` 是独立的平铺计算器，无 ELK、边路由或端口输入。
- 明确类型组、业务模块、行顺序、横/纵间距、模块/分组间距及对齐基准。无项目标准时，可从横/纵 32、分组 64 个画布单位起调；数据中记录实际采用值。默认卡片顶端、同高标题栏及预览区顶端对齐；比较弹层内容时同时核对组件实际内容边界，保留原响应式留白，不为对齐改写原组件。手动拖拽是临时偏移，重置恢复稳定排列与间距，不清空预览输入。
- 同一比较组使用同一预览缩放比例，保留组件真实尺寸差异；禁止按每张卡片可用宽度各自拉伸或缩小，造成尺寸看似一致。比较缩放是外部视觉 transform，iframe 内按声明的响应式视口渲染；宽页面扩大槽位，保留该流程单行并允许横向平移，不以初始窄 iframe 挤压组件声明宽度。
- 记录预览比例与画布缩放，实际屏幕尺度是两者乘积。默认打开当前模块或相关比较行并保持标题及主要内容可读；大量条目不必首屏 fit-all 到无法阅读，可按模块或完整行分页并保留“适配全图”。“缩放到选中”及单条目独立预览提供实际尺寸阅读。用户已缩放、拖动或输入后，尺寸上报不反复抢视口。
- 标题使用组件/页面名称及有区分度的场景标签，单行截断时可查看全名；来源、能力状态和验证缺口可在说明/记录中查看。源码记录明确显示能力标签，不与加载骨架混淆；加载失败保留条目和失败信息。

## 目录与入口

目录按组件类型使用独立的 **Sidebar Section Group**（如 Dialog、Sheet）；每个 Section Group 下直接使用 **Sidebar Item**，单位是业务模块（如文件空间、知识库、自动任务），不使用文件夹、嵌套分组或折叠树，不把每个弹层实例放成主目录项。Sheet 独立于 Dialog。同一个业务模块可在相应类型组下各有直接项，用稳定 ID 区分。

这些名称描述侧栏组合语义；先核实项目实际导出，没有同名 API 时复用已有的 Section/Header/Item 等组合实现，不能虚构 `SidebarSectionGroup` 导入。主目录不显示流程连线筛选、流程面包屑或连线图例。

每个模块项打开其完整行视图；其中每个已收集条目都有可搜索/清单定位项及独立查看入口（不增加实例级主目录层），标明源码记录/交互预览能力；集合总数、筛选后数量和预览数量区分。点击条目定位卡片并保留输入焦点；源码记录打开证据，真实预览打开其独立入口。当前业务模块由目录选中态表达，卡片选中态表达当前条目。

沿用项目业务路由下的画布；可采用 `?mode=tiles&module={id}` 和稳定的 `?item={id}`。`?item=` 在平铺模式只显示指定原组件场景或源码记录，隐藏其他条目和画布；刷新、切语言和未知 ID 均有可观察结果，未知 ID 显示空态及可用条目/返回入口。已有路由契约可适配，不改变已使用的流程 `?preview={name}` 含义。混合视图通过模式参数或明确的视图入口区分。

## 验收与完成

执行 [验收矩阵](verification.md) 的共用项与平铺项；流程端口、入边可达和连线指标不适用。遍历清单核对全部收集条目都可查看；逐项显示能力状态，对本次新增/改变的真实预览验证交互、稳定尺寸、滚动及底部操作。原有未预览项可作为明确记录交付，不把它们标为预览已验证；若用户要求全部真实预览，缺口就是未完成项，不能将降低范围当作完成。
