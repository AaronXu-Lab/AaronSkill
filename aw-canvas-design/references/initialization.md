# 画布环境初始化（独立模块）

仅初始化、现有环境缺失能力、环境变更导致能力失效时读取。这个模块负责承载能力，不负责业务分支、字段设计或评论内容。可单独执行并交付；业务设计通过就绪记录消费其结果。

## 检测、复用与增量补齐

检查项目约定、包清单与锁文件、现有画布路由、节点/边注册、预览入口、Fake 开关、布局和验收记录。对下列能力逐项记为“已验证可复用 / 缺失 / 失效 / 本次不适用”，附路径或验证证据。已有记录需核对相关依赖、路由和组件接口是否变化；有效证据可以复用，不重复初始化。

依赖选型按[执行工作流](workflow.md#0-前置核实可复用的画布能力)复用项目现有能力；`canvas-kit` 的 React、`@xyflow/react`、`elkjs` 版本只是参考，不要求项目对齐。优先顺序是现有画布能力 → 现有依赖与项目基础设施 → 为确定缺口引入最小依赖，并遵守项目包管理、兼容性和许可约定。只修补本次所需缺口，保留现有路由、布局和用户改动。

## 基础能力清单

| 能力 | 实施与通过条件 |
| --- | --- |
| 画布路由 | 画布挂在所属业务页面路由下，形如 `/<业务路由>/design-canvas`（如 `/login/design-canvas`，叠加项目 base path 或 hash 路由前缀），不用顶层共享路由，不另起端口或独立站点；已有画布在其他路径时迁到此处，旧地址全部重定向并原样保留 query，节点预览（如 iframe）的地址同步改到新路径。遵循项目演示开关，不替换业务入口 |
| 单流程预览 | `/<业务路由>/design-canvas?preview={name}` 只渲染该流程，隐藏画布、连线与其他流程；从流程入口起以实际尺寸和真实组件逐步操作，打开、下一步、取消、完成按边定义衔接。`name` 为注册表中稳定的 kebab-case 流程 ID，可直达、刷新、返回；无参数显示完整画布，未知名称给出空态并列出可用名称及返回画布入口。画布中每个流程提供打开其预览的入口 |
| 节点与边 | 定义稳定节点 ID、所属流程、预览场景、变更类别、层级（列）与泳道；边具有稳定 ID、源/目标及端口、触发条件和标签。注册 UI 节点与语义节点，边描述流程而非默认允许用户改业务关系。按 [连线精简](#连线精简) 区分画线边与节点出口 |
| 预览隔离 | 每实例独立状态和生命周期；Portal、遮罩、焦点陷阱、Esc、滚动锁局限于预览视口；输入、菜单、按钮校验和关闭重开可用。共享主题与组件，隔离可变 store、定时器和演示持久化命名空间 |
| 视口控制 | 右下角控件组提供放大、缩小、适配全图（Shift+1）、缩放到选中卡片（Shift+2）和重置布局，不可用时置灰；区分重置布局、重置视口和卡片上的重置场景，避免隐式清除输入。内容滚动不变成画布平移，输入快捷键不触发画布操作 |
| 拖拽 | 拖拽只在自动布局结果上微调偏移，不改变节点所在列和泳道；重新布局时保留或明确重置偏移。仅标题命中区可拖，标题中的按钮和链接必须排除在指针捕获之外（如 nodrag），否则要点两次；拖动后只在布局路线上平移首末段（见 [画布呈现规范](canvas-presentation.md#连线与标签)），不重新计算路线；内容区域禁止节点拖拽和平移。支持缩放后的正确坐标换算；跨 iframe 用标题上的可靠 pointer capture 或等价机制，处理 pointerup、pointercancel、lost capture、卸载并清理监听器 |
| 聚焦 | 点击节点或预览内部选中当前节点、突出相邻边并淡化无关边；不抢输入焦点，不在输入时反复移动视口；需要移到可见位置时使用独立聚焦动作或首次选择。点击空白恢复全部连线 |
| 分层布局 | 按 [分层布局](#分层布局) 用成熟布局引擎统一计算节点位置与正交路由，输入实测节点尺寸和固定端口；节点拖动、内容变化、字体加载及尺寸更新后重新布局或重新路由。未测量尺寸只能暂用估计，测量后必须替换 |
| 连线显示 | 默认“全部”，主路径加粗高亮、分支淡化；筛选依次为“全部 / 主路径 / 仅异常分支”。选中节点高亮其相邻边，点击空白恢复当前筛选 |
| 标签和降级 | 标签放在布局引擎给出的边标签位置，并检测与节点、其他标签碰撞。达不到 [连线指标](#连线指标) 时先精简连线、调整端口；不能静默画穿弹窗的线冒充通过 |

## 连线精简

只为前进步骤画线：主路径和有业务依据的分支。以下不画常驻线：

- 有去向的取消、关闭、返回：做成卡片底栏里的出口控件，悬停时临时显示去向，见 [画布呈现规范](canvas-presentation.md#出口)。
- 重新发送、刷新状态等页面内一眼能懂的原地操作：不画线，也不列出口。
- 同一对节点之间的多条边合并为一条，标签列出各条件。
- 终态结果（完成、失败）以短边接到节点右侧的结果节点；多个节点走向同一结果时，优先各流程只保留一个结果节点，不从每个节点拉长线；复制条件同下方跨流程引用。

出口和边同属流程模型，仍需在覆盖表记录并验收。

## 分层布局

- 每条流程独占一个分区，流程之间不连线。同一组件被多条流程使用时，在各流程内各放一个节点实例，不共享节点跨区连线。
- 流程内主路径占第一条泳道，按步骤顺序分列，节点顶端对齐在同一水平基线上，主路径边是一条不拐弯的直线；相邻主路径节点之间不插入只属于分支的列，避免主路径边跨列绕行。分支放在其下方泳道，与分叉点对齐列。
- 一个节点有 3 条及以上出边时，目标节点在下一列紧凑堆叠，垂直方向以源节点为中心；这些边从同一端口共用一条主干，在各目标前分叉，标签写在分叉后的末段。不要画成多条平行长线组成的“梳子”。
- 分支边从源节点独立的分支端口（底部或右侧下半部）出发，不从主路径边的中途分出；读者必须能一眼看出分支属于哪个节点，而不是像从某条边或其标签上长出来。
- 多个源以相同条件汇入同一目标时，合并为一条入边主干，只保留一个标签，不画成两条平行线加两个重复标签。不同条件的入边不合并到同一端口；单行节点的第一条入边从左侧基线进入，其余从底边进入。
- 同一流程内同一跨流程目标只放一个引用节点，多个触发点汇入它；只有汇入会产生回指边、穿过节点、超过 2 个拐点，或迫使分支列插入主路径时才复制实例；复制的实例标题相同，不为区分而改名。
- 所有画线边从左到右；回指边一律按连线精简改为出口。
- 布局优先复用项目现有且能满足连线指标的成熟引擎；`canvas-kit` 的 `reference/layout.ts` 展示 ELK layered、正交路由与固定端口的参考配置。若现有方案达不到指标，再按本次缺口选择或调整引擎；不手写脆弱的全局布局与避障算法。

## 连线指标

每条流程需满足：主路径零交叉；边不穿过任何节点；标签之间、标签与节点零重叠；每条边最多 2 个拐点；无从右向左的边；除同源扇出的共用主干外，不同边不共用线段，平行段间距至少 12px。达不到时先检查是否有应改为出口的边，再调整端口分配和同一页面的场景合并；流程已按业务段落划分到两级时，不为指标继续拆分，把剩余差距记入就绪记录。全图字号只作参考值，与指标一起写在画板根节点的 `data-checks` 等属性上，不在界面上展示。

## 画布呈现

卡片、目录、视口控件、图例、出口和加载的视觉与交互规则见 [画布呈现规范](canvas-presentation.md)，以 [canvas-kit](../assets/canvas-kit/) 为标准件。初始化新画布时先复制 canvas-kit，按其 README 映射 token、换成设计系统组件，再接入流程数据；已有画布只按 kit 补齐缺口。

## 隔离实现选择

可用独立文档/iframe 获得独立视口，或在现有运行环境使用独立根、受控 Portal 容器与焦点管理。后者必须实际验证焦点陷阱和全局滚动锁不互相干扰，单纯把组件包进 div 不等于隔离。

使用 iframe 时：保证主题与资源正常载入；同源可桥接选择与尺寸事件，跨源使用经过 origin、source、消息类型及场景实例 ID 校验的消息协议，禁止任意代码消息。设置 title，按需求收紧权限；iframe 本身不能保证请求无副作用。拖拽时不永久覆盖预览或禁用其指针事件。重复载入和卸载均清理桥接监听。

## 就绪记录与出口

在目标项目沿用已有文档位置，无约定时采用画布目录旁的环境记录，包含：

- `/<业务路由>/design-canvas` 路由挂载位置、流程注册表及可用 `preview` 名称；实际采用的画布、布局与图标依赖版本，以及本次新增依赖的授权记录。
- 节点、边、场景适配器、主题和 Fake 入口的路径与接口。
- 上表能力状态、缺口、本次补齐项、验收证据及适用版本/变更范围。
- 重置语义、隔离方案、临时资源清理结果、需重新初始化检查的变更条件。

以两个同时打开且可独立输入和关闭重开的实际组件实例完成冒烟，覆盖跨预览拖动、动态高度后重新布局并满足连线指标、视口控制、`?preview=` 直达与刷新及无副作用。可复用项目已有实例，不为初始化编造业务流程。

必要能力通过则标记 ready 并返回业务流程；只要求初始化时直接交付。失败可在已授权本地范围修复；隔离无法保证、依赖缺失或运行条件不可用时标记 blocked 并报告具体缺口。禁止删除重建整套画布作为默认恢复方式。
