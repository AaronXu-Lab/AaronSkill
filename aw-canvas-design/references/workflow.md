# 交互式画布工作流

本文为执行事实源，`workflow.svg` 为面向人的可视化投影。目标是在同一画布中操作真实页面、Modal、Sheet、Dialog，按审查意图选择流程模式或设计平铺模式。画布挂在所属业务页面路由下，形如 `/<业务路由>/design-canvas`；它是 Step 1 的设计整理与评审工具，不是业务正式页面。Step 2 仅在用户明确要求时，把已审阅设计接入实际业务入口。

## 按意图选择模式

| 模式 | 选择条件 | 模型、布局与目录 | 验收 |
| --- | --- | --- | --- |
| 流程 `flow` | 查看业务步骤、状态转移、分支与结果，回答“从哪里来、操作后去哪里” | 入口—场景—组件—节点—边覆盖表；有依据的判断、连线及出口；适用的 ELK 分层流程布局；目录按流程/子流程组织 | 入口可达、操作与边一致、连线指标与流程覆盖 |
| 设计平铺 `tiles` | 收集页面或弹层、并列比较设计，回答“有哪些、哪里不同、怎样对齐” | 独立条目和场景清单，区分源码记录与真实交互预览；有序逐行平铺；类型 Section Group 下直接用业务模块 Sidebar Item，模块内每组相关步骤一行，条目逐项可达 | 全部收集条目可查看、比较尺度与对齐、真实预览稳定尺寸及交互覆盖 |

模式由任务意图决定，不由组件种类或有没有连线决定。收集 Dialog/Sheet 制定统一规则属于设计平铺；检查一组 Dialog 的业务分支属于流程。平铺不是把流程图的 `edges` 清空后继续使用流程布局，不创建无业务依据的关系、入口旗、判断或流程出口。流程保留已有有效的节点和连线规则。

混合任务可在同一工具中提供两个有明确边界的视图，标明各自目的、条目/节点 ID 映射与覆盖范围；切换视图不把条目顺序变成业务关系，验收分别执行。已有授权和明确意图直接沿用，无需为模式选择或共用基础能力重复确认。

## 选择执行范围

沿用完整会话中的范围和授权。先读取项目约定、现有画布就绪记录及相关路由；不要以目录存在推断环境可用。

- **仅初始化环境**：进入 [初始化模块](initialization.md)，完成就绪记录与基础交互验收后交付，不自动设计业务。
- **新建或扩展画布**：快速核实当前环境能力；满足需求则跳过初始化，仅在缺失或失效时进入初始化模块补齐。按所选模式执行下列阶段。
- **局部评论修改**：沿稳定节点 ID 定位相关组件、场景和入口，只读受影响资料；扩展状态、路由或隔离机制时才扩大检查。
- **应用到业务**：先核实用户是否已明确要求迁移，再进入 [评论与迁移模块](iteration-and-migration.md)。画布认可本身不构成迁移授权。

## 0. 前置：核实可复用的画布能力

先看现有画布的就绪记录、实际运行能力及项目清单／锁文件。局部评论或业务入口修改只核对受影响能力；现有画布能完成本次任务时直接沿用，不因依赖版本与参考实现不同而要求升级或阻塞。

- **新建或补齐基础设施**：优先复用项目已经安装且能满足隔离预览、所选模式布局和交互要求；连线仅在流程模式适用的框架与库。`canvas-kit` 的 React、`@xyflow/react` 和 `elkjs` 是参考实现，不是固定技术栈或版本门槛；移植时按项目实际 API 适配。
- **确有能力缺口**：先确认现有依赖和项目设施无法满足；需要安装时按项目包管理约定选择兼容版本，说明目标包、许可、安装命令及锁文件变化，并在引入前取得所需授权。用户已明确授权本次依赖更新时直接执行，不重复询问。
- **无法引入必要依赖**：只暂停依赖该能力的画布实现；仍可完成所选模式建模、组件或实际入口中不依赖它的工作，不用不可靠的静态截图代替交互预览。
- 在就绪记录中写明本项目实际使用的依赖与版本，供复现和后续升级判断；版本不同本身不是失败。

`@phosphor-icons/react` 同样只是参考图标，可用项目现有图标替换。

### 从初始化建立同一套展示代码

画布节点、独立预览（单流程或单条目）和实际业务页面必须引用同一展示组件及其样式，差异只由承载容器、场景参数、数据和回调注入产生。只复用设计系统控件、复制 JSX 或维护两套相似样式不满足此约束；不得先写独立画布 UI，等迁移时再对齐。

初始化时追踪实际入口的组件引用，建立“实际入口 → 共享展示组件 → 画布/预览适配器”的映射。展示层承载布局、字段、文案、视觉状态和通用交互；业务控制器保留真实请求、身份、状态编排和导航，预览适配器提供隔离的场景数据与局部回调，不引入真实副作用。共享范围遵守项目工程边界，不能借复用跨工程导入业务代码。

已有组件混合展示与业务逻辑时，在本次授权范围内提取展示层，并让实际入口与画布共同引用；不改写范围外业务编排。无实际对应的新设计先建立唯一可复用展示组件，记录为“待接入”，实际入口接入仍遵守 Step 2 授权。无法在当前范围完成提取时记录具体缺口，不用复制 UI 代替，也不把该场景标为共享就绪。

就绪证据需包含组件和样式路径、双方引用位置、控制器/适配器边界，以及同一场景输入下的展示一致性验证。已有画布也检查此项，发现双份 UI 时按缺口增量修复；共享组件修改后回归实际页面与受影响画布场景。


## 1. 建立事实与模式覆盖模型

- **流程模式**：读取 [流程建模](modeling.md)，从实际路由、触发按钮、调用方、组件和条件追踪可达链路，产出入口—场景—组件—节点—边覆盖表。边注明画线或出口，保留有依据的入口、判断和结果。
- **设计平铺模式**：读取 [平铺建模与比较](design-tiling.md)，产出集合—条目—组件—场景清单。分别记录源码定义、引用可达证据、可操作原组件预览及交互验证状态；目录按类型 → 业务模块直接导航，不使用文件夹/折叠树；模块内每个流程/相关场景组一行，全部条目可查看，未实现预览不伪装为完成。

两者均标注实际存在、本次提议、旧不可达代码及待核实内容、证据、变更类别和期望行为。缺失事实只阻塞依赖它的部分，不虚构分支或预览覆盖。

## 2. 在就绪环境中实现与设计

实现真实交互预览时读取 [组件预览与场景设计](component-design.md)，执行第 0 节共享展示契约。流程节点挂载实际组件或有依据的语义节点；平铺条目挂载实际组件，源码记录呈现证据及缺口，不用假 UI 冒充原组件。

- **流程布局**：用成熟分层引擎按流程分区、主路径泳道和从左到右的边计算；ELK 参考配置与连线验收见初始化模块。手动拖拽只作微调，不为指标拆出更深流程层级。
- **平铺布局**：按模块内有依据的相关步骤顺序逐行排列，一个流程一行，独立场景可单卡成行，未核实顺序明确标记；以实际卡片尺寸计算槽位、间距和顶端基准；比较缩放作用于已确定的预览视口，不压缩原组件声明宽度。不得调用流程分层布局来排列无关系条目。

新画布复制 [canvas-kit](../assets/canvas-kit/) 中所选模式及共用部分，再填模式数据；HTML 标准件和 `reference/` 的适用范围见 kit README。项目有设计系统时用其组件与 token 实现同等效果，具体规则见 [画布呈现](canvas-presentation.md)。

实现覆盖模型中的交互与状态，按实际响应式留白回算 iframe 视口，等待宽高稳定后检查内容及底部操作。适用且可用时使用 aw-design-fake / aw-wording-reviewer；缺少时沿项目现有规则执行同等范围的隔离或文案检查并报告未使用专门审查。不能建立可靠无副作用预览则停止运行该场景，保留源码记录和缺口。

画布实现、验证和修复属于设计请求范围；除非用户要求阶段评审，第一版后继续自查与修复，不等待默认确认。

## 3. 评论驱动迭代

读取 [评论与迁移](iteration-and-migration.md)。将评论绑定到稳定节点、场景和组件；修改后回读对应节点及其上下游（流程），或对应条目和同组比较场景（平铺），记录处理状态与证据。没有原生评论能力时可用项目内结构化记录承载，不强制安装协作服务。

将新增发现回填覆盖表，逐个核对所选模式的场景和入口/条目；不能只完成评论列表便宣布覆盖完成。

## 4. 验证与设计交付

按 [验收矩阵](verification.md) 执行受影响范围的浏览器交互检查及项目适用的类型、lint、构建或测试。新环境需完整基础验收，成熟环境局部设计只回归受影响能力。必要检查失败时修复并重验；若受环境、事实或权限阻塞，交付可用部分及明确未通过项，不宣称完成。

交付画布与模式入口、流程 `?preview={name}` 或条目 `?item={id}` 独立预览/源码记录入口、模式覆盖清单、组件复用关系、评论状态和检查证据。平铺交付分别报告收集范围、源码记录、可操作预览与已验证交互数量及分母，不将抽样或代表场景冒充完整覆盖；说明未覆盖与未验证项。收尾清理本次验证创建的临时文件、命名浏览器会话和进程；保留正式画布、评论和验收证据。

## 5. 按授权迁移并验收

Step 1 的 `design-canvas` 只交付设计整理结果。若用户未要求应用到业务，到此完成当前范围；若明确要求迁移，Step 2 复用已审阅组件接入实际入口，按迁移模块处理状态编排与业务适配，再核对覆盖表和验收矩阵。迁移中发现新的生产副作用或范围外操作时仅暂停该动作，明确所需授权；完整会话已授权的内容不重复询问。

最终交付区分“画布设计已验证”与“业务入口已接入并验证”。画布通过不能替代真实入口验收。
