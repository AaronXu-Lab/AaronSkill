# 三站评分与证据边界

macOS 开始三站评分优化时读取；执行顺序和停止条件以 [工作流](workflow.md#三站优化评价体系) 为准。以下记录基于 2026-10-13 的页面、可取得的公开脚本与 Codex 内置浏览器（Chrome 155）走查，不是 Safari 回放；页面实现和可用性可能变化，使用时核对当次字段。

| 工具 | 可参考证据与用途 | 本次核查及边界 |
| --- | --- | --- |

## 记录与解释

- 每项记录网站/时间/浏览器、请求目标、原始值、来源与完成状态；分开写“页面宣称”“源码可见实现”“本机实际观测”。静态页面文案不是一次成功检测。
- trace 证明该请求到该域名的出口；不能代表登录、模型调用、桌面进程或全部业务子域名。CORS、浏览器拦截、超时、HTTP错误分别记录；`no-cors` 的不透明响应不能作为状态码成功证据。
- WebRTC 记录已观察到的 STUN 端点和所有有效公网候选，再与相应 HTTP 出口及用户预期比较。`0.0.0.0` 等非公网候选不证明暴露了真实公网；未发现候选也不证明所有UDP路径安全。
- DNS 页显示的是被权威端观测到的递归解析出口，不必等于配置的 DoH 地址或其品牌；供应商、出口国家变化须结合核心解析路径核实。不能仅因显示 Google 而断言 Cloudflare/Quad9 配置失效。
- 本次同一出口在 Net.Coffee 显示77分、CLIS曾显示78分。这些来自不同口径与浏览器，不与此前 Safari/IPKK 的94分构成升降关系，也不是需要盲目继续修改配置的依据。
- 网页用“Claude检测”命名，不证明由 Claude 发起探测或使用同样的计分/风控；不采用站点未经验证的“与官方高度一致”营销说法。
