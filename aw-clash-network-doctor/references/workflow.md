# 执行工作流

本文是执行事实源；[../docs/workflow.svg](../docs/workflow.svg) 是面向人的可视化投影，仅作概览。

## 按目的选择两条线

### 清理

独立按 [Claude 数据清理](workspace-cleanup.md) 执行。先明确工作区、用户主目录或系统应用数据的范围，再扫描分类；只扫描请求停止在清单。清理不触发网络优化、系统时区调整或 IPKK 评分。用户明确扩大扫描范围时可只读检查相应 ~/.claude、用户 Library 或 /Library；不因扫描授权推定删除授权。

### 诊断与优化

网络、DNS、WebRTC、Type64/65、环境一致性及系统时区均属于这条线。单纯解释检测项时直接回答；只诊断请求完成当前范围的只读检查与建议后停止。优化流程为：优化前完整 IPKK 检测 → 只读诊断 → 列出具体调整项 → 用户允许 → 执行获准项 → 优化后完整 IPKK 检测及相关验证 → 对比交付/必要回滚。

先完成可审查的诊断与调整清单；清单逐项列出现状、证据、建议值/动作、预期效果、影响、修改文件或设置、验证方式与恢复方式。用户可以全部、部分批准或拒绝。仅“诊断与优化”的概括请求不跳过这次清单许可；完整会话中已明确批准相同具体项目的许可继续有效，不重复索要。新增项目、改变实际出口偏好或扩大范围需重新列出并取得许可。自动回滚恢复已批准变更的旧状态属于执行步骤。

许可前仅只读诊断和候选草稿；不切节点/TUN、安装候选、刷新缓存、做局部过滤试验或修改系统时区。既有 --check 可能有临时切组等副作用，读取实现后把这些动作纳入待批准项，不能作为只读诊断偷偷执行。得到许可后持续完成实现、相关检查与修复，不在第一版实现后另等确认。

涉及环境一致性、系统语言/区域/定位或 SSH 方案时，按需读取 [环境与 SSH 参考](environment-ssh.md)；SSH 参考不提供默认部署授权。涉及 updater 事务时读取 [事务与验证接口](transaction.md)。

以下阶段均属于诊断与优化线；时区是其中的可选调整项，不再是第三条独立流程。

跨机器交接文档、上次结果和参考脚本不是当前状态证明。检查当前适用目录约定、OS、客户端和核心版本、活动订阅、配置路径、物理接口、控制 API、代理端口、TUN、系统 DNS/代理、节点与组。ClashX Meta 的私有 helper、偏好记录和 URL scheme 只适用于相应客户端；其他环境需适配。API secret、订阅链接、节点凭据只在私有上下文使用，日志和共享报告脱敏。

## 1. 建立本机基线与回滚点

只读记录活动配置及关键状态。获准执行前保存活动 YAML、持久规则、更新脚本和本次涉及的偏好/关键运行状态；记录 SHA-256、文件权限、mode、TUN 与组选择。私有备份目录 0700、敏感文件 0600，脚本按需 0700。区分 Clash 内部 DNS 与 macOS 网络服务的系统 DNS；不要把清缓存描述成修改系统 DNS。

用正常系统网络路径记录 Apple、Cloudflare、Claude、ChatGPT 的基线。优先使用现有基线端点，例如各服务的 `/cdn-cgi/trace`；保持前后 URL、请求方法和环境一致。记录 curl 退出码、HTTP、DNS/TCP/TLS/总耗时。403/429 是 HTTP 层响应，不能直接归因 DNS，亦不能当业务可用证明。在目标设备真实浏览器（macOS Safari；Android 用户实际使用的浏览器）打开 https://ipkk.com/claude-ip-check 获取优化前完整页面基线，等待 DNS/WebRTC 等检测结束、按钮恢复后记录分数。分数为辅助记录，不作为执行授权或成功条件。

前后记录采用相同浏览器及 URL，保存时间、浏览器版本、页面完成状态、信任分数、风险标签、网页/Claude/DNS/WebRTC 出口与地区、系统/浏览器时区和业务可用性；IPKK 未完成或失败时分数写“未取得”并说明原因，不填 --、猜数或引用历史分数代替当前基线。无法取得前测时报告限制并完成其余只读诊断；默认等用户明确允许缺少前测再执行变更。仅改时区也记录前后完整分数，所需业务检查按改动范围选择，不因此重跑无关网络安装。

评分出现波动时记录实际各轮结果与环境差异，不挑最高分，不把分数提高解释成帐号安全提高。

### 按扣分来源选择调整项

将当前标签区分为网络路径（DNS、WebRTC、出口分流）、最终出口 IP 信誉（代理、VPN、滥用记录）和本地环境（时区、语言、字体）。结合真实请求判断原因；网络路径已通过时，不因 IP 信誉或字体扣分继续修改 DNS。

用户以提高分数为目标时，核对当前页面源码、实际标签与完成状态，确认权重、参照出口和计分条件；仅能从总分推算的项标明推断，无法核实的权重记未知。不把历史权重或预计提分写成固定规则。出口信誉标记优先检查最终 IP 的数据来源；更换中转入口但保持最终 IP 不变，不应预期消除其标记。更换最终出口仍需列入调整清单。

环境项按需读取 [环境与 SSH 参考](environment-ssh.md)，先比较预计收益与对日常使用的影响，不为分数默认安装字体、伪造指纹或改动整机设置。

## 2. 区分节点故障与 DNS 故障

私下按节点服务器 hostname/port 分组，不同显示名称不等于独立入口。重复解析与探测；发生失败时，对照正常 TUN、显式 HTTP CONNECT、绑定实际物理接口且绕过 TUN 的入口 TCP，再用隔离核心确认代理握手和 UDP。只有失败或不确定时扩大对照范围。

连接超时预算覆盖 DNS、TCP、TLS 和代理握手；过短预算会制造误判。合理起点为握手 12 秒、单请求 20 秒，按基线调整，不无限增加预算。TCP 通不证明代理/UDP 可用，节点 delay API 失败也需真实请求补证。地址轮换和端口故障不能证明某 DNS 污染；不永久钉死曾经正常的 IP。

无可用入口且没有授权切换路径时，停止安装候选，报告入口阻塞，保留诊断和可用原配置。不要反复盲改 DNS。

## 3. 选择 DNS 与 WebRTC 修复

区分业务解析、直连业务解析、节点 hostname 引导解析。明确“非大陆 DNS”覆盖范围：业务 DNS 境外不等于所有系统查询与节点引导都境外。按任务测试 Cloudflare、Quad9 或其他合适端点的直连与代理路径。DoH 必须用有效 RFC 8484 查询并验证 DNS 应答；访问 HTTPS 首页或收到任意 HTTP 状态不够。按当前核心文档验证 DoH URL 代理绑定等功能；代理引导解析不得通过自身节点形成循环。多 nameserver 可能并发，不把列表顺序称为主备。

检查订阅 nameserver-policy、fallback 和 direct-nameserver 是否绕过候选 DNS；严格不回退的要求需明确范围，并在隔离环境验证故障时行为。只清普通 DNS 缓存；有证据才处理其他缓存，不默认清 Fake-IP 池或重启系统 DNS 服务。

### 条件性检查：SVCB / HTTPS（Type 64 / 65）

仅在用户要求检查，或观察到连接偏离预期分流、异常 IPv6/直连时检查；正常的小修不增加必跑项。Type 64 是 SVCB，Type 65 是 HTTPS 记录，用于服务绑定、协议/端口和服务器 IPv4/IPv6 地址提示；记录中的地址不是客户端真实公网地址。记录存在不等于 DNS 泄露，屏蔽也不构成 Claude 帐号安全或不封号保证。

1. 对实际异常业务域名，经当前配置的 DNS 路径查询 A、AAAA、SVCB、HTTPS，记录回答及 TargetName、alpn、port、ipv4hint、ipv6hint 等相关参数。单独通过公共 DoH 查询只能作对照，不能证明浏览器或系统实际使用该路径。
2. 关联真实 Safari 请求与核心连接/必要抓包，核对实际 DNS 查询路径、连接目的地址、IPv4/IPv6、命中规则和代理链。存在地址提示或 HTTP/3 宣告本身不是绕过代理的证据；缺少可观察的流量证据时明确未证实。
3. 有可复现的相关异常且处于已授权修复范围时，才做该域名的局部过滤前后对照；先备份、确认当前核心/解析器支持的处理方式，并区分 NODATA、REFUSED 与静默丢包，避免将丢包引起的等待误称为正常回退。不默认全网屏蔽 Type 64/65。
4. 对照实际 Safari 的业务可用性、连接路径、耗时与其他受影响网站/功能；无改善或出现退化则恢复该项，按正常路径确认恢复。验证结果不能只来自 DNS 回答变化或检测分数。

SVCB/HTTPS 可帮助连接优化；许多客户端可回退到 A/AAAA，但兼容性、耗时和隐私能力影响需验证，不能承诺“完全不影响其他网站”。ipleak 等检测不漏只证明该次检测范围，不能推出封号概率。报告将协议事实、观察证据与未经证实的防封说法分开。

WebRTC 将页面观察到的公网候选与实际本机公网地址、普通网页出口、Claude 出口分别比较，同时查看核心连接的进程、域名/IP、UDP 端口、命中规则及完整代理链。区分真实地址暴露与代理出口不同。相关 STUN 示例包括 `stun.miwifi.com`、`stun.l.google.com`、`stun.cloudflare.com`，但域名、A/AAAA 和端口需本机重新捕获，不硬编码历史 IP。

优先最小范围精确规则并确认节点支持 UDP。共享 STUN 无法可靠识别发起网页，有限规则不构成全浏览器防泄露保证；检查实际需求中的 TURN/IPv6 绕行。Fake-IP 排除不等于 DIRECT。扩大默认出口、所有 UDP、阻断媒体或统一其他应用出口之前，说明影响并沿用用户已有授权；没有对应授权时请求具体选择。不得只改检测站点使页面变绿。

保留本次用户原有服务分流；Apple/Figma 直连、不同 AI 服务的指定节点或删除 AXO/Grok 专用规则均属于实例偏好，下一次只在用户要求或当前配置契约成立时沿用，不能作为默认模板。

## 4. 用户允许后持久更新与事务安装

先核对调整清单的获准项，未批准项目不执行。只生成候选不足以完成已批准的安装任务。配置应进入持久 overlay/合并逻辑，后续更新仍保留；不要只改将被订阅覆盖的活动 YAML。修 updater 时阅读现有实现和参数真实含义，再使用 [事务与验证接口](transaction.md) 约束校验、安装、监测、恢复与验收。

语法和核心配置校验、引用验证、真实 DoH 预查通过后才原子安装。恢复原 mode/TUN/组选择，并核对实际加载 DNS 和规则；不要顺便切 GLOBAL 组。隔离检查如临时切组，必须 finally 恢复并核对。客户端 scheme 调用成功不等于订阅已下载：核对 mtime、内容哈希、订阅更新时间及下载证据；失败时明确本轮使用本地订阅。

## 5. 正常路径与目标浏览器验收

完整修复默认持续观察至少 5 分钟，多轮新连接，记录每个目标而非单个聚合“成功”。连续失败 3 轮触发回滚，结束时至少连续成功 3 轮。已有充分证据后不重复测试；最后出现新失败则属于未解决证据，需针对性复查。

验收前明确有限重试的次数、间隔、恢复条件和回滚阈值；请求重试不能清零已累计的连续失败轮次或隐藏首次失败。已恢复的单次失败与持续故障分别报告。用户接受已观察到的偶发失败，只适用于明确的线路、变更和验收范围，不自动放宽后续任务。updater 的重试实现与留证要求见 [事务接口](transaction.md)。

优化后在同一设备、同一真实浏览器完整重扫 https://ipkk.com/claude-ip-check，按前测字段记录分数及差值（前后均有效时才计算）。即使分数下降、变更失败或准备回滚，也保存实际后测结果；回滚后的结果单列，不能冒充优化结果。使用真正 Safari，不用 Chromium、curl 或 in-app browser 替代用户要求的 Safari。等待 DNS、WebRTC、出口查询完成，记录地区、IPv4/IPv6、时间与业务结果；若 IPKK 仍按“UDP 候选 != 网站出口”打标签，可报告出口分流与真实本机地址暴露的差别。住宅、Proxy、滥用标记可共存；网站分数不代表 Claude 官方风控或长期稳定性。

最终通过需要适用的当前事务标记匹配、完整目标浏览器结果满足目标、必要业务验证通过且没有未解释的新失败。前面连续监测通过不能覆盖最后的 TLS 故障或业务失败。对 403/429 或 TLS 错误先区分 HTTP 验证/限流、curl 与浏览器差异、线路故障；保留证据。未解决则不写 pass，写 fail 触发回滚或等待有明确时限的用户决策，不绕过本地超时。

如果涉及媒体阻断或出口统一，实际媒体可用性也需验证；“无法探测”不能写成 UDP 正确代理。页面未暴露本机公网 IP 只能证明本次页面范围。

## 6. 回滚、停止与交付

失败恢复本机备份的文件及运行配置、mode/TUN/组选择，核对哈希和实际 DNS/规则。正常路径至少连续健康 3 轮才写联网恢复。有限恢复重试后仍失败，报告“文件已恢复、联网未恢复”，保留诊断并停止重复安装同一失败候选。脚本自身恢复与偏好整体恢复必须按实现范围声明，不能假定配置回滚已恢复所有文件。

交付获准/未获准项目、实际完成项、安装或回滚结果、配置/系统变化、IPKK 优化前后分数及有效差值、风险标签变化、验证时间和范围、残留问题、备份位置与脚本路径；不把短测描述成长期稳定保证。关闭为验证新建的命名浏览器/Playwright 会话，不关闭用户原有窗口。临时目录产物提醒用户保存或备份。

## 诊断与优化中的可选项目：系统时区

先读取当前系统时区、自动时区和目标出口地区，将必要调整列入本次清单；仅在用户许可该具体项目后执行。普通 DNS/WebRTC 修复不隐含时区写入授权。先检查当前系统时区和当前目标出口地区；用城市对应的 IANA 区域，如 Houston → `America/Chicago`，不要固定 UTC−5（夏令时会变化）。旧出口发生变化时重新核对，不自动追随节点持续修改。

macOS 可用 `systemsetup -settimezone <IANA>`；需要管理员验证时用原生系统验证，例如 `osascript` 的 `do shell script ... with administrator privileges`，让用户在系统窗口认证，不索要或保存密码。验证取消即停止此分支。用 `/etc/localtime` 指向及 `date` 的时区/偏移确认结果，刷新真实浏览器验证。自动时区可能覆盖手动设置，先记录开关状态；用户要求固定手动时区时，可在授权范围内关闭自动时区并核对。修改取消或部分失败时重新读取状态，按实际已改变项恢复或报告；不能假定管理员命令是原子事务。

时区检测通常读取 `Intl.DateTimeFormat().resolvedOptions().timeZone` 和当前 `Date.getTimezoneOffset()`，与 IP 地区当前偏移比较；同国跨时区也可不同。具体参照 IP 和 UTC 隐私模式需查当前站点实现，不写成所有站点通用算法。

调整后的自动时区覆盖检查按 [原生设置参考](environment-ssh.md#native-system-settings) 执行，不仅以当前偏移一致作为固定手动时区的完成证据。

## Android：诊断、分流与订阅重新合并

Android 请求执行本节，沿用上文授权、前后评分和失败恢复契约。macOS helper、Safari 事务标记不套用到手机。电脑只用于控制或辅助请求时，不能把电脑浏览器结果当作手机结果。

### 设备与基线

- 确认 ADB 已授权的目标设备、型号、Android/客户端/核心版本；多设备时所有命令显式指定目标，设备更换后重新建立基线，不沿用旧机状态。设备序列号、订阅地址、凭据不进入共享报告。
- 锁屏或授权弹窗由用户自行解锁/确认，不绕过认证、不使用 root 或强行授予受限权限。使用 ADB、投屏或 Computer Use 时遵循该工具约束；无授权先列所需环境，不默认安装工具。
- 若用户允许临时保持亮屏，先读 `stay_on_while_plugged_in` 和实际 AC/USB/无线供电状态，再设置相应供电掩码。USB 接线不意味着系统报告 USB 供电；检查 `mStayOn`。结束或失败恢复原值，不能一律恢复为 0，也不顺改屏幕超时。
- 记录活动配置的 URL/File 类型、规则模式、组选择、VPN 启停、路由全部应用、DNS 劫持、允许绕过 VPN、附加系统 HTTP 代理、追加系统 DNS、IPv6、网络栈、私有网段绕过和 Android 私人 DNS。覆写界面的“不修改”不证明实际配置值；需导出配置对照。只读取任务需要的内容。
- 在手机真实浏览器按完整 IPKK 流程记录前测；用户先切节点后要重新测量，不能拿旧出口分数作新出口基线。电脑/手机应用名称相近也不意味着同一实现。

导出当前配置到私有备份（实际文件可能被文档提供程序加 `.txt` 后缀），读取完整 YAML 生成候选；保留节点凭据、组、原规则和未获准设置。保存可重复执行的合并脚本及非敏感规则/参数，而非只保存最终 YAML。检查目标节点存在、UDP 能力、所有代理引用和规则优先级。可用隔离且兼容的核心验证候选，不能将手机配置加载到电脑活动核心；最终仍以手机客户端成功解析、启动和实际路由为准。

URL 配置可能不可直接编辑；需要导入 File 配置时先明确它不再自动跟随 URL 订阅。原 URL 订阅及原可用优化配置均保留作恢复点。通过客户端文件导入与保存，选择新配置；不要把上传到 Downloads 当作安装成功。按客户端需要停止/启动 VPN，读取活动配置名称和错误日志，核对实际加载。

新 File 配置可能重置节点选择为自动选择。恢复获准普通节点及涉及的各组；等待滚动动画结束再点击，之后截图确认选中状态。不能只依据一次点击或节点显示名称判断成功。VPN 重启后用新连接核对选择持续生效。错误临时选择与过渡检测单列，不能混入最终验收。

Android 时区优先原生设置；已获准且 shell 支持时可核查 `cmd time_zone_detector`、`cmd alarm set-timezone` 等接口后使用。命令权限失败时改走原生 UI，不提升权限绕过。读取实际 IANA 时区、自动开关和偏移，再核对浏览器，不把返回码单独当成功。

### 手机真实路径验证与收尾

在同一手机浏览器完整后测，保存实际分数，即使日本普通出口/美国服务出口使分数下降。分别记录网页、Claude、DNS、UDP 和时区；页面的 WebRTC/DNS 异国标签可能源于出口差异，只有看到代理公网候选不能推断本机真实地址暴露。DNS 结果异常时先核对实际加载和重启后新查询，不能无证据称为缓存问题。

用手机浏览器分别访问 Claude/ChatGPT/Cloudflare trace 及 Apple 测试页，记录实际 HTTP/地区/IP 或页面成功状态。网络调整按上文至少五分钟观察和失败恢复规则执行。必要时 ADB forward 到手机 HTTP 代理可辅助连续检查；按每个目标分别断言普通与定向出口，不能全目标断言同一美国 IP。这是显式代理路径，不能替代正常 VPN/TUN 浏览器、UDP或蜂窝验证。Wi-Fi 与蜂窝、IPv6、媒体未测时明确列出，不扩写验证范围。

恢复原亮屏设置，删除本次手机 Downloads 中含凭据的导入/导出副本，移除自己创建的 ADB 转发。关闭本次新增标签页前核对数量和 URL，保留用户原有标签；不清理用户应用数据或其他转发。报告活动配置、节点、评分差值、失败/过渡轮次、重启后结果和订阅更新限制；提醒私有备份勿公开。

### 订阅更新后重新合并

1. 读取当前手机活动配置、各组选择、客户端覆写及合并参数；检查上次批准的 DNS、服务出口和时区偏好是否仍适用。沿用相同具体许可；节点消失、改出口、扩大规则或调整时区时重新列项确认。先取得本次完整前测。
2. 在原 URL 订阅中更新，核对更新时间及下载/内容变化证据，再导出最新完整配置到私有目录。更新失败则停止本轮安装，保留原活动配置；不能把旧导出称为最新订阅。
3. 将最新订阅作为输入，执行保存在私有目录的合并脚本/overlay：合并获准业务 DNS、追加系统 DNS策略（客户端设置单独核对）、定向服务及重新核实的 STUN 规则。保留最新订阅节点与其余规则；去除本工具规则的重复项，避免累积。检查节点重命名/删除、代理引用、UDP 能力；缺失时不能静默改为 DIRECT、自动选择或其他国家。
4. 对 YAML 和兼容核心作适用校验，再作为新的 File 配置导入、保存并选为活动配置。导入新版本前保留当前可用版本；旧 URL 订阅不会自动更新这个 File 配置，手机 Downloads 副本删除不影响已导入内部配置。
5. 恢复普通日本/定向美国等获准组选择与覆写，必要时重启 VPN；用实际新连接验证持久选择、手机业务与完整后测，按范围完成持续检查。失败恢复前一可用 File 配置及其选择、覆写；核对恢复联网再收尾。未经用户要求不删除旧回滚配置。

合并脚本与敏感备份保存在用户指定长期目录；不将订阅 URL、节点密码或本次完整 YAML 收录到 Skill。历史评分变化不能作为下一台设备的预期分数。只有用户要求维护脚本时才改脚本；说明其参数、输入输出和恢复办法。
