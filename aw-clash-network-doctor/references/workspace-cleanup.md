# 独立分支：工作区 Claude 数据清理

用于用户明确选择的工作区内 Claude 缓存、会话/历史、配置残留或既有备份清理；不等于清空工作区，也不是网络修复或帐号防封措施。只做扫描时直接提供清单；“把清理逻辑加入 Skill”不授权立即删除文件。

## 范围和扫描

先定位用户指定的真实根目录和适用项目规则；lstat/realpath 核对所有权、链接及实际路径。拒绝意外的其他用户目录、符号链接根和越界目标。正常根路径含系统别名时先展示解析后的真实范围，不机械将平台路径别名判为恶意。目录扫描不跟随符号链接，不进入 .git、node_modules、vendor、虚拟环境及构建输出；确需清理这些目录需用户明确指定另一个范围。

使用当前 Claude 版本的已核实白名单识别，例如 .claude/cache、paste-cache、stats-cache.json；projects、sessions、history.jsonl、file-history 是会话/历史资料，不能标成普通缓存。.claude/settings*、skills、commands、MCP 配置、项目源码、CLAUDE.md 和 AGENTS.md 默认保留。旧版 telemetry/debug 路径按实际用途分类，日志可能包含有价值的诊断，不凭目录名断言都可安全删除。

只扫描本次工作区；不扩大至用户主目录 .claude、系统 Library、登录凭据或 Keychain。发现这些外部项目可说明存在，但修改需要单独明确范围。既有 .claude.json.backup*、ClaudeBackups 或网络事务备份默认保留；新建备份不得被同一批清理再次选中。

清单记录每个目标的绝对/相对路径、类型、类别、体积/数量、影响、扫描是否完整和快照身份（设备/inode/mtime/size、必要目录树签名）。设置适合目录的条目/层级/时间上限；达到上限、权限不足或统计不完整必须标记，不能把未扫描当作不存在或允许整目录删除。

## 审查与执行

按可再生缓存、会话/历史、配置、凭据、旧备份分别说明结果，保留实际用户选择。用户已有授权覆盖确定的可再生缓存时可继续；宽泛的“清理工作区”不推定授权删除会话、项目、凭据或备份，先完成具体清单再取得相应选择。永久删除必须遵守当前工具/环境的确认要求。

默认选用系统废纸篓或移动到工作区外的私有隔离目录（0700，敏感文件0600），记录恢复映射，核对跨卷移动是否完整。保留能力不得虚构：永久删除无 undo，目录部分失败不能声称已回滚。不要直接复制第三方永久删除命令，不使用 rm -rf 工作区根目录或未核实通配符。

如果 Claude 仍写入选中数据，先要求其退出或根据已有授权停止对应进程；确认身份与未保存工作影响，不杀宽泛进程名。退出后重新扫描；新增或身份变化项目需要重新审查。执行前及每项操作前核对路径边界、链接/所有权、快照和进程状态；任何漂移、重新启动或错误都停止剩余项。配置仅按已授权键变更，原子写回并保留权限，避免删整份 JSON。

## 完成与恢复

逐项记录已处理、未处理和失败；重新扫描确认选中项目的状态与保留内容。目录移动/删除失败可能是部分成功，不能按总数估算完成。可恢复清理提供准确恢复位置/命令；实际删除不可恢复则明确说明。若执行脚本实现此分支，用隔离测试目录验证链接越界、快照变化、未选项目保留、部分失败停止与恢复映射，不在真实工作区做破坏性测试。

最终交付范围、结果、空间变化的测量依据、恢复位置和残留问题。清理不承诺清除服务端身份、消除风控或提升网络质量。
