# 漫画档案打包工作流

本文档是执行 AW Comic Dossier Packer 时优先读取的文本工作流，也是 `workflow.svg` 的语义事实源。SVG 是与本文档同步的可视化投影。

## 输入与产物

- 输入：漫画名称，以及可选的输出目录、高清化选择和可用的辅助 Skill。
- 产物：一个清理后的漫画档案目录，包含唯一一套每卷封面、社交封面卡片、约 400 字中文介绍和 7 个介绍来源链接。

## 执行步骤

1. 解析输出目录，在其中建立 `manga-social-pack/<safe manga title>/`，不得向 Skill 目录写入产物。
2. 使用内置脚本从 BOOKOF/bookof.moe 收集全部原始卷封；零结果时依次尝试可靠别名，多候选时由用户选择。
3. 报告封面数量和费用估算，并询问是否跳过高清化。
   - 跳过：保留 `covers/`。
   - 不跳过：使用 Nano Banana API 生成 `covers-enhanced/`，记录失败卷与原因。
4. 从 7 个可靠漫画资料页读取原始介绍，综合为版权安全的中文介绍；可用时再按 `humanizer-zh` 生成优化稿。
5. 始终直接用 Codex ImageGen 生成一张原创 3:4 小红书封面；可用时按 `xhs-visual-director` 生成并保留额外变体，逐张视觉检查。
6. 生成 `{漫画名称}.md`，写入介绍、可选优化稿、全部社交卡、每卷封面及 7 个介绍来源。
7. 清理中间产物，只保留 Markdown、`social-card/` 和 `covers/` 或 `covers-enhanced/` 其中之一，再报告失败项与人工处理边界。

## 停止条件

- 原始封面收集完成后，用户尚未明确选择跳过或执行高清化时停止。
- 高清化所需 API Key 缺失或调用失败时，不泄露密钥；报告具体失败并保留可用原图。
- 用户要求依赖未安装的可选 Skill 时，不伪造其能力；说明降级路径或按用户要求处理安装。
- 不能确认候选漫画身份或输出目录会导致写错目标时，先确认再继续。

## 最终交付

交付可点击的最终 Markdown 和图片路径，说明采用的封面目录、实际来源数量、生成的卡片版本，以及仍需人工处理的卷或视觉问题。
