# Editing Mode

本模式维护 Component References 与[组件索引](../references/components/index.md)，适用于组件新增、移除、改名、正式分组迁移、能力变化或指定的规则文案修改。用户说“编辑模式”或直接要求维护这些文件，即进入本模式；不要求固定口令，也不启动产品界面 Review。

## Scope & Sources

沿用用户指定的组件、文件、章节和已授权操作。未指定具体组件而要求“按当前 Gallery 同步索引”时，比较完整正式集合，只处理实际差异。仅要求改一句文案时，直接定位目标章节，不顺带同步其他组件。

正式成员资格的唯一依据是`axo-design-system` 仓库（当前本地路径 `/Users/wally/Documents/SHIZAI/SOIA/axo-design-system`）的 `gallery/gallery-registry.ts` 中 `NAV_GROUPS` 的 `general` 与 `composite`。读取其引用的 section，确认最终归属；索引是需要维护的快照，数量不得固定为初始的 80。Temporary、Styles、Rules、Scenarios、无正式 Panel 的导出不纳入；来自 temporary section 的组件仍可能已提升为正式组件。

先读索引，再读取目标 Reference。新增规则或语义、能力发生变化时，补读目标的当前公开实现、类型、Gallery 说明与示例、相关文档和适用 Scenario；仅在判断受影响边界时加载相似组件。ADM 仅在确有场景缺口时按其项目规则只读调查，历史调用不独自决定推荐规则；外部资料按实际证据缺口选用官方来源。

维护范围是本 Skill 的规则、索引和必要元数据。不要为了让文档一致而修改组件实现、Gallery 注册、其他项目或库包版本。先核实用户所指的是展示名、Gallery ID 还是代码目录；三者不必相同。若请求与当前正式归属仍有冲突，说明差异，保留无法确定的增删项并完成其他已明确部分。用户明确改变收录范围时，按该授权同步范围定义和检查口径，不能静默产生例外。

## Apply Changes

| 变更 | 对应维护 |
| --- | --- |
| 新增或提升为正式 Panel | 创建唯一的 `references/components/<gallery-id>.md`，写入完整七维规则；在正确分组增加唯一索引行，填入当前名称、文件链接与家族。只在确有语义关联时补充相似组件的边界。 |
| 移除或降为 Temporary | 确认该 ID 已退出正式集合，查找指向目标文件的入链和相关名称/ID 表述；删除对应索引行与 Reference，并在引用方清理失效关系。存在已核实的替代组件时才改指向，不按外观猜测替代，也不删除整个引用方文件。 |
| 展示名改变，ID 不变 | 更新索引名称、目标标题和确实受影响的名称表述，保留 ID 和文件名。例如 Guide Card 不因此改名为 guide-card.md。 |
| Gallery ID 改变 | 从当前注册、实现或明确变更说明确认新旧映射，迁移目标文件；同步索引、文件内 ID、所有直接入链和有效的旧 ID 表述。不同时保留新旧两条正式记录。历史研究记录不是当前 ID 别名的依据。 |
| 正式分组或家族改变 | 移动索引行并更新家族与分组计数；ID 不变就不迁移文件。由 Foundations 转为 Composites 不代表移除组件。 |
| 能力或语义改变 | 更新目标真正受影响的维度及直接相关的语义边界；只有名称、家族或正式归属改变时才同步索引元信息。 |
| 局部文案修改 | 只修改指定文件或章节的匹配文字；没有匹配时说明未改，不扩大到近义词、其他规则或全库同步。 |

删除与迁移前可用 `rg -n --fixed-strings '<旧ID>.md' <skill目录>` 查找入链，再按旧 ID 与名称定向查找剩余表述。搜索可覆盖整个 Skill，语义阅读与内容修改仅扩展到真正受影响的位置。不要批量增加无意义的反向链接。

新增或实质改写 Reference 时保留七个英文维度：Definition & Semantics、When to Use、When Not to Use、Similar & Easily Misused Components、Composition、Internal Usage、Examples。Composition 保留 Recommended / Avoid，Examples 保留 Recommended / Problematic；正文使用索引约定的中文术语，案例解释规则而不定义规则。可以参考同家族文件的结构，不能复制规则凑出占位内容。

涉及成员、分组或名称变更时，同步索引表格、开头总数/分组数，以及已失效的名称映射说明；计数来自当前实际集合。没有相关差异就保留索引原文，不为制造改动而重排整个表格。用户删除过的临时研究文件无需重新建立，维护不依赖其存在；若本次更新现有研究记录，只处理相关条目，保留其可删除性质。

## Verify & Complete

验证应与变更范围一致：

- 成员、ID 或分组变化：重新比较当前正式注册集合、索引行和 Reference 文件集合；确保一 Panel 一文件、ID 唯一、分组及计数准确，没有误收临时项。局部维护发现范围外已有差异时报告该差异，不自动扩大内容修改范围，也不宣称已全量同步。
- 目标规则及直接受影响的文件：检查七维与必需子章节非空、术语和主要相似边界一致。删除/改 ID 后检查全包相对链接可解析，确认失效路径与当前规则中的旧 ID 已清理。展示名变更不应触发文件迁移。
- 普通文案小修：检查指定文字、章节边界与差异；内容无实际变化时不升级版本。不为纯文案变更重读全部组件或运行前端构建。
- 本 Skill 有实际修改时，沿用 AW 版本策略：一般维护提升 MINOR 并将 PATCH 归零，明确的小修只提升 PATCH；保留 author 与 creation_context。仅流程或触发范围改变时同步入口、文字工作流和 SVG；文件增删本身不要求重画流程图。
- 运行 skill-creator 的 `quick_validate.py`、aw-meta-skill 的 `validate_aw_skill.py` 和 `git diff --check`；新增文件还需覆盖空白检查。按当前环境定位校验器，不依赖研究阶段的临时脚本路径。这些结构检查不能代替正式集合和语义检查。

在已授权范围内修复必要检查发现的问题并重验；无法解决的核心归属或语义问题保留为待定，说明影响范围，不能伪造完成。仅因本模式需要增删规则和索引，不再重复索取同一授权。

交付说明本次实际新增、移除、迁移或修改的 ID、索引当前总数及分组数、适用检查结果、版本变化与仍待确认的差异；遵守项目的 HANDOFF 记录要求。完成意味着本次范围内的规则、索引和链接已同步，不在只更新表格或只创建空文件后停止。

## Request Examples

- “编辑模式：按当前 Gallery 同步组件索引。”——比较正式集合并处理增删、名称与分组差异。
- “编辑模式：删除已退出正式 Gallery 的旧 ID，并清理引用。”——联动移除索引行、规则文件与失效关系。
- “更新这个组件的 Reference，只调整变化的能力边界。”——维护相关规则，不启动界面 Review。
- “只改 Button Reference 的 Examples 文案。”——局部编辑，不扩展到全库同步。
