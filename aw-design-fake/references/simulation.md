# Fixture 与演示状态

适用于需要完整演示对象、跨组件读取、列表 / 详情联动、流程推进或本地模拟行为的情况。

- 业务域 fixture 优先放在该域的 `fake.ts`；跨页面的演示状态或模拟行为放在项目统一的演示状态层。真实数据与 fake data 只能在展示侧的 adapter、view-model 或 selector 层合并。
- **真实契约优先。** 开始接入前识别页面已有的真实数据源、状态解释和交互写入路径。凡已接入真实契约的区域，真实数据、状态与交互必须继续展示和执行；全局「填充假数据」开关不得替换该区域的 UI 数据来源、状态或 handler。假数据只用于明确未接入的区域，或独立的演示场景。
- 项目存在「填充假数据」这类演示开关时，导出 fixture、seed、mock catalog 或 mock fallback 的数据模块，其所有公开读取入口都必须经过该开关的 selector；该要求只作用于演示数据读取，不能把真实契约数据改为从此 selector 取值。项目没有开关且用户已要求可关闭时，在授权原型边界内添加一个统一开关；仅在位置或行为仍有实质歧义时询问，不要散落多个布尔量。
- React Hook 订阅该 selector；非 Hook getter 通过同一 selector 读取当前有效值。不能只在路由、页面入口或 JSX 外层做条件渲染，也不能在模块加载时缓存 getter 的开关结果。
- 开关关闭时返回真实数据或稳定空值，fixture / seed 数量必须为 0；列表、详情、统计、侧栏计数、关联选择器和跨模块 adapter 必须一致关闭。
- 开关开启时只可恢复未接入区域的演示数据；它不能把已接入的真实数据替换成 fixture，也不能覆盖真实状态。真实空数据、加载中、失败、未绑定、凭证失效等均是契约状态，不是触发 mock fallback 的“缺数据”。
- 若需展示模拟状态，提供显式、可退出的入口进入独立演示场景，并允许退出后回到真实场景；查看真实契约不能依赖关闭全局填充开关。具体入口形态由项目现有交互决定，不限定为特定控件。
- 真实与演示场景必须隔离数据来源、状态与写入路径。模拟只写本地演示状态；fake ID 及演示字段不得进入真实 API 或真实写接口。演示状态推进集中在明确的模拟入口或演示状态层（不是给用户可见 UI 加来源标签），不混入真实配置、授权、凭证或生产动作区。

## 验收反例：智能体设置页 IM 频道

反例是全局开启「填充假数据」后，IM 频道被 fixture/mock fallback 替换，因而只有关闭开关才能看到真实频道或凭证错误状态。此行为不符合本 Skill。

验收时在全局假数据关闭、开启两种状态下检查 IM 频道：已接入的真实频道内容与交互保持连接真实契约；真实空数据、加载中、失败、未绑定、凭证失效等状态均正常展示，不能被演示成功态覆盖。若需呈现模拟 IM 数据，应从显式、可退出的独立演示场景进入；退出后回到真实契约场景。确认演示写入仅影响本地演示状态，fake ID 不会传入真实写接口。
