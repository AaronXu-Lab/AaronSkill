# DESIGN.md 编写与维护工作流

本文档是执行 AW DESIGN.md Author 时优先读取的文本工作流，也是 `workflow.svg` 的语义事实源。SVG 是与本文档同步的可视化投影。

## 输入与产物

- 输入：创建、审查、修改或校验 `DESIGN.md` 的请求，以及现有设计系统与实现证据。
- 产物：通过官方 lint 的规范性视觉契约，或只包含详细 `TODO(DESIGN)` 注释的延后决策记录。

## 执行步骤

1. 读取规范摘要、lint 规则、编写约定，以及项目指令和现有 `DESIGN.md`。
2. 确定所有权模式：独立契约、代码支撑契约或生成投影；生成投影应修改事实源而非产物。
3. 选择工作模式。
   - 规范契约模式：创建、审查或修改 Token、主题、正式规则和所有权边界。
   - 注释模式：仅在用户明确延后决策时添加 `TODO(DESIGN)`，不得改变规范值或版本。
4. 规范契约模式下，检查现有实现与可复用 Token，完成规范 YAML 和标准章节，核对语义命名、引用、主题对等和所有权。
5. 注释模式下，把当前证据、候选变化、影响范围、未决问题和下一次复核标准写在对应所有者之前，并用 diff 确认只有注释变化。
6. 运行官方 lint；更新已有文件时同时运行 diff，对外部视觉或交互验证边界作准确说明。
7. 按固定结果模板交付文件路径、所有权模式、校验结果和仍需用户决定的事项。

## 停止条件

- 无法确定所有权模式，且选择会改变应编辑的事实源时停止确认。
- 官方 lint 仍有错误时不得宣称完成。
- 注释模式出现任何规范值、键、引用或正式规则变化时，停止该模式并转入规范契约模式。
- 缺少必要实现或设计证据时，标明外部检查，不用推测补齐。

## 最终交付

交付经过 lint 的 `DESIGN.md` 或纯注释变更，并报告 lint、diff、外部检查边界及未决决策。
