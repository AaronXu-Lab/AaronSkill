# DESIGN.md 编写与维护工作流

本文是执行事实源；workflow.svg 是面向人的概览。输入为 DESIGN.md 请求、现有契约、项目证据与完整会话中的授权。输出为规范契约、纯注释 TODO 或只读审查报告；不可用的检查须明确标记。

## 选择任务与资料

先按请求选择下列路径，不默认通读全部参考资料。沿用本会话已经读取且仍适用的内容；遇到未覆盖的 schema、设计判断或校验问题时再扩展读取。

| 请求 | 读取资料 | 工作范围 |
| --- | --- | --- |
| 新建契约 | [规范摘要](../references/spec-summary.md)、[编写约定](../references/authoring-conventions.md)与[校验指南](../references/lint-rules.md) | 覆盖文档实际拥有的完整设计范围；示例仅在需要格式或设计参考时读取 |
| 局部规范维护 | 编写约定中相关章节、校验指南；涉及 schema 时读规范摘要相关部分 | 检查完整契约，修改拥有层及受影响引用；沿用无关设计决定 |
| 审查 | 全面审查读规范摘要、编写约定、校验指南；专项审查读相应章节 | 检查完整契约，在请求的审查维度报告问题；不自动修复 |
| 仅运行校验 | 校验指南；需要解释发现时再读对应规范或约定 | 运行检查，报告证据，保持文件不变 |
| 纯注释 TODO | [注释模式](../references/annotation-mode.md)、校验指南 | 保存基线，记录待定设计或已定契约的实现迁移，不改规范 |

涉及间距命名或迁移时，读取[尺寸档位与迁移](../references/authoring-conventions.md#spacing-tiers-and-migration)；涉及正文修改或正文审查时，读取同一文档的 Prose 与 Body boundary examples；涉及主题时读取 Multi-theme systems。参考文档可按章节读取。不能用减少资料读取代替必要的契约检查或验证。

## 确定编辑源

编辑前从生成标记、构建脚本、导入关系、分发需要及已有决定选择拥有层：

- 独立契约：DESIGN.md 拥有精确 token、组件外观与相关状态，可独立分发。
- 代码支撑：代码拥有组件内部细节；文档拥有稳定的跨组件语义与选择意图，不把偶然 CSS 反向写成规范。
- 生成投影：规范和 TODO 均在拥有源维护，再重新生成；不维护两套权威。

仅在证据不足且歧义会改变编辑源时询问；沿用已有决定与完整会话授权。只读任务无需为不影响审查的编辑源疑问停下。所有权用于内部决策，工程证据留在交付报告；正式正文与身份字段的边界见编写约定。

## 执行与保护

新建时确定设计意图、受众与风格，按拥有范围写 YAML 和必要的设计理由。按规范摘要的章节顺序组织正文，省略不适用章节，保留有用的领域扩展；示例值不作为默认设计决定。

维护现有契约时保存临时基线，先校验，做最小拥有层修改，再校验并检查实际 diff。即使请求很窄，也检查完整契约；不因此重建设计意图、重写全部 YAML、补写无关章节或清理其他 TODO。沿用已有且未失效的检查结果，不重复执行同一状态的检查。基线按用户回滚偏好保留或清理。

只读审查和校验以准确的问题报告完成；发现错误不授权修复。纯注释按注释模式保护 YAML、版本和正式正文。规范更新仅落实范围内已解决的决定并移除相应 TODO；已定契约的实现 TODO 要等实现核验后才能删除。规范批次按项目版本策略处理一次；官方 `version: alpha` 是格式标记，不是项目发布版本。

## 验证、恢复与完成

按校验指南运行完整文档的保护检查、官方 lint 与适用的 diff，并核对实际授权范围。正文语义、TODO 充分性、间距解析值与受影响布局由相应任务路径核对，脚本不能代替这些判断。

- 修改任务发现本次变更造成的内容错误时，在授权范围内修复并重跑受影响检查；不在第一版实现后默认停止等待评审。
- 纯注释保护失败先恢复意外的规范变化；只有会话已经授权规范修改时才转换模式。
- 校验环境不可用时可交付有用的人工发现或修改产物，并明确官方验证未完成；不得把失败或未执行记为通过。
- 对范围外、既有或依赖未决设计的错误记录证据，不擅自扩大修改。完成标准是约定产物、适用检查及范围内修复都已处理；无法完成的部分明确说明原因。

交付在 DESIGN.md 之外报告产物路径、实际变更、验证结果、尚未完成的实现或外部检查，以及确需用户决定的事项。报告格式按任务规模组织，不强制固定标题；工程职责和校验日志不追加到设计正文。
