# AW Design System Gallery

以目标项目的事实源和 Gallery 约定为准，审查或优化组件展示。默认从用户指定的最小范围开始；用户明确要求批量、全量或一致性审计时，按授权扩展。

执行前读取 [Gallery 工作流](docs/workflow.md)：

![Gallery 工作流程](docs/workflow.svg)

## 路由

- 先读取目标目录适用的仓库规则、设计规范与 Gallery 文档，识别当地展示模型、术语、框架、项目配置和验证入口。
- 详细展示判断读取 [Gallery 审阅规则](references/gallery-rules.md)。
- 只有涉及组件契约、名称映射或 API 修改时，才读取 [组件 API 设计约束](references/component-api-design.md)。
- Skill 不内置任何项目的组件注册表、顺序表或属性映射，也不规定项目应使用 CSV、JSON、Markdown 或代码注释。

## 核心决策

1. **聚焦正式设计审阅。** Gallery 展示默认示例，以及帮助理解组件视觉、内容结构、布局或关键交互状态的真实公开设计轴／状态对比；组件调用数据、实现机制、便利行为、事件、调试项与内部状态即使保留在 API 中，也不自动成为 Gallery 轴。仅为验证健壮性而设置的窄容器、限高滚动、溢出、异常输入、回退或空数据场景，不默认进入正式 Gallery；测试或临时验证不构成新增 Panel 或场景区的理由。边界展示仅在用户明确要求或属于当前组件正式设计契约时按具体范围处理；Empty State 等有明确设计含义的正式状态仍可展示。
2. **依赖分组优先。** 父轴后紧跟依赖子轴；无依赖时才按几何/布局、主视觉、内容/槽位、状态、行为作可调整兜底。
3. **遵循当地默认模型。** 项目使用 default 元数据时，它只列实际展示轴，并与最终展示轴顺序一致；没有展示轴的组件仍保留有意义的 default 示例和当地舞台边框，但省略整行 default Caption。是否归入 Temporary 另行判断。默认或推荐组合必须有证据，不凭结构猜测。
4. **映射现场判断。** 先检查目标框架的平台保留属性与项目映射约定；没有配置时只为当前范围推导。歧义先询问，不自动改变组件契约。
5. **渐进扩展范围。** 默认局部取证；用户明确授权或当前判断确有需要时，可读取相邻展示、共享基础设施或只读使用证据，并说明原因。写操作仍受任务授权约束。
6. **先筛选展示，再确定 Caption。** Caption 只能展示真实公开 API 的设计轴和组件状态。容器宽度、舞台尺寸、布局 wrapper、触发方式等是示例条件，不得伪装成组件属性；仅对符合正式展示标准的示例，在必要时用 Panel description 或场景说明解释条件。范围内已有的纯验证展示应移除，不得只取消 Caption 后继续保留为场景区。
7. **按证据决定真实占位范围提示。** 当组件自身边界不明显，且真实占位范围对当前设计审阅有必要时，Gallery 才补充范围提示；判断依据是边界可辨识度与审阅必要性，与组件类别无关。优先复用目标项目既有的 Dashed Light / line-light；已有边界显示开关时，必须复用受控入口，不能用基础 token 或硬编码虚线绕过开关。提示必须保持 Gallery-only，不得改变组件布局、冒充公开 API 或出现在 Caption 中。边界已清晰或无范围审阅价值时不机械添加。
8. **通用分类保持领域中立。** 通用设计系统 Gallery 不创建 Conversation 等产品领域分组；可复用组件按 Foundations、Composites 等设计系统角色归类。产品领域分类留给产品专属 Gallery 或产品文档；迁移分类时保持 Panel ID 稳定，避免破坏链接和置顶状态。
9. **复合展示不吞并子级矩阵。** 父组件 Panel 可用一个代表性组合覆盖公开子组件并减少重复父级表面；子组件 Panel 仍保留所有有独立审阅价值的属性轴，并移除非目标的父级视觉外壳。运行所必需的上下文 wrapper 可以保留，但必须视觉不可见且不引入父组件样式。

## 实现与交付

遵循目标 Gallery 的内容、Caption、边界提示、Token 与验证方式。新增或修改受控范围提示时验证开关两态，确认关闭只隐藏提示、不改变布局或真实边框；接入与验证细则见 [Gallery 审阅规则](references/gallery-rules.md#5-决定真实占位范围提示)。没有约定时使用中性、可比较且不改变组件行为的 fallback，不自动新增边界开关。

默认占位内容遵循 [Gallery 审阅规则](references/gallery-rules.md)：没有用户特别要求、项目事实源或当地约定覆盖时，文本使用 `Text`，图标使用 `Placeholder`；存在明确语义时才改用语义内容。

示例布局先比较可用宽度与示例固有宽度：完整容纳时单行展示，否则使用显式且均衡的网格或纵向排列；不要依赖自动换行决定比较结构。仅在组件自身边界不明显且真实占位范围对当前审阅有必要时添加范围提示；优先复用目标项目既有的 Dashed Light / line-light，无当地约定时才使用中性虚线 fallback。提示必须保持 Gallery-only，不得传入组件、改变组件布局或冒充公开 API。

浮层、菜单、Popover 等表面应直接展示其表面本身；只有触发方式属于组件公开契约且是审阅目标时，才把触发器纳入对比。保持语义排序、尺寸边界、键盘与焦点等可访问性检查。视觉验证默认只检查 Light；组件正确使用主题 color token 且不存在主题专属分支或已知主题风险时，不重复验证 Dark。只有这些条件不成立、用户明确要求或视觉证据表明 Dark 可能异常时，才追加 Dark 验证。按组件需要通过测试或临时验证检查视口、窄容器、溢出和响应式条件；结束后清理临时展示，不把验证案例留作正式 Gallery 内容。

项目专属顺序或映射值得复用时，建议用户选择是否写回目标仓库；未经授权不创建或更新项目配置，也不写入 Skill。运行与范围和风险相称的项目检查，报告证据、修改、验证、假设和未解决债务。
