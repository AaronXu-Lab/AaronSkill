# Design System Gallery 工作流

本文维护执行模式、取证边界与完成标准；展示判断由 [审阅规则](../references/gallery-rules.md) 对应章节维护，`workflow.svg` 是面向人的可视化投影。

## 1. 确定范围与模式

结合完整会话识别只读审查或实施修改。审查、审计、评估、给建议本身不授权写入；只读时，规则中的“移除、接入、调整”均转为建议。已有实施或方案批准直接沿用，不因进入新阶段重复询问。

默认处理指定的最小范围；批量、全量或一致性审计按用户授权展开。判断确需相邻展示、共享设施或只读使用证据时可以扩展读取并说明原因。修改公开 API、真实调用点、共享设施或项目配置仍须在任务授权内，只读取证不扩大写入范围。

## 2. 按问题取证

遵循目标目录适用的仓库规则，复用本会话中仍有效的项目约定。先定位本次 Gallery 实现、相关组件契约和能回答当前问题的设计或运行证据，再按 [入口路由](../SKILL.md#按任务读取) 选择规则章节；局部任务无需通读全部资料。

- 调整轴、default 或 Caption：查目标轴的语义、依赖、实际展示和当地元数据约定。
- 核对名称映射或修改 API：查宿主框架、保留属性、值域及已声明的映射配置。
- 处理范围提示：查现有边界开关、共享接入与涉及的渲染容器。
- 调整示例或分类：查相应内容、布局、导航和稳定标识约定。

只在项目声明配置路径时按实际格式读取，不猜测隐藏文件。目标已定位且证据足够时，缺少专门文档、default 模型或映射文件不阻塞；沿用可观察结构与最小 fallback，不补造配置。项目专属注册表、顺序和映射留在目标项目；值得持久化时，已有写回授权则执行，未授权则给出具体建议。

默认值与推荐组合的依据依次为：用户决策 → 项目契约或设计文档 → 组件运行时默认 → 必要且受控的只读使用证据。不能从组件结构推断“最常见用法”；证据不足但不影响当前结果时标记假设，会实质改变结果时按局部阻塞处理。

## 3. 审阅或实施

按所选章节建立当前范围的审阅结论。只读路径交付具体位置、证据、原因和可执行建议；实施路径完成授权修改，并以该章节的约束检查实际结果。新增或评估保留场景、增删展示轴或改变 Caption 表达的属性或状态时，先按 [正式展示筛选](../references/gallery-rules.md#2-选择设计审阅轴) 判断其用途，再处理排版与说明。

## 4. 验证与交付

实施完成包括运行适用检查、查看结果、修复本次变更引起且在范围内的问题，再重验受影响部分；第一版实现不是默认停止点。选择项目已有且与改动相称的类型、lint、测试、构建或视觉检查；[验证规则](../references/gallery-rules.md#9-验证与恢复) 说明主题、交互与临时展示要求，专项验收条件保留在对应规则章节。机器检查不能替代依赖关系和展示目的等语义判断。

交付范围、修改或建议、关键依据、实际验证及未解决项。只说明本次涉及的假设、API 债务、项目配置建议或展示例外；范围提示说明审阅价值与当地接入依据。恢复本次临时改变的预览状态并清理临时展示。

## 停止与局部阻塞

- 无法定位目标且缺少必要代码、设计或运行证据时，请求最少的缺失输入；仅缺少约定文档不停止。
- 映射、默认选择或语义依赖有多个会实质改变结果的解释时，只暂停受影响项并提出具体选择。代码、值域和契约能唯一确定时直接处理；Gallery 纠正方式唯一且不改 API 时，可在已有展示修改授权内执行。
- 某项需要未授权写入时，先完成独立可执行的取证、建议和获授权修改，报告受阻操作。
- 必要验证失败且无法在当前范围修复时，保留证据并交付局部结果；工具缺失或未运行的检查明确记为未验证，不宣称通过。
