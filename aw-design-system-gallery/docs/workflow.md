# Design System Gallery 工作流

本文档是 `aw-design-system-gallery` 的执行事实源。`workflow.svg` 是主线的视觉概览；详细判断集中在 references，避免三处重复维护。

## 1. 确定范围

默认从用户指定的最小 Gallery 范围开始。用户明确要求批量优化、完整审计或规范化时，按授权范围执行；局部判断确实需要相邻展示、共享基础设施或只读使用证据时，可以扩展读取，并说明原因。

修改真实调用点、公开 API、共享 Gallery 基础设施或项目注册资料仍需处于用户授权范围内。只读抽样不等于修改授权。

## 2. 发现目标项目约定

读取目标目录适用的仓库规则、设计规范和 Gallery 文档，识别：

- 项目对 Gallery、展示单元、标签和比较容器使用的真实术语与结构；
- 目标框架的平台保留属性、公开 API、内容入口和样式扩展机制；
- 项目声明的顺序、属性映射、Caption、内容、边界提示、Token 与验证约定；
- 边界显示开关及其受控 wrapper、属性、样式类或变量入口（若存在）；
- 项目专属配置的实际路径与格式。

不要假定项目使用特定框架、组件结构或 CSV。只有项目明确声明配置路径时才把它作为事实源。

## 3. 收集证据

读取目标展示实现、组件公开契约与直接依赖。默认值和推荐组合的证据优先级是：用户决策 → 项目契约或设计文档 → 组件运行时默认 → 必要且受控的只读使用证据。

证据不足时标记假设或询问，不把组件结构本身当成“最常见用法”的证明。

## 4. 建立审阅模型

读取 [Gallery 审阅规则](../references/gallery-rules.md)；涉及组件契约时再读取 [组件 API 设计约束](../references/component-api-design.md)。

只选择能帮助理解组件视觉、内容结构、布局或关键交互状态的公开设计轴。区分组件调用所需数据、公开 API 能力、Gallery 展示轴和调试 props；它们不必完全相同。先识别父轴与依赖子轴并保持相邻；无依赖时，才以几何/布局 → 主视觉 → 内容/槽位 → 状态 → 行为作为可调整的兜底。

正式 Gallery 聚焦默认示例及有设计审阅价值的真实属性轴／状态对比。仅为验证健壮性而设置的窄容器、限高滚动、溢出、异常输入、未知值回退或空数据，不默认纳入展示；需要验证时通过测试或临时验证完成，不因此新增正式 Panel 或场景区。审查范围内已有这类纯验证展示时，应移除对应展示，不能只删除 Caption 后保留场景。

按场景的目的与契约证据判断，不能仅凭“空”“错误”“滚动”等名称排除。Empty State 等本身具有明确设计含义的正式组件状态仍可纳入审阅；边界场景只有在用户明确要求展示，或确实属于当前组件正式设计契约时，才按其具体范围纳入，并说明依据，不顺带补齐其他边界案例。

对由父组件与公开子组件构成的复合组件，分别建立父级组合审阅与子级属性矩阵。父组件 Panel 可以用一个有代表性的组合覆盖其公开子组件，减少重复的父级表面，但该组合不能替代子组件自身仍有独立审阅价值的属性轴。子组件 Panel 应移除非审阅目标的父级背景、阴影、圆角、内边距等视觉外壳，使示例尽可能原子化；若 headless primitive 必须依赖 Root、Provider 或等价上下文才能工作，可以保留技术 wrapper，但它必须在视觉上不可见且不得引入父组件样式。

Caption 只能列出真实公开 API 的属性轴和组件状态。`container`、stage width、演示容器尺寸、布局 wrapper、触发方式等仅用于搭建示例时，属于场景条件，不得改写成组件属性或 Caption 轴。先按上述标准决定示例是否进入正式 Gallery；仅对已纳入展示且需要解释的条件使用 Panel description 或场景说明，说明位置本身不构成保留场景的理由。

如果目标 Gallery 使用 default 与 Caption 概念，default 元数据只列实际展示轴，并按依赖关系与最终展示轴顺序一致。没有展示轴时仍保留有意义的 default 示例和 Gallery 自己的 line-light 舞台边框，但省略整行 default Caption；是否归入 Temporary 必须独立判断。项目没有这些概念时，不强行引入。

判断是否需要显示组件的真实占位范围时，使用两个条件：组件自身边界的可辨识度，以及该范围对当前设计审阅是否必要。只有当组件自身边界不明显且显示范围能帮助完成审阅时，才补充范围提示；该判断与组件类别无关。优先复用目标项目既有的 Dashed Light / line-light 范围提示；提示必须是 Gallery-only 的外部视觉辅助，不得传入组件、改变组件布局或真实布局行为，也不得冒充公开 API 或出现在 Caption 中。边界已清晰或范围对当前审阅没有价值时，不机械添加提示；目标项目没有既有约定时，才采用中性虚线范围 fallback。

## 5. 实现授权范围

遵循目标 Gallery 的术语、结构、内容与视觉约定。没有约定时，使用中性、可比较且不改变组件行为的最小 fallback。

构造示例前，按 [Gallery 审阅规则](../references/gallery-rules.md) 的默认占位内容规则确定文本和图标：没有用户特别要求、项目事实源或当地约定覆盖时，文本用 `Text`，图标用 `Placeholder`；存在明确语义或特别要求时才使用其他文本或语义图标。

每个轴隔离单一变量，保持值的声明与阅读顺序，并尽量固定无关尺寸和内容。先估算容器可用宽度与示例固有宽度：完整容纳才使用单行；否则根据数量、固有尺寸、比较目标和容器宽度选择显式且均衡的网格或纵向排列，避免 flex 自动换行造成孤立末项、不稳定行数或误导性比较。只有在组件自身边界不明显且真实占位范围对当前审阅有必要时，才按当地约定增加外部的 Gallery-only 范围提示；优先复用 Dashed Light / line-light，无当地约定时才使用中性虚线 fallback，且不得改变组件布局、公开 API 或真实行为。

新增或修改范围提示前，定位项目的边界显示开关及共享接入方式。已有开关时，必须复用受其控制的入口，不能直接引用基础边框 token 或硬编码虚线绕过开关；若现有入口无法覆盖当前示例，先在授权范围内补齐共享机制再接入。具体 wrapper、属性、样式类和变量名从目标项目文档与代码获取，不写死在通用 Skill 中。项目没有边界开关时，遵循既有展示方式，不为此自动新增开关。

实现复合组件展示时，父级代表性组合负责说明整体构成，子级 Panel 负责隔离各自属性轴。不要为每个子级矩阵重复渲染相同的父级视觉表面，也不要因父级组合已经出现某个子级就删掉该子级的独立变体。技术上下文 wrapper 只承担运行依赖，不承担视觉呈现。

浮层、菜单、Popover 等组件直接展示浮层表面，不用演示触发器遮蔽目标；仅当触发方式本身是公开契约且属于审阅目标时才展示触发器。通用设计系统 Gallery 按设计系统角色组织可复用内容，例如 Foundations、Composites；不得新建 Conversation 等产品领域分组。产品领域分类保留在产品专属 Gallery 或产品文档。移动既有 Panel 的分类时保持 Panel ID 不变，以维持深链接、导航引用与置顶状态。

项目没有顺序或映射配置时，只为当前范围现场推导。结果值得复用时，建议用户选择是否写回目标仓库，并说明建议内容；未经授权不创建或更新项目注册资料，也不写入通用 Skill。

## 6. 验证与交付

运行目标项目已有且与范围相称的类型、lint、测试、构建或视觉检查。若现有工具能理解 Gallery 结构，可自动核对 default 元数据与展示轴是否同序；语义依赖仍由评审判断。人工核对正式 Gallery 没有混入纯健壮性验证面板或场景区，例外有明确的用户要求或当前组件设计契约依据，且 Empty State 等正式状态未被误删。核对 Caption 没有混入场景条件、分类保持领域中立且分类迁移未改变 Panel ID；同时检查范围提示是否仅在“边界不明显且审阅有必要”时出现、是否复用当地 Dashed Light / line-light、是否保持 Gallery-only 且未改变组件布局或公开 API；再检查语义排序、浮层表面、键盘、焦点和可见状态。按组件需要通过测试或临时验证检查尺寸边界、视口、窄容器、溢出和响应式条件；验证完成后清理临时展示，不将其留作正式 Gallery 内容。

主题视觉验证默认只运行 Light。若组件和 Gallery 正确使用主题 color token，且没有硬编码主题色、主题专属分支、已知主题缺陷或其他具体风险，则不重复运行 Dark；“项目支持 Dark”本身不构成每次都验证 Dark 的理由。只有上述条件不成立、用户明确要求或 Light/代码证据指向潜在主题问题时，才追加 Dark 验证。没有可靠工具时人工核对，不增加脆弱的文本匹配。

本次新增或修改了受开关控制的范围提示时，通过现有开关验证开启可见、关闭隐藏，且组件尺寸与布局不变；组件真实边框和边框 token 示例不得被误隐藏。范围涉及 Portal 或其他独立渲染容器时，覆盖其状态传递。保留项目既有默认值及偏好记忆行为，验证后按项目规范恢复预览；没有恢复规范时还原验证前的选择。

交付时报告审阅范围、证据、修改、验证、假设、API 债务，以及是否建议在目标项目持久化顺序或映射；涉及边界场景时，区分正式展示的契约或用户要求依据与测试／临时验证结果。对采用的真实占位范围提示，说明其审阅价值、复用了何种当地约定，或为何使用 fallback。复合组件还需核对子级矩阵是否完整、子级 Panel 是否去除了无关父级视觉外壳，以及必要的技术 wrapper 是否保持视觉不可见。

## 停止条件

- 无法定位目标 Gallery 或目标项目约定；
- 映射、默认选择或语义依赖存在会实质改变结果的歧义；
- 继续需要未获授权的 API、真实调用点、共享基础设施或项目配置写入；
- 验证持续失败且无法在授权范围内修复。
