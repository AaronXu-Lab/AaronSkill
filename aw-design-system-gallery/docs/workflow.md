# Design System Gallery 工作流

本文档是 `aw-design-system-gallery` 的执行事实源。`workflow.svg` 是主线的视觉概览；详细判断集中在 references，避免三处重复维护。

## 1. 确定范围

默认从用户指定的最小 Gallery 范围开始。用户明确要求批量优化、完整审计或规范化时，按授权范围执行；局部判断确实需要相邻展示、共享基础设施或只读使用证据时，可以扩展读取，并说明原因。

修改真实调用点、公开 API、共享 Gallery 基础设施或项目注册资料仍需处于用户授权范围内。只读抽样不等于修改授权。

## 2. 发现目标项目约定

读取目标目录适用的仓库规则、设计规范和 Gallery 文档，识别：

- 项目对 Gallery、展示单元、标签和比较容器使用的真实术语与结构；
- 目标框架的平台保留属性、公开 API、内容入口和样式扩展机制；
- 项目声明的顺序、属性映射、Caption、内容、边界提示、Token 与验证约定；
- 项目专属配置的实际路径与格式。

不要假定项目使用特定框架、组件结构或 CSV。只有项目明确声明配置路径时才把它作为事实源。

## 3. 收集证据

读取目标展示实现、组件公开契约与直接依赖。默认值和推荐组合的证据优先级是：用户决策 → 项目契约或设计文档 → 组件运行时默认 → 必要且受控的只读使用证据。

证据不足时标记假设或询问，不把组件结构本身当成“最常见用法”的证明。

## 4. 建立审阅模型

读取 [Gallery 审阅规则](../references/gallery-rules.md)；涉及组件契约时再读取 [组件 API 设计约束](../references/component-api-design.md)。

只选择能帮助理解组件视觉、内容结构、布局或关键交互状态的公开设计轴。区分组件调用所需数据、公开 API 能力、Gallery 展示轴和调试 props；它们不必完全相同。先识别父轴与依赖子轴并保持相邻；无依赖时，才以几何/布局 → 主视觉 → 内容/槽位 → 状态 → 行为作为可调整的兜底。

Caption 只能列出真实公开 API 的属性轴和组件状态。`container`、stage width、演示容器尺寸、布局 wrapper、触发方式等仅用于搭建示例时，属于场景条件，不得改写成组件属性或 Caption 轴。窄容器、溢出、响应式与触发情境若能揭示组件边界，仍必须保留视觉覆盖，并在 Panel description 或场景说明中解释；不能为了隐藏伪属性而删除验证场景。

如果目标 Gallery 使用 default 与 Caption 概念，default 元数据只列实际展示轴，并按依赖关系与最终展示轴顺序一致。没有展示轴时仍保留有意义的 default 示例和 Gallery 自己的 line-light 舞台边框，但省略整行 default Caption；是否归入 Temporary 必须独立判断。项目没有这些概念时，不强行引入。

判断是否需要显示组件的真实占位范围时，使用两个条件：组件自身边界的可辨识度，以及该范围对当前设计审阅是否必要。只有当组件自身边界不明显且显示范围能帮助完成审阅时，才补充范围提示；该判断与组件类别无关，不因组件是某种子组件、Item 或 Row 而自动触发。优先复用目标项目既有的 Dashed Light / line-light 范围提示；提示必须是 Gallery-only 的外部视觉辅助，不得传入组件、改变组件布局或真实布局行为，也不得冒充公开 API 或出现在 Caption 中。边界已清晰或范围对当前审阅没有价值时，不机械添加提示。

## 5. 实现授权范围

遵循目标 Gallery 的术语、结构、内容与视觉约定。没有约定时，使用中性、可比较且不改变组件行为的最小 fallback。

每个轴隔离单一变量，保持值的声明与阅读顺序，并尽量固定无关尺寸和内容。先估算容器可用宽度与示例固有宽度：完整容纳才使用单行；否则根据数量、固有尺寸、比较目标和容器宽度选择显式且均衡的网格或纵向排列，避免 flex 自动换行造成孤立末项、不稳定行数或误导性比较。只有在组件自身边界不明显且真实占位范围对当前审阅有必要时，才按当地约定增加外部的 Gallery-only 范围提示；优先复用 Dashed Light / line-light，且不得改变组件布局、公开 API 或真实行为。

浮层、菜单、Popover 等组件直接展示浮层表面，不用演示触发器遮蔽目标；仅当触发方式本身是公开契约且属于审阅目标时才展示触发器。通用设计系统 Gallery 按设计系统角色组织可复用内容，例如 Foundations、Composites；不得新建 Conversation 等产品领域分组。产品领域分类保留在产品专属 Gallery 或产品文档。移动既有 Panel 的分类时保持 Panel ID 不变，以维持深链接、导航引用与置顶状态。

项目没有顺序或映射配置时，只为当前范围现场推导。结果值得复用时，建议用户选择是否写回目标仓库，并说明建议内容；未经授权不创建或更新项目注册资料，也不写入通用 Skill。

## 6. 验证与交付

运行目标项目已有且与范围相称的类型、lint、测试、构建或视觉检查。若现有工具能理解 Gallery 结构，可自动核对 default 元数据与展示轴是否同序；语义依赖仍由评审判断。人工核对 Caption 没有混入场景条件、分类保持领域中立且分类迁移未改变 Panel ID；同时检查范围提示是否仅在“边界不明显且审阅有必要”时出现、是否复用当地 Dashed Light / line-light、是否保持 Gallery-only 且未改变组件布局或公开 API；再检查语义排序、尺寸边界、浮层表面、键盘、焦点、可见状态，以及适用主题、视口、窄容器、溢出和响应式条件。没有可靠工具时人工核对，不增加脆弱的文本匹配。

交付时报告审阅范围、证据、修改、验证、假设、API 债务，以及是否建议在目标项目持久化顺序或映射。

## 停止条件

- 无法定位目标 Gallery 或目标项目约定；
- 映射、默认选择或语义依赖存在会实质改变结果的歧义；
- 继续需要未获授权的 API、真实调用点、共享基础设施或项目配置写入；
- 验证持续失败且无法在授权范围内修复。
