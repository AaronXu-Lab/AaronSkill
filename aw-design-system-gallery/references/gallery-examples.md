# Gallery 示例

按动作读取对应小节：实例数量、交互归属、边界提示、展示宽度与排列、示例内容、父子展示。审查公开子组件是否内化时，再读组件契约的公开边界。

## 实例数量

Playground 默认只展示一个目标组件实例；Properties 中每个 value 默认一个对应实例。默认渲染器不应为覆盖数据场景同时输出多组实例，再将整组复制到每条属性比较中。组件成立所必需的组合（如组内项目）可作为一个目标组合，不能把组内子项数量误算为重复目标实例。

多实例仅用于组件成立所必需的组合或有明确比较目的的展示，须能说明实例数量与当前设计问题的关系。不同数据集、异常值、溢出或其他健壮性案例不因共享渲染器而进入默认示例；按正式展示筛选留给测试或临时验证，不为凑覆盖率增加场景。

验收先追踪默认渲染器及其在 Properties 的复用，核对实际目标实例数和保留多实例的理由；每个 value 的实例只服务当前比较。尺寸正确或成功加载不能证明多实例有设计必要性。

## 交互归属

先区分组件内在行为与调用方决定的效果。选择、展开、关闭等组件自身契约应真实运行并保持正确状态与回调；移除及空预览继续按共享 Restore 契约处理，不用空回调代替本该发生的内部行为。

文件预览、导航、提交、下载等由调用方决定的效果，默认示例使用无副作用回调承接，保留组件可点击外观、原生交互反馈、键盘与事件契约，不追加 Gallery 自制成功提示、伪预览或业务流程。无副作用不等于吞掉事件、破坏原生能力或禁用组件；默认示例不实际导航、提交或下载，必要状态仅用于真实组件契约。

只有为明确说明组合职责才独立演示调用方效果，并交代效果由谁提供，按 Interactive Demo／Composition 的共享方式展示，不从回调名称自动推导产品流程。验收沿事件处理器追踪效果来源，确认示例没有擅自补流程、反馈或外部副作用；组件真实交互与调用方效果分开判断。

## 真实占位范围提示

- 用“边界可辨识度 + 当前审阅的必要性”决定是否显示组件的真实占位范围：只有组件自身边界不明显，并且范围信息能帮助回答当前设计问题时才添加提示。该判断适用于任何组件类别，类别名称本身不构成触发条件。
- Bounds 开启后，每个被展示的目标组件只标最外层一层辅助边界；不同时给示例包装层、内部布局或内部子组件重复画 Bounds。多个必要目标实例各自一层；复用子组件不因此成为额外目标。真实组件边框可以与辅助边界同时存在，不能把真实边框误判为重复 Bounds 或为消除辅助线删掉真实边框。
- 优先复用目标项目既有的 Dashed Light / line-light 范围提示；没有当地约定时才选择等价的中性 fallback。
- 范围提示必须是 Gallery-only 的外部视觉辅助：不得传入组件、改变组件布局或真实布局行为，不得冒充公开 API，也不得出现在 Caption 中。边界已清晰或范围没有独立审阅价值时，不机械添加。
- 已有边界显示开关时，新增和修改的提示必须复用受开关控制的共享入口。直接使用基础 Dashed Light token 或硬编码虚线，即使开启时外观相同，只要关闭时仍可见，就不算完成接入。当前示例需要扩展支持时，在授权范围内补齐共享机制，不另建逐组件状态。
- 将提示与组件真实边框、边框 token 示例分开控制，不通过全局覆写基础边框 token 来关闭提示。提示出现在 Portal 或其他独立渲染容器时，确认其也能取得开关状态或受控样式。
- 通过项目现有开关验证本次涉及的提示：开启仅目标最外层一层可见、关闭辅助线隐藏，切换不改变尺寸与布局，真实边框和 token 示例不受影响。保留项目的默认值及偏好记忆方式；验证结束按项目规范恢复预览，没有规范时还原验证前选择。
- 具体接入名称与实现方式以目标项目文档和代码为准，不在通用 Skill 中固定项目专属类名、属性名或变量名。项目没有边界开关时，沿用其现有展示约定，不自动引入新开关。

## 展示宽度与排列

宽度、Playground 对齐、Properties 排列是三项独立判断，不从其中一项机械推导另一项。

- 展示宽度按组件角色选择自适应、固定宽度或占满可用宽度；以组件契约、使用职责和比较目的为依据，不由随意包装宽度决定，不把所有组件统一成同一种宽度。占满宽度的比较实例各自使用其所在行的可用宽度；固定宽度在窄容器中仍遵守有效尺寸与防溢出要求，不能用无限宽舞台掩盖问题。
- Playground 默认将实际目标组件水平、垂直居中；有明确布局职责或项目契约时采用相应对齐并说明依据。仅把一个占满宽度的包装层居中、让紧凑目标仍贴左不算达成。占满宽度组件按自身宽度职责渲染，不能为了居中缩窄；此规则不改变组件内部文字、图标或内容布局，也不决定 Properties 的排列。
- Properties 按比较目标、示例尺寸与容器宽度选择横向排列并自动换行、明确网格或纵向逐项排列。横排／换行须保持顺序、间距和每个实例的可辨识性；相邻实例若易误读为同一组件，应改为纵向每行一个。固定宽度本身不意味着必须横排或纵排，不能用统一布局代替判断；网格或换行不得产生误导分组、不稳定阅读顺序或溢出。

验收分别记录目标宽度的依据、实际目标对齐、比较实例是否独立可辨；从渲染器和样式判断，必要时按源码优先策略复核实际宽窄容器。仅包装层尺寸正确不证明目标组件对齐或排列正确。

## 可比较示例

- 优先使用目标 Gallery 的内容和 Caption 语法。没有约定时使用中性、清楚且不会被误认成产品默认值的内容。
- 在没有用户特别要求、项目事实源或当地约定覆盖时，Gallery 示例中的通用默认文本使用 `Text`，描述角色允许使用 `Description`，默认图标使用 `Placeholder`。`Description` 是允许的角色占位，不需要额外业务语义或特别要求，不能仅因它不是 `Text` 就判错或要求替换；这不意味着所有描述必须改成 `Description`，也不扩大为任意业务文案。其他文本或语义图标仍需明确语义、项目依据或特别要求；该规则只约束 Gallery 示例的默认占位内容，不改变组件 API 或产品文案。
- Playground／Properties 展示 `custom` 等由调用方提供的任意自定义内容插槽时，统一用英文 `Content` 加虚线边框表示，复用目标项目既有的内容占位组件；不要在通用插槽示例内填入具体业务组件或嵌套组合。真实组合、嵌套层级放在明确的场景 Example 中展示，不把该场景反向复用为通用插槽的默认或属性比较内容。
- 先判断插槽职责：上述规则仅针对任意自定义内容；文本、描述、图标等专用插槽继续沿用各自占位约定，不能全部替换为 `Content`。占位尺寸按组件与当地展示需要确定，不规定跨项目固定高度；虚线是插槽占位的识别边界，按当地机制与目标组件的 Bounds 辅助线区分，不重复注册成额外目标边界。验收默认及各属性实例均使用该占位，真实组合仍位于明确的场景 Example。
- 同一示例内的并列文本项使用 `Text 1`、`Text 2` 等序号，例如 Dropdown 选项、Tab、菜单项和图表分类。序号用于区分同级内容；不同属性值的比较示例仍复用同一组内容，不因示例的位置改变文案。标题、描述等不同角色的槽位不视为同级文本项。
- 对 Dropdown、Select、Menu Button 等“外部触发器 + 内部浮层”组合，分别确定两处占位文案：外部单个触发器显示 `Text`；浮层内多个并列选项显示 `Text 1`、`Text 2`、`Text 3` 等。浮层只有一个菜单项时用 `Text`。不要因为默认选中了第一项，就把外部默认展示写成 `Text 1`；选项的编号用于浮层内部区分，不表示触发器需要编号。
- 触发器与浮层只是展示位置不同，不自动构成字段—值关系；只有实际展示了独立字段名及其所属值时，才使用下方的 `Text n / SubText n` 规则。例如普通下拉外部是 `Text`、内部是 `Text 1 / Text 2`；明确的字段和值组合才是 `Text 1: SubText 2`。
- 将占位展示与选择状态分开：通过组件已有的触发器内容、选中值渲染或 Gallery 适配能力实现外部 `Text`，保留真实选项 value、选择回调与内部选中标记；不要把所有选项 label 都改成 `Text`，也不要用 CSS 伪元素盖住真实文本、伪造未选中状态或吞掉回调。若当前 API 将两处文案绑定，先核对已有扩展能力；不要仅为占位文案擅自扩展公共 API。交互示例确实需要外部回显选中项时，可在选择后显示对应 `Text n`，但默认与重置后的外部展示仍为 `Text`。验证默认触发器、展开选项、选择反馈和重置四处，避免只修截图中的一处。
- 存在明确的字段—值或父项—选项从属关系时，区分角色：字段／父项使用 `Text n`，所属值／选项使用 `SubText n`，组合显示为 `Text 1: SubText 2`。不要把两层都写成 `Text`，以免误读为同级内容；字段序号与值序号各自编号，值序号可在每个字段内重新开始。无从属关系的普通并列选项仍使用 `Text n`。
- 需要长段落展示时，可以使用下方统一的 Lorem ipsum；同组比较保持段落一致，不为制造视觉差异添加业务叙事。
- 当按钮与 value text 并列出现、需要区分内容和操作时，按钮文案允许使用 `Button`，例如 Detail Activity 的 trailing 按钮；不要机械替换成 `Text`。有明确操作语义的文案仍按其语义保留。
- 需要多个图标切换的通用示例（例如 Action Button 的 hoverIcon）默认主图标使用 `Placeholder`，次图标统一使用 `icon/selection`。在实现前核对目标项目中该设计图标的映射，不凭名称猜成其他图标；明确的业务或交互语义仍优先。

长段落占位：

```text
Lorem ipsum dolor sit amet, consectetur adipiscing elit, sed do eiusmod tempor incididunt ut labore et dolore magna aliqua. Ut enim ad minim veniam, quis nostrud exercitation ullamco laboris nisi ut aliquip ex ea commodo consequat. Duis aute irure dolor in reprehenderit in voluptate velit esse cillum dolore eu fugiat nulla pariatur. Excepteur sint occaecat cupidatat non proident, sunt in culpa qui officia deserunt mollit anim id est laborum.
```

- 内容、标签和示例数量应与所表达的比较关系对应；布尔或枚举值的展示顺序以项目约定和可理解性为准。
- 若需要判断或调整真实占位范围提示，读取 [范围提示](gallery-examples.md#真实占位范围提示)。
- 比较布局按 [展示宽度与排列](#展示宽度与排列) 分别确定目标宽度和排列方式，不以宽度直接推导排列。
- 浮层、菜单、Popover、Tooltip 的视觉属性优先直接展示表面。必须通过交互才能辨别的公开属性（如 `closeOnOutsideClick`，或形成可感知动画差异的 `animated`）也可成为属性轴，允许在独立 Block 中用按钮分别触发各属性值的真实实例，不必强行绘制无差异的静态表面。Playground 提供对应属性设置与体验当前组合的触发器；需要独立交互体验时按 [Interactive Demo](component-sections.md#interactive-demo) 展示，复用统一演示方式，不为触发按钮额外包一层 Block 背景。属性轴内用于比较不同值的触发按钮仍保留在该轴的 Block 中；实例继承当前 default，仅覆写被比较的属性，重置遵循默认设置的统一机制。Caption 标注真实属性和值，触发按钮应清楚区分所验证的值；不要把触发手段本身伪装成属性。
- 不用无限宽舞台掩盖布局问题；尺寸与内容边界按 [验证与恢复](verification.md) 验证。

## 父子组件展示

- 父组件页面可以优先采用一个有代表性的组合，在同一整体示例中覆盖其公开子组件，以说明构成关系并减少重复展示相同的父级表面。代表性组合应服务于整体审阅，不要求枚举每个子组件的全部变体。
- 在父组件的组合示例中，嵌入的子组件默认使用其运行时默认属性；只有该子属性本身属于当前审阅目标，或明确的项目契约／推荐组合要求显式配置时才覆写。先核对子组件实现默认值，不要为了让组合示例显得醒目而任意指定尺寸、颜色或视觉样式；若确需覆写，应能说明它如何服务于父级组合的展示目的。
- 父级组合覆盖与子级属性矩阵承担不同任务：前者展示整体构成，后者隔离子组件自身的设计空间。父级组合中出现过某个子组件，不构成删除该子组件属性轴或变体的理由。
- 子组件页面应移除不属于当前审阅目标的父级视觉外壳，包括父级背景、阴影、圆角、内边距及其他装饰性表面，使每个示例尽可能只呈现目标子组件。不要为了模拟完整父组件而重复引入会干扰比较的视觉环境。
- 子组件仍需保留所有具有独立设计审阅价值的公开属性轴。是否保留一个轴，应由它能否形成值得比较的视觉、内容结构、布局、动画行为或关键交互差异决定，而不是由父组件是否已经展示过它决定。
- 必须依赖 Root、Provider 或等价上下文才能工作的 headless primitive，可以使用最小技术 wrapper 满足运行契约。wrapper 必须在视觉上不可见，不得引入父组件样式、改变目标子组件布局，或被误认为 Gallery 中正在审阅的表面。
