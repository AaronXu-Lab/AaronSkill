# Gallery 分类与稳定标识

分类或导航迁移、新增组件、组件部件或槽位变化，以及完整审计时读取；组件身份改名另读组件契约，Section 深链实现另读页面操作。

- 通用设计系统 Gallery 按设计系统角色组织可复用内容，例如 Foundations、Composites，以及目标项目已有的等价通用分类。
- 不在通用 Gallery 中创建 Conversation、Commerce、Inbox 等产品领域分组。领域叙事、业务任务和产品专属组合留在产品 Gallery 或产品文档中。
- 组件跨产品复用时，以它在设计系统中的主要角色归类，不以当前产品中的使用位置归类。
- 仅调整分类时只改变导航归属，不改变稳定的页面 ID。用户授权组件身份改名时，按 [组件身份规则](component-api-design.md#5-组件身份与-gallery-映射) 同步路由与引用，不能用稳定标识规则阻止已授权改名。迁移前后核对深链接、引用和置顶状态仍指向同一页面。

## Foundations、Composites 与 Container

目标项目使用这三类或等价分类时，按下列顺序判断，命中即停：

1. **Container**：纯容器层控制，只负责排列、分组、折叠、浮层定位或溢出收纳等容器行为，自身不拥有可见组件或视觉样式。可见内容全部来自调用方传入或已公开的组件。容器若自带专属的可见控件（例如私有的溢出按钮），说明实现越过了容器职责，报告实现问题，不改判为 Composite。
2. **Composite**：满足任一条件。
   - 由多种**不同类型**的部件或槽位组成，调用方会分别搭配各部件的设计属性。例如顶栏的前导／标题／尾部，菜单的 Header／Item／Footer，状态反馈的图标／标题／描述／操作。
   - 在通用部件上叠加特定产品或任务语义的特化版本。例如通用 Chip 之上的上下文 Chip、通用 Item 之上的资产卡、为确认／取消任务固定的弹窗操作区。
3. **Foundation**：其余组件。它是通用、按整体使用的单元，调用方不拆开它，也不分别搭配其内部部件。
   - 重复同一种部件不构成组合，例如由同类项组成的 Tabs、Pagination、Breadcrumb、分段定位线。
   - 实现复杂、内部引用其它组件，或内容格式丰富，都不构成组合，例如 Button、Calendar、Markdown、Code Block。
   - 带有产品语境但本身是单一整体的组件仍归 Foundation，例如单条建议项。

不作为判断依据：代码是否 import 其它设计系统组件、实现复杂度、是否属于对话等特定领域、在当前产品中的使用位置、历史所在源码文件。

### 主动检查

- 新增组件、改变组件的部件或槽位结构、拆合子组件时，按上述顺序复核其分组；完整审计逐组件复核。只读任务把不符项写成建议；分类不符归 Components 第 1 项（页面结构）报告。
- 同类组件被分到不同组时（如两个 Chip、两个 Item），先检查它们是否在第 2 条的“特化语义”上有区别；说不出区别时视为分类不一致。
- 规则无法唯一判定时，暂停受影响组件的归类并询问用户。用户裁定的项目特例和组件清单记录在目标项目，不写回本 Skill。
- 实施迁移仍遵守上方稳定标识要求：只改变导航归属，核对深链接、引用、置顶和小窗预览仍指向同一页面。
