# 其他页面标准

用于 Docs、Styles、Scenario、概览与导航等非组件详情页。按页面目的读取对应项，不套用 Components 的十章节结构；若同一任务涉及组件页，再进入 Components 路由。

## 页面职责与结构

先确认页面类型、受众和需要回答的问题，复用项目现有 MDX 模板、共享布局、语言与内容来源。核对标题层级、章节顺序、引用与导入、代码围栏、示例组件参数、链接及实际渲染；删除空占位或重复内容的建议须有当前范围依据。项目未采用 MDX 时检查其等价内容源，不引入新格式。

## 按页面类型判断

- Docs：说明目标概念、适用范围、前提与可执行步骤；示例和 API 引用应与当前实现一致，有失败或限制条件时如实说明。
- Styles：名称、Token、语义、主题与示例相符；区分规范和演示辅助，不从页面效果推断不存在的 Token 或契约。修改代码或主题映射仍须在授权内。
- Scenario：解释场景目标、相关组件及组合关系，示例真实成立；产品专属叙事留在相应场景，不反向改成通用组件分类。
- 概览／索引：覆盖其声明范围、分组可理解、名称与目标一致，避免重复或失效入口。

## Docs 文章

默认读者是正在做设计决策的设计师。正文写清在什么情况下选择哪种做法、用户会看到什么，以及哪些例外会改变选择。Develop Guide 面向开发者和 AI，可按任务说明接口、前提、调用步骤和失败条件。

页面结构、章节职责和顺序沿用 Gallery 的 Docs 规则与项目模板。具体段落的说明和措辞交给 `technical-writing`，使用前按[关联 Skill 检测与管理](related-skills.md)处理。其写作建议在既定结构、读者和项目语言规范内使用。

Core Rules 源文件沿用项目的规则块（如 `DocRule`），不手写 Markdown 列表；页面呈现为项目约定的 bullet list（加粗标题＋缩进正文）。项目以文章 ID 名单等方式控制该呈现时，新建或核对文章须确认已纳入并实际渲染出 bullet。每块一个标题、一个独立判断；正文中有先后的步骤用有序列表，并列条件用无序列表。只是另一条规则反向表述（如宽度恢复按折叠的相反顺序）或可由其他规则直接推出的情况，并入原规则，不单独成块；复述其他文章规则时只保留链接。

优先在展示区演示具体例子。正文保留判断条件和设计规则，读者从下方示例就能看到的标题、按钮组合或操作过程无需再复述。核对展示区是否确实呈现规则所指的状态。

正文提及规则指定的关键界面 Label 时，各语言统一用规范英文，并通过项目的 CodeBlock Inline（行内代码）呈现。例如「用户可以放弃本次操作时，用 `Cancel`。」周围的说明按页面语言撰写。

## 导航与验收

分类迁移读 [稳定标识](gallery-navigation.md)，Section 操作变化读 [共享页面操作](gallery-page.md#section-头部与深链)。已有链接仍核对目标和锚点；不做全站关联覆盖普查；已知独立案例的入口按 [关联文章](gallery-page.md#关联文章) 检查。

按改动核对内容源和实际页面；涉及交互、主题或响应式时按 [验证与恢复](verification.md) 检查受影响项。设计系统校验的其他页面结果按 [统一报告](audit-report.md#其他页面) 单独列示，不伪装为组件。
