# 其他页面标准

用于 Docs、Styles、Scenario、概览与导航等非组件详情页。按页面目的读取对应项，不套用 Components 的十章节结构；若同一任务涉及组件页，再进入 Components 路由。

## 页面职责与结构

先确认页面类型、受众和需要回答的问题，复用项目现有 MDX 模板、共享布局、语言与内容来源。核对标题层级、章节顺序、引用与导入、代码围栏、示例组件参数、链接及实际渲染；删除空占位或重复内容的建议须有当前范围依据。项目未采用 MDX 时检查其等价内容源，不引入新格式。

## 按页面类型判断

- Docs：说明目标概念、适用范围、前提与可执行步骤；示例和 API 引用应与当前实现一致，有失败或限制条件时如实说明。
- Styles：名称、Token、语义、主题与示例相符；区分规范和演示辅助，不从页面效果推断不存在的 Token 或契约。修改代码或主题映射仍须在授权内。
- Scenario：解释场景目标、相关组件及组合关系，示例真实成立；产品专属叙事留在相应场景，不反向改成通用组件分类。
- 概览／索引：覆盖其声明范围、分组可理解、名称与目标一致，避免重复或失效入口。

## 导航与验收

分类迁移读 [稳定标识](gallery-navigation.md)，Section 操作变化读 [共享页面操作](gallery-page.md#section-头部与深链)。已有链接仍核对目标和锚点；不主动审计关联覆盖或要求增加关联入口。

按改动核对内容源和实际页面；涉及交互、主题或响应式时按 [验证与恢复](verification.md) 检查受影响项。设计系统校验的其他页面结果按 [统一报告](audit-report.md#其他页面) 单独列示，不伪装为组件。
