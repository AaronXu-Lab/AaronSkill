# 属性顺序与依赖

仅排序时读取轴排序或 Value 排序；修改适用条件时读取依赖及验收。两者均不要求重选所有正式场景或重审全部 API。

## 轴排序

本文的设计属性定义表指项目已有的轴元数据或驱动编辑器的数据源，不要求页面新增 API Props 表。

新增或修改组件时，设计属性默认按以下语义分组排序；同类属性在不同组件中保持稳定的相对位置，不按字母排序或直接照搬代码声明顺序：

1. **尺寸与布局**：尺寸、方向、宽高、对齐、密度。
2. **外观与语义**：视觉样式、颜色、语义色调。
3. **内容构成**：内容类型、可选部件、显示开关、数量。
4. **交互模式**：选择模式、触发方式、交互策略。
5. **当前值与状态**：选中、勾选、展开、加载、禁用等；无依赖约束时禁用状态放在本组末尾。
6. **内容编辑与插槽**：可编辑文本、图标替换、内容插槽。控制插槽是否出现或采用何种结构的属性归入内容构成，实际内容编辑项放在这里。

先按实际语义判断属性类别，同名字段不一定同义。仅排列组件已有设计属性，不为凑齐分组而新增属性或展示轴。

以下规则优先于默认分组：

- 标出决定结构或适用范围的父轴，把子轴紧跟父轴，保持依赖组连续；多项共同前提按主要结构依赖组织，不因通用禁用状态也参与条件判断就拆散结构组。
- 决定整体结构和后续可用属性的核心模式可以提前，并记录例外依据。跨组件同名同义属性在无依赖冲突时保持相对顺序。
- 已明确的用户决策或项目契约优先；例外及逐组件顺序留在目标项目，不在 Skill 中维护跨项目固定字段优先级。

排序示例：`size` → `style`、`fillColor`、`fillHover`（依赖组连续）→ `type`、`dropdown` → `disabled`。决定加载结构的 `type` 可先于仅适用于某种结构的 `size`。示例说明语义及依赖，不是逐字段强制清单。

设计属性定义表（若项目已有）、Playground 编辑项、Properties 比较轴与已有 Caption 必须使用同一顺序来源；表格已驱动编辑器时，调整表格并同步底层设计轴，避免脱离文档或独立预览时回到旧顺序。只显示于编辑器的属性保留其约定，比较轴按同一顺序过滤，不能为追求列表完全一致而新增比较块或取消适用条件。

仅调整属性轴顺序时，只移动已有属性及相关展示定义；保留属性名、默认值、枚举值及其顺序、标签、依赖条件、状态和组件行为，不要求修改调用处或代码 Props 的声明顺序。验证改动前后的属性集合及定义一致，并在浏览器抽查表格与 Playground 同序、依赖生效、已有值保留及显式 Reset。项目已有属性值排序约定继续适用，但不能借纯顺序任务重选默认值或扩大为 API 调整。

## Value 排序

轴内取值优先按自然顺序排列；无自然顺序时按语义分组，同义值跨组件保持稳定的相对顺序。不按字母排序，不照搬代码枚举声明顺序，也不因某值是默认值就将它移到首位。默认值只决定初始选中项。

| 值的类型 | 排序依据与示例 |
| --- | --- |
| 有无、开关 | 无到有、关闭到开启：`none` 在具体类型前，`false → true`。 |
| 尺寸、数量、强度 | 从小到大或从弱到强：`xs → sm → md → lg → xl`；`ghost → outline → light → fill`。语义尺寸按实际占用空间排序，例如 `compact → default`；没有稳定大小或强弱关系时按语义分组，不伪造阶梯。 |
| 内容组合 | 从简单到丰富：`text → icon+text`、`title → title+description`；互不包含的类型不强行比较复杂程度。 |
| 方向、位置 | 按阅读或空间顺序：`leading → center → trailing`、`top → right → bottom → left`；同义方向跨组件保持一致。 |
| 状态 | 按组件实际状态关系：`unselected → selected`、`uploading → completed → failed`。分支结果相邻，不把错误态误写成必经步骤，不强加通用线性生命周期。 |
| 不同功能类型 | 同类相邻，组间稳定：无内容 → 展示信息 → 执行动作 → 选择或设置；不强行比较不同控件的复杂程度。 |

功能类型的相对顺序示例：`none → text → badge → button → dropdown → segment → radio → checkbox → switch`。其中 `text`、`badge` 是信息展示，`button` 是动作，后续控件为选择或设置。组件只支持其中一部分时保留相对顺序，不新增值、不重命名现有值；此例用于说明分组，实际取值清单仍由目标项目维护。

设计属性定义表（若项目已有）、Playground 下拉选项、Caption 与比较示例使用同一套 value 顺序；条件过滤只取其子序列。只调整 value 顺序时保留取值集合、默认值、显示标签、设计值与代码值映射、依赖条件及行为；不能用数组首项替代既有默认值，也不要求更改代码枚举或调用处。验收时对照前后定义，确认只有排列变化，并抽查初始选中、切换、比较顺序和 Reset。

## 排序约定的维护

后续调整属性或 value 顺序时，主动提醒用户核对并同步本 Skill，说明拟写回的规则变化或可复用例外；获用户许可后及时同步相关规则、工作流及版本索引，并运行 Skill 维护校验。完整会话中已有明确写回许可时直接沿用，不重复确认；项目排序的授权本身不等于修改 Skill 的授权。

通用排序规则只在本节维护，项目 `AGENTS.md` 引用本 Skill 及相关章节，不复制整份规则。具体组件顺序清单与项目专属例外留在目标项目。若只是按已有规则重排，核对后说明 Skill 已覆盖，无需为留下修改记录而重复改写通用规则。

## 属性依赖与失效展示

先区分三个位置：组件本体按契约隐藏不支持的结构（例如某模式没有拖动手柄）；Properties 保留设计轴以解释适用条件；Playground 配置控件用于保存当前设置。组件本体的隐藏不能推导为删除 Gallery 的配置入口或属性轴。

Playground（即 Default 编辑器）中的依赖控件与 Properties 子轴比较 Block 使用一致的禁用处理，并共用同一份依赖判断与 `disabledReason`；不得各写一套。只禁用前提不满足的依赖项，不禁用整个 Playground 或无关控件，保留入口、轴说明和用户值。

每个 Properties 轴继承当前 Playground 值，仅覆写当前轴。子轴前提不满足时，依赖控件、比较 Block 及其内部内容均灰化，并用 `inert` 阻断点击、键盘操作和内部触发器响应；不要隐藏该轴，也不要为制造差异而偷偷覆写前提属性。两处都由 `inert` 范围之外的外层触发器承接 hover 与键盘聚焦 Tooltip。非 DOM 平台使用能同等阻断交互的机制；只有灰化、`aria-disabled` 或 `pointer-events: none` 不能证明鼠标与键盘均被阻断。前提满足后恢复交互与原设置，不改组件契约或清空用户值。

### Tooltip 文案

统一使用 `Set 「属性名」 to 「值」 to enable`，属性名与每个值名均用「」包裹，并使用 Gallery 设计名称。多个可选值用 `or`：`Set 「type」 to 「icon」 or 「icon+text」 to enable`；多个同时成立的条件用 `and`：`Set 「type」 to 「icon」 or 「icon+text」 and 「dropdown」 to 「true」 to enable`。Tooltip 不得出现 `Default`，它是代码内部概念。Playground 与 Properties 直接复用同一份 `disabledReason` 文案。

### 依赖验收

在当前有效设置中先保存一个非默认子轴值，切换到前提不满足的模式，再切回并单独测试显式重置：

- 失效时 Playground 依赖控件、轴说明与 Properties 比较 Block 仍可见，依赖控件与整块内部均呈禁用态；示例没有偷偷改回父轴前提。
- 鼠标点击、拖动（若适用）、Tab 与 Enter／Space 不触发依赖控件或 Block 内部交互；外层 hover 和键盘聚焦均能读取明确的启用条件。
- 前提恢复后交互恢复，用户先前设置仍在；前提切换不等于重置，只有显式重置才按项目默认机制处理。
- 分别核对组件本体、Playground 依赖控件与 Properties 比较块，确认后两者共用 `disabledReason`、提示格式一致，记录实际观察。未运行的交互检查明确标为未验证。

非约束示例：`surfaceMode → surfaceTone → surfaceHover`、`trailingSlot → trailingInteraction`、`sortable → sortDirection`、`contentMode → contentDetail`、`layoutMode → layoutPreset`。这些名称仅说明依赖形态，不是推荐 API。

如果项目使用 default 元数据与分轴展示，default Caption（存在时）的轴顺序必须按依赖关系组织，并与后续展示轴顺序逐项一致，而不只是集合相同。不要在 Skill 中维护具体项目的组件顺序表或属性清单。项目没有 default 或 Caption 概念时，不为满足 Skill 而新增。

选择 default 的具体值或推荐组合时，再读取 [默认与状态](component-api-design.md#3-默认与状态)。仅调整已有轴顺序无需重选默认值。
