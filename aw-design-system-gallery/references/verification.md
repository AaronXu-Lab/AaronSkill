# 验证与恢复

只核对本次涉及的规则和受影响行为，专项验收随对应专题维护。有结构化验证入口时可自动检查 default 与展示轴是否同序；依赖语义、正式展示目的和例外依据仍需基于实际结果评审，不以脆弱文本匹配代替。

## 源码优先，必要时浏览器复核

1. 先审查 MDX／内容源、组件实现、属性元数据、样式和相关调用，批量判断结构、文案、排序、默认值、API 映射、依赖及继承逻辑，形成初步问题矩阵。能从源码确定的缺陷直接记录证据，无需为再次证明同一缺陷打开页面。
2. 优先复用与当前代码及条件一致的已有行为测试、项目验证脚本和本轮有效运行证据。按实际问题运行相关检查，不为每个组件重复创建相同测试或重复验证共享机制；共享实现证据仅覆盖已确认共用且无独立分支的部分，不能外推到不同实现。
3. 只有源码和已有测试不足以回答、发现疑似异常，或需要观察实际布局、遮挡、动画效果、焦点与重复交互等运行表现时，才使用浏览器复核对应组件和最小操作路径。明确本次复核要解决的问题，不默认逐页遍历所有控件、尺寸、主题与状态组合。用户明确要求浏览器完整验收或项目有适用的强制检查时，遵循该要求。
4. 保留已有浏览器结论，改用源码优先不重做已完成步骤。只对新增疑点、失败或发生变更的部分补验；复核后恢复临时预览状态。

各专题的验收描述需要成立的结果，不意味着每次都必须用浏览器重新证明。源码、静态检查、行为测试、浏览器观察分别说明能支持的结论；类型通过不等于运行行为通过，静态截图不能证明动画与交互。源码能够判定的项目可以给出源码检查结论；仍需运行证据且本轮未验证的具体行为标待验，不能把整个维度未经区分地判通过，也不因未开浏览器就把纯文档或明确的源码判断全部标待验。

实例数量、Anatomy 必要性、状态形态抽象及事件效果归属须按对应专题作语义判断。尺寸、加载或截图检查仅证明其直接覆盖的工程结果，不能替代这些判断或据此将整项标为通过。

## 按需验证与恢复

- 主题视觉验证默认只运行 Light。组件和 Gallery 正确使用主题 color token，且无硬编码主题色、主题专属分支、已知主题缺陷或其他具体风险时，不重复运行 Dark；项目支持 Dark 本身不构成理由。上述条件不成立、用户明确要求或 Light/代码证据指向主题问题时，追加 Dark。
- 涉及动画轴时，以相同内容、状态切换与触发条件实际比较各值，记录动画启用／关闭或其他可感知的过程差异；不要只检查起止截图。未观察到运行过程时明确标为未验证，不据此判定该轴无设计价值。
- 涉及交互或展示结构时，复核语义排序、键盘路径、焦点可见性、可访问名称与状态表达。
- 按组件与改动需要，用测试或临时验证检查最小/最大有效宽度、内容扩张、截断、换行、滚动、overflow 和响应式行为。是否正式展示由 [正式展示筛选](design-axes.md) 判断，验证完成后清理临时展示。
- 修改范围提示时，开关两态、Portal、真实边框与偏好恢复按 [范围提示](gallery-examples.md#真实占位范围提示) 验收。其他临时预览选择也按项目规范恢复，无规范时还原验证前状态。

修复、重验、局部失败与交付状态按 [工作流](../references/workflow.md#4-验证与交付) 处理。
