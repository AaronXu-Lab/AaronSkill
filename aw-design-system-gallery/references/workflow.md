# Design System Gallery 工作流

本文只维护执行顺序、授权与交付边界。判断标准按 [入口路由](../SKILL.md#按任务读取) 进入专题；同一规则只在专题中维护，[流程图](../docs/workflow.svg) 为本文的可视化概览。

## 1. 确定范围与模式

结合完整会话识别只读审查或实施修改，沿用已有授权。只读时，规则中的“移除、接入、调整”转为建议。默认处理指定的最小范围；批量或完整审计按用户授权展开。修改公开 API、调用点、共享设施、项目配置和 Skill 本身均须在对应授权内。

## 2. 按问题取证

遵循目标目录规则，定位本次 Gallery、相关组件契约及能回答问题的设计或运行证据。先按入口区分其他页面与 Components，再按任务读取对应标准的小节；只有新增证据引出关联判断时才扩展。完整 Components 校验逐组件覆盖九项判断；其他页面按页面职责校验。局部任务只读相关项，完整校验仍不自动授权 API 修改或子组件内化。

目标项目事实源优先。复用其展示单元、内容适配器、Caption、Token、边界提示与配置格式；只读取已声明的配置路径，不猜测隐藏文件。缺少专门文档但目标和证据足够时，使用可观察结构与最小 fallback，不补造配置。项目专属注册表、顺序、映射及例外留在目标项目。

涉及默认值或推荐组合选择时，依据依次为：用户决策 → 项目契约或设计文档 → 组件运行时默认 → 必要且受控的只读使用证据。不能从结构推断“最常见用法”；仅排序或换占位内容时不重选默认值。

取证采用 [源码优先、必要时浏览器复核](verification.md#源码优先必要时浏览器复核)：先批量审查内容源、属性定义和实现，复用相关已有测试及有效运行证据，再针对未解决的问题选择最小浏览器路径。完整校验覆盖九项判断，不等于每个组件都重复执行完整浏览器巡检。

不做全站关联覆盖普查；已有文章关联及已知独立 Example 的入口，按 [关联文章](gallery-page.md#关联文章) 核对目标与呈现。处理当前组件的案例归属时，只定位用户指出、当前正文已引用或当前迁出的案例所对应的文章，不扩展为其他主题的检索。

## 3. 审阅或实施

先完成所选专题的判断，再处理呈现与实现。Anatomy 等可选章节先判断适用性；Anatomy 以组件自身拥有的可视构成为依据，调用方内容、上下文或行为管理不构成必需理由，Composition 依赖说明另行判断。新增或改名轴先读取正式展示筛选及 API 命名预检；已有轴只调整顺序不触发全页命名审查。属性适用条件变化须在实施前识别依赖并读依赖规则；不能因组件本体隐藏结构而删掉 Gallery 配置或比较轴。

按 [Composition](component-sections.md#composition) 区分组合关系说明与完整任务案例；已有独立 Example 时检查重复维护，并按关联文章规则保留入口。发现案例正文放错位置归第 8 项，已知 Example 缺少关联入口归第 1 项；不另加报告维度。

核对部件身份、职责和配置归属：Anatomy 按 [部件命名与职责说明](component-sections.md#anatomy) 检查，组合 API 按 [组合职责与属性归属](component-api-design.md#组合职责与属性归属) 追踪到实际子组件；同步检查公开契约、Playground、Properties 与用法说明的一致性。发现职责重复时报告实现层建议，不只改展示文案，也不因审查自行迁移 API。

在现有九项内复核示例语义：多实例是否必要、Anatomy 是否有独立自身部位、互斥状态是否误拆部位、事件效果归组件还是调用方。按 [实例数量](gallery-examples.md#实例数量)、[交互归属](gallery-examples.md#交互归属) 和 Anatomy 标准判定，不另增检查项。

检查占位文案时，按 [可比较示例](gallery-examples.md#可比较示例) 区分通用占位、描述角色与有助于理解用法的具体文案；按该节判断何时保留简短语义标签，不机械替换为 Text。 遇到任意自定义内容插槽时，同节核对 Content 加虚线占位与场景 Example 的分工；文本、图标等专用插槽不套用通用内容占位。

涉及舞台或比较布局时，分别按 [展示宽度与排列](gallery-examples.md#展示宽度与排列) 判断目标宽度、实际组件对齐与比较排列，按范围提示规则核对最外层 Bounds；无可调属性时读取 Playground 的展示方式。演示先确认当前组件核心 UX，Anatomy 核对稳定职责与简短名称，空预览补查首次加载／刷新，均归既有九项，不增加报告列。

涉及移除交互或空预览时，按 [移除与空预览](gallery-page.md#移除与空预览) 判断真实移除及共享恢复入口。

只读路径记录具体位置、证据、原因和可执行建议；实施路径完成授权修改与对应验收。排序约定涉及 Skill 写回时，按 [排序约定的维护](property-model.md#排序约定的维护) 处理，沿用已有明确许可。

## 4. 验证与交付

先用专题自带验收条件检查受影响结果，再按 [验证与恢复](verification.md) 选择相称的项目检查。修复本次变更引起且在范围内的问题，重验受影响部分；第一版实现不是默认停止点。机器检查不能替代设计价值、依赖语义、映射或实际交互判断。

设计系统校验、组件检查或批量审计按 [统一校验报告](audit-report.md) 输出矩阵和编号问题列表；普通实施任务报告本次修改与验证，不强制运行完整审计。交付范围、修改或建议、关键依据、实际验证和未解决项；恢复临时预览并清理临时展示。未运行的检查明确标为未验证。

仅维护本 Skill 时，按改动选择 [依赖与页面回归](../tests/dependency-routing.md)、[命名回归](../tests/design-axis-naming.md)、[动画轴回归](../tests/animation-design-axes.md)、[渐进读取回归](../tests/progressive-disclosure.md)、[九项标准与报告回归](../tests/component-audit.md) 和 [展示语义回归](../tests/display-semantics.md)；普通 Gallery 任务不读取维护测试。

## 停止与局部阻塞

- 无法定位目标且缺少必要证据时，请求最少的缺失输入；仅缺约定文档不停止。
- 映射、默认选择或依赖存在会实质改变结果的歧义时，只暂停受影响项；契约和证据能唯一确定时直接处理，不擅改 API 消除展示问题。
- 某项需要未授权写入时，先完成独立可执行的取证、建议和获授权工作，报告受阻操作。
- 必要验证失败且无法在范围内修复时保留证据、交付局部结果；工具缺失不能记为通过。
