# 九项标准与统一报告回归

仅供 Skill 维护。按入口、工作流、Components 九项或其他页面标准以及统一报告逐项走查；表格检查只证明结构，不能替代模型回放或真实组件验证。

| 请求与事实 | 应选择的路径与可观察结果 |
| --- | --- |
| “检查设计系统的 Docs、Styles 和 Button。” | 最上层分别进入其他页面与 Components；Docs、Styles 不套组件章节，Button 覆盖九项。报告中组件矩阵与其他页面表分开，问题编号全报告唯一。 |
| “只把 Button 图标换成 Placeholder。” | Components → Playground → 示例内容；不审查全部代码、不强制填完整审计表。 |
| “单独校验 Button 的 Playground。” | 读取 Playground 三组适用标准；输出固定九项列，其他未检查项标待验并交代范围，不为了表格扩大全量检查。 |
| “完整校验多个组件。” | 每个组件一行，首列组件名，后续严格按九项顺序；完整检查覆盖九项的适用性与结果，不遗漏代码；不检查关联覆盖。 |
| “一个 Playground 同时有 Reset 和图标问题。” | 同一 cell 分别写两个唯一编号和简述，表后每个编号完整展开，不填数字 2 表示问题总数。 |
| “Properties 继承错误，同时影响 Playground 体验。” | 主要修复位置归属 Properties，详情提及关联影响，不为同一缺陷在多列重复计数。 |
| “Anatomy 不适用，但必有 Usage 缺失。” | Anatomy 有依据填 —；Usage 分配缺陷编号，不能也填 —。 |
| “只能读源码，动画过程未观察到。” | 相关行为填待验；可确认的源码缺陷仍编号，不能用截图或类型检查判整个维度通过。 |
| “Dialog 需要独立触发，现有 Interactive Demo 能重复打开。” | 按可选演示标准判断必要性与共享呈现，验证触发、关闭、再次打开及键盘；不套旧版禁止独立 Demo 的规则。 |
| “新增 Anatomy、Usage 和 Best Practices 内容。” | 分别核对可见部位层级、具体使用场景和可执行建议；不把内部 DOM 或泛泛口号当内容通过。 |
| “父组件组合已展示子组件。” | Composition 核对常见真实组合，不替代 Properties，也不自动改变公开导出。 |
| “组件没有关联卡片。” | 不作为缺陷，不检索关联覆盖，不要求补 Announcement 卡片，不添加第 10 列占位。 |
| “MDX 中现有链接目标失效。” | 在页面结构／MDX 或对应内容项记录链接问题，不能借此恢复关联覆盖检查。 |
| “修复后再次校验同一报告。” | 问题列表保留原编号和复验结果，矩阵表达当前状态；不得静默删除已修复问题或将待验写为通过。 |

| “动画效果、遮挡或焦点表现无法从源码确定。” | 对对应疑点使用浏览器；未观察的必要运行项标待验，纯文档及源码结论不连带待验。 |
| “用户明确要求浏览器逐页验收。” | 遵循用户范围与适用项目强制检查，源码优先不覆盖该要求。 |

| 给定事实 | 预期判断 |

| 给定事实 | 预期判断 |

## 示例语义回归与 4.13.0 走查

下列为给定事实的语义案例，不是项目固定组件清单；正式判断规则维护在实例数量、交互归属及 Anatomy 专题。

| 给定事实 | 预期判断及九项归属 |
| --- | --- |
| Bar Chart 的默认 render 同时 map 普通、正负混合、全负值三组图表，每条 Properties 又复用整组。 | Playground／Properties 不通过：默认一个图表，每个 value 一个对应图表；混合与全负值若仅验证健壮性归测试。不能因三张都加载成功或尺寸正常判展示合理。 |
| Content Group 负责排列／包裹／裁剪调用方提供的项目，并复用子组件展示溢出提示。Collapsible 仅管理展开／收起。 | 两者 Anatomy 均为 —；调用方项目、复用子组件、辅助溢出机制、trigger／panel 或 DOM wrapper 不构成拆解理由。Composition 的真实依赖说明独立判断。 |
| Checkbox 的同一位置在 checked 显示 Checkmark，indeterminate 显示 Mixed Indicator，二者职责相同且互斥。 | Anatomy 合并为稳定的 Indicator 一行，直白说明 checked 勾号和 indeterminate 横线；图形差异归属性状态，不按渲染分支拆行。 |
| File Chip 可点击，Gallery 的回调却另造预览浮层或成功消息。 | Playground／Interactive Demo 按交互归属判问题：点击遵循 Button，保留可点击外观和原生反馈，默认无副作用承接，不额外打开伪预览；自身关闭／移除仍真实运行。 |
| 组件组必须包含两个项目才有选择关系，或 Composition 明确比较两种配合方式。 | 多实例有明确成立条件或比较目的可保留并说明，不机械删成无法工作的一个子项。 |
| 同时存在且承担不同职责的自身图标区与操作区。 | 可分别作为 Anatomy 部位；状态形态合并不意味着把所有部位合为一个。 |
| 为解释独立组合职责，调用方显式提供预览并交代归属。 | 可在相应 Interactive Demo／Composition 中真实演示，沿用共享方式，不反向要求所有默认实例添加效果。 |
| 组件自身选择／展开／关闭未更新，却用无副作用回调解释。 | 不通过；内在状态与回调契约必须真实运行，无副作用规则只约束调用方决定的效果。 |
| 移除后整个预览为空，当前属性与主题已修改。 | 继续使用 4.12.0 共享唯一 Restore，恢复内容并保留设置，不新增逐组件反馈或恢复按钮；顶部 Reset 契约不变。 |

维护者逐项追踪既有九项入口、Playground、代码行为、Anatomy、Interactive Demo、Properties 到对应细则与验收；源码优先、关联覆盖排除、动画轴、移除与共享 Restore 均保留。本记录为文档语义走查，未进行独立模型回放或 AaronUI-Web UI 测试，不代表来源项目已修复。
