# 设计轴命名路由回归

维护新增／改名设计轴路由时使用。正式规则见 [命名预检](../references/component-api-design.md#设计轴命名预检)；本文件只提供任务输入和可观察判定，不建立项目通用映射。

| 请求与给定事实 | 预期路径与结果 |
| --- | --- |
| “升级 Reply 组件，自己增加设计属性。”项目已声明 type → contentType，新轴两侧值均为 single/multiple，组件 API 不改名。 | 新增轴入口 → §4 → 命名预检。先确认属性名映射；编辑器、可访问名称、Caption 与文档显示 type；调用使用 contentType。切换每个值及 Reset 后名称、默认值和渲染分支正确。不能因值相同或 API 未改而跳过。 |
| “把刚才漏掉的 contentType 设计名称改对，并检查其他属性。”另有 status、expanded 直接对应。 | 仅在该组件范围核对全部轴；type 映射到 contentType，status/expanded 直接对应，不凭惯例把 status 改成 state。回调、数据载荷不自动成为设计轴。 |
| “新增视觉轴。”项目已有 style → variant。 | 定义轴前读取映射；设计侧使用 style，调用侧使用 variant，原生 style 仍接受样式对象。 |
| “所有组件的 contentType 都改成 type。”无其他语义或映射证据。 | 不按代码字段机械改名；先区分设计展示和公开 API，并核对项目事实。只修改当前已授权且依据明确的部分。 |
| “只调已有 size 轴的顺序。” | 进入排序规则，无需扩展为全部轴命名审查。 |
| “只换默认占位文字。” | 进入示例文案规则，不引入无关映射或 API 改动。 |
| “API 说明里的 contentType 能不能出现？” | 可在明确的 API 用法／集成说明中出现；不能混入设计轴名称。 |

4.4.0：维护者逐项走查入口 → 工作流 → §4 → 命名预检及映射验收；新增轴、不改 API、同值异名进入预检，排序／占位局部任务不扩大范围。此为文档语义走查，未进行独立模型回放，不保证未来执行必不遗漏。
