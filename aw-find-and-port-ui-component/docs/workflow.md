# UI 组件查找与移植工作流

本文档是执行 AW Find and Port UI Component 时优先读取的文本工作流，也是 `workflow.svg` 的语义事实源。SVG 是与本文档同步的可视化投影。

## 输入与产物

- 输入：需要查找的组件行为，或用户已明确选择的实现来源和目标项目。
- 产物：Find 阶段的候选比较报告，或 Port 阶段经验证的最小移植实现；两阶段不得在同一轮自动连跑。

## 执行步骤

1. 根据请求选择唯一阶段。
   - Find：用户要发现、比较或推荐实现。
   - Port：用户已明确选择候选或给出准确来源。
2. Find 阶段先刷新目录，按行为与别名搜索，逐个验证预览、准确源码、依赖、许可证、维护状态和目标兼容性。
3. Find 阶段对所有内置来源负责，分别列出合适与不兼容候选，给出推荐与取舍，然后停在用户选择门。
4. Port 阶段重新验证选定来源及其授权，再读取目标项目指令、依赖、现有组件、样式系统、Token、测试和可选 `DESIGN.md`。
5. 优先复用或扩展现有组件，只移植当前行为与无障碍契约；新增依赖或基础 UI 系统前取得明确批准。
6. 按项目现有技术栈、样式、图标、命名和 API 约定实现最小范围，移除没有当前需求的源实现复杂度。
7. 运行与风险相称的类型检查、测试、页面检查和构建，恢复临时状态并准确报告未验证边界。

## 停止条件

- Find 完成后必须停止，直到用户明确选择候选。
- Port 来源含糊、许可证限制不清或所需行为无法验证时停止。
- 新依赖、公共 API、数据契约或可见行为需要用户选择时停止确认。
- 无法运行交互验证时不得把编译成功表述为界面已验证。

## 最终交付

Find 交付来源齐全的比较表、推荐、取舍和明确下一步；Port 交付来源、移植位置、复用与删减内容、验证结果及后续触发条件。
