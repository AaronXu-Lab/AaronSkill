# UI 组件查找与移植工作流

本文是适用判断、阶段选择、共同边界和交付状态的事实源；阶段细节按下表读取。workflow.svg 是面向人的概览，执行时无需读取。

## 适用门

仅当以下两项同时成立时使用本 Skill：

1. 工作单元是一个可识别的具体 UI 组件，可由角色、行为、现有实现或准确组件来源界定，不要求用户已经知道组件名称。
2. 请求的主要意图是发现／比较该组件的实现，或把用户已选定的准确组件实现适配进目标项目。

来源位置本身不决定适用性。同仓库分支、本地源码或独立设计应用可以成为准确组件来源；只有当请求明确指向其中某个组件实现及其目标落点时，才进入 Port。

以下任务不使用本 Skill：

- 整个应用、页面、功能域或工作区的设计迁移、重构、拆分、初始化或对齐；
- 把设计快照作为独立应用来源、建立双应用结构、复制或同步未限定到具体组件的文件；
- 仅因仓库中存在设计分支、本地参考源码或可复用组件，就把普通实现任务改写成组件发现／移植；
- 不涉及外部或本地参考实现的普通组件修复与重构。

若较大任务中另有一个明确的组件级发现或移植子任务，只对该子任务使用本 Skill，不接管整项迁移。维护本适用边界时，用 [路由回归场景](../tests/applicability-routing.md) 走查正反例。

## 选择阶段与资料

输入是待查找的组件行为，或已选定的准确来源和目标项目。根据完整会话选择一个阶段，仅加载该阶段资料：

先通过适用门，再根据完整会话选择一个阶段；不通过时不读取 Find 或 Port。

| 已通过适用门的请求 | 阶段与读取资料 | 产物与停止点 |
| --- | --- | --- |
| 发现、比较或推荐一个具体组件的实现，包括“找一个并直接实现” | Find：[查找流程](../references/find.md) | 比较候选并停止，等待用户明确选择；不修改目标项目、不安装包、不自动进入 Port |
| 要求实施，且用户已选择候选或给出该具体组件的准确预览、registry、仓库路径、源码 URL 或本地参考实现 | Port：[移植流程](../references/port.md) | 完成授权范围内的组件实现、适用验证与修复，再交付；准确来源仍需核实 |
| 仅比较一个准确组件 URL | Find | URL 本身不构成实施请求 |
| 来源只定位到应用、页面、分支、仓库或文件集合，未界定具体组件移植 | 不使用本 Skill | 按目标项目的设计迁移、项目重构或普通实现工作流处理 |

既有选择和批准持续有效，不重复询问。Find 与 Port 不在同一轮自动连跑。

## 共同证据与授权边界

- 根据请求的行为判断匹配程度，不按名称或库品牌推断兼容性。
- 目录、预览和交接记录仅提供线索；推荐或移植前，按 [来源核验](../references/source-retrieval.md) 检查准确实现、行为、许可证和传递依赖。预览与源码不一致或证据不足时列为待验证，不宣称已验证推荐；本地参考无在线预览时可用源码和行为文档建立契约，不据此宣称界面已验证。
- 新增组件框架、运行时或包前需要明确批准；沿用会话中已有批准。只有尚未解决且超出既有授权的依赖、公共 API、数据契约或可见行为选择才暂停确认，先完成独立调查与可审阅方案。
- 来源含糊、许可证限制不清或所需行为无法建立时，暂停依赖该证据的推荐或实施，报告具体缺口。许可证与兼容性判断按来源核验文档执行。

## 完成与恢复

Find 的完成标准是覆盖约定来源、区分已验证候选与待验证线索、说明推荐与取舍，并停在选择门。

Port 的完成标准是最小实现已完成、适用检查已执行、本次改动引起且可在授权范围内修复的问题已修复，并重验受影响检查。不要在第一版实现后默认停下来等评审；不重复已通过且未受后续修改影响的检查。具体检查与报告字段见移植流程。

无法运行必要检查或遇到范围外阻碍时，报告已完成内容、失败证据、未验证项和所需条件，不将部分结果标为完整完成。编译成功不能替代交互验证；不扩大授权以消除阻碍。
