# Port：移植选定实现

仅在工作流选定 Port 后读取。共同证据、已有批准、停止与修复边界见 [工作流](../docs/workflow.md)；本阶段不刷新或搜索内置目录。

## 来源与目标契约

按 [来源核验](source-retrieval.md) 重新确认用户选择的准确实现，建立所需行为、状态与无障碍契约。

读取目标项目适用的指令，检查最接近的现有实现及其消费者。围绕本次移植需要，核实框架与依赖版本、公共 API、样式与 Token、图标以及可用检查；只在这些判断需要时扩展到对应 manifest、lockfile 或配置，不固定通读整份项目资料。涉及视觉适配且存在 `DESIGN.md` 时读取相关规则；文档由代码支撑时，以代码拥有的实现细节为准。

## 最小实现

- 优先复用或扩展已有组件；不要只为匹配外部名称创建等价副本。
- 按真实页面、交互和现有组织方式决定共享组件或页面局部实现的位置。
- 将所需行为与无障碍契约适配到项目当前框架、样式、Token、图标、命名、状态与公共 API；外部实现提供行为和结构证据，不决定目标项目视觉风格。
- 删除无当前需求的变体、provider 和抽象；记录无法避免的新依赖与硬编码视觉值，新增依赖遵守工作流的授权门。

## 验证与修复

按实际变更及项目要求选择检查：

| 影响范围 | 适用检查 |
| --- | --- |
| 公共 API 或类型变化 | 可用的类型或编译检查 |
| 行为逻辑变化 | 相关现有测试，或确有必要的聚焦测试 |
| 有意义的 UI 变化 | 目标页面或组件 Gallery 的相关状态、键盘／焦点交互、视觉与控制台错误 |
| 配置、打包变化或项目明确要求 | 生产构建 |

按工作流的完成与恢复规则继续修复、重验；验证期间产生的临时 mock、日志、环境值、浏览器状态和 viewport 覆盖在结束后恢复。遇到认证、数据或运行环境限制时准确说明；不要用静态文档或编译检查宣称交互已经验证。

## 交付

报告选定来源、实际移植位置、复用内容、兼容性适配、删减内容及理由；列出已执行检查的结果与未验证边界。有明确条件会让被省略的复杂度变得必要时，说明该后续触发条件。
