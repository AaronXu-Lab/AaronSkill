# Port：移植选定实现

仅在请求通过工作流的组件粒度适用门并选定 Port 后读取。来源必须定位到具体组件实现及其目标落点；仓库、分支、本地应用或目录只有在提供这项组件级映射时才是准确来源，不能仅凭其存在启动 Port。来源可以不是 Base UI，但目标项目必须能采用 Base UI ＋ CSS Modules 规范；不绑定某个具体项目。共同证据、已有批准、停止与修复边界见 [工作流](../references/workflow.md)；本阶段不刷新或搜索内置目录。

## 来源与目标契约

按 [来源核验](source-retrieval.md) 重新确认用户选择的准确实现，建立所需行为、状态、无障碍与视觉／动效契约。区分来源中要保留的用户可见结果，以及其特有的 primitive、样式工具、主题和内部模块。

读取目标项目适用的指令，检查最接近的现有实现及其消费者。围绕本次移植需要，核实 React 与 Base UI 版本、CSS Modules 支持、公共 API、样式与 Token、图标以及可用检查；只在这些判断需要时扩展到对应 manifest、lockfile 或配置，不固定通读整份项目资料。涉及视觉适配且存在 `DESIGN.md` 时读取相关规则；文档由代码支撑时，以代码拥有的实现细节为准。

在修改目标项目前，形成具体转换判断：来源行为能否用目标项目已有组件、Base UI primitive 或原生元素实现；Tailwind CSS、StyleX 等来源样式如何写成 CSS Modules 并映射到目标 Token；哪些来源依赖可删除，哪些运行时能力确需保留。若确认会失去用户要求的视觉、动效或交互细节，说明差异与可选方案后取得二次确认。确需新增框架、运行时或包时同时说明必要性、替代方案和代价，并在同一次请求中确认。未取得所需批准前，不开始依赖该选择的转换。

## 最小实现

- 优先复用或扩展已有组件；不要只为匹配外部名称创建等价副本。
- 按真实页面、交互和现有组织方式决定共享组件或页面局部实现的位置。
- 交互适合 Base UI primitive 时组合项目已用或获批准的 Base UI 组件；纯展示与简单控件使用原生元素。不要把其他组件框架作为移植后同类交互的隐性基础。
- 将来源的 Tailwind CSS、StyleX 或其他样式写法转为 CSS Modules，映射目标项目 Token，并适配图标、命名、状态与公共 API；外部实现提供行为和结构证据，不决定目标项目视觉风格。无需为了复制来源样式而引入来源的样式框架。
- 删除无当前需求的变体、provider 和抽象；记录无法避免的新依赖与硬编码视觉值，新增依赖遵守工作流的授权门。

## 验证与修复

按实际变更及项目要求选择检查：

| 影响范围 | 适用检查 |
| --- | --- |
| 公共 API 或类型变化 | 可用的类型或编译检查 |
| 行为逻辑变化 | 相关现有测试，或确有必要的聚焦测试 |
| 有意义的 UI 变化 | 目标页面或组件 Gallery 的相关状态、键盘／焦点交互、视觉／动效与控制台错误；核对承诺保留的来源细节 |
| 配置、打包变化或项目明确要求 | 生产构建 |

按工作流的完成与恢复规则继续修复、重验；验证期间产生的临时 mock、日志、环境值、浏览器状态和 viewport 覆盖在结束后恢复。遇到认证、数据或运行环境限制时准确说明；不要用静态文档或编译检查宣称交互已经验证。

## 交付

报告选定来源、实际移植位置、Base UI／原生元素映射、CSS Modules／Token 适配、复用与删减内容及理由；说明已批准的偏差和新增依赖，列出检查结果与未验证边界。有明确条件会让被省略的复杂度变得必要时，说明该后续触发条件。
