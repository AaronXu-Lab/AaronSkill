# 适用性路由回归

仅在维护本 Skill 的 description、入口或 Find／Port 路由时使用。以下是语义走查输入与判定依据，不是另一份正式规则；规则事实源为 [适用门](../references/workflow.md#适用门)。可由维护者逐项走查，或在隔离任务中回放模型执行；报告必须区分两者，不以关键词匹配声称行为通过。

## 双应用拆分反例

请求：“在 axo-worker-desktop 将现有 qa 工作区拆分为 worker-fe、worker-design-mock、worker-runtime，并把同仓库 design-pr-0918 快照作为独立设计应用来源。”

判定：不触发本 Skill。主要意图和工作单元是工作区拆分与双应用初始化，`design-pr-0918` 只定位整套设计来源，没有界定某个组件实现及其目标组件。执行者应使用目标项目的重构或应用初始化工作流，不应声称“设计侧会按本 Skill 核对来源”。即使拆分过程复制文件或发现可复用组件，结论也不改变。

## 相邻反例与正向场景

| 测试请求 | 预期路由与判定 |
| --- | --- |
| “把 `design-pr-0918` 的页面和资源复制进独立的 `worker-design-mock` 应用。” | 不触发；来源和目标都是应用级，复制文件不等于组件移植。 |
| “参照同仓库设计应用重做任务详情页。” | 不触发；页面级设计迁移没有具体组件工作单元。 |
| “修复现有 Button 的 padding，不需要参考其他实现。” | 不触发；这是普通本地组件修复。 |
| “找一个支持搜索、分组和键盘导航的 Command Palette 组件，比较实现。” | Find；行为界定了具体组件，主要意图是发现与比较。 |
| “只比较这个 Combobox 组件的准确源码 URL 与现有实现。” | Find；准确 URL 不构成实施授权。 |
| “已选定 `design-pr-0918/src/components/Button.tsx`，把这个 Button 适配到 `worker-fe` 的共享 Button。” | Port；同仓库本地来源已准确映射到具体组件及目标落点。 |
| “拆分应用时，另请为 `worker-fe` 找一个符合这些交互要求的 Date Picker。” | 仅 Date Picker 子任务使用 Find；本 Skill 不接管应用拆分。 |

## 本次维护走查记录

1.3.0：维护者依据上述输入逐项追踪 description → 入口 → 适用门 → Find／Port 路由。双应用拆分、页面迁移、文件复制与普通本地修复均停在适用门外；具体组件发现进入 Find；已选同仓库组件实现进入 Port；大任务中的明确组件子任务仅局部适用。

这是文档语义走查，未运行独立模型回放或真实项目移植，不能证明未来模型必然执行，也不代表反例项目已被修改。
