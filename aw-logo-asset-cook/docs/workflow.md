# 应用图标资源生成工作流

本文档是执行 AW Logo Asset Cook 时优先读取的文本工作流，也是 `workflow.svg` 的语义事实源。SVG 是与本文档同步的可视化投影。

## 输入与产物

- 输入：用户明确指定的单个 SVG，或根层恰好包含一个 SVG 的资源目录，以及明确的目标目录。
- 产物：经过主题、格式和平台校验的 Web、Apple、Windows、Linux、Android、菜单栏与托盘图标资源，以及对应中文 README。

## 执行步骤

1. 只在用户指定范围内解析唯一 SVG；目录根层没有或存在多个 SVG 时列出结果并等待选择。
2. 在安装依赖、清理和生成前运行只读主题检查。
   - 双主题：保留原几何、颜色和媒体查询，继续。
   - 单主题：请求 AI 补充互补主题的明确授权；拒绝或未授权时停止。
3. 获得补色授权后，只创建临时双主题 SVG，不覆盖源文件；渲染明暗外观并复检，结果必须为双主题。
4. 检查目标项目中的 `compose-app-icon` 是否完整；缺失时先请求安装许可，安装并完整读取依赖后再继续。
5. 用明确的 `--source` 和 `--project-root` 运行生成脚本，生成最小平台资源树和与实际路径一致的 README；Apple 同时交付现代 `.icon` 与传统 macOS `.icns`。生成前检查 `iconutil`，缺失时不得清理产物。
6. 使用依赖 schema 校验 Apple `.icon`；Icon Composer 可用时渲染各外观作临时验证，不可用时准确报告跳过的引擎检查。
7. 从明色 SVG 在临时 `.iconset` 中直接渲染 16、32、128、256、512 点的 1x/2x PNG，保留源轮廓与透明度；用 `iconutil` 打包 `iOS&macOS/app.icns` 后将 16/32px 转成传统 RGB RLE 与独立 Alpha 块（规避部分 iconutil 的 ARGB 编码差异），再解包，核对完整尺寸及 RGBA 像素，临时文件不交付。`.icns` 是固定明色回退，不支持主题切换。
8. 核对主题、尺寸、Alpha、遮罩、安全区、单色状态资源和目录最小性，确认未修改产品集成代码。

## 停止条件

- 用户未明确指定源文件或目录、目录中的 SVG 不唯一时停止。
- 单主题输入未获得 AI 补色授权，或补色复检仍非双主题时停止且不得清理现有产物。
- `compose-app-icon` 缺失且用户未批准安装，或安装后仍不完整时停止。
- 任何必要格式或平台不变量校验失败时不得宣称生成完成。

## 最终交付

交付目标资源目录与根 README，报告源 SVG、主题处理、各平台校验结果、Icon Composer 可用性和未执行的产品集成工作。
