# 工作流程细则

## 1. 初始化并读取项目索引

把 `project-directory` 解析为当前任务实际使用的项目或工作区根目录，优先使用当前工作目录或项目明确根目录。数据目录固定为 `<project-directory>/data/aw-mail-read-later`，不要使用技能目录、全局软链目标或技能仓库。

如果目录、`articles.csv` 或 `feedback.csv` 任一缺失，先运行：

```bash
python3 <skill-directory>/scripts/read_later_index.py init --data-dir <project-directory>/data/aw-mail-read-later
```

确认两个 CSV 都能读取后，报告索引是“已创建”还是“已加载”。初始化或读取失败时停止本次流程，不用临时内存记录代替。修改字段或状态前先阅读 [CSV 数据结构](data-schema.md)。

如果技能目录下仍有旧版 `data/`，不要自动混用或迁移；只有用户明确同意时才复制到项目索引，且不得覆盖已有项目文件。

## 2. 同步 `Read Later` 队列

1. 使用 Outlook 的列表或搜索操作查找显示名称精确为 `Read Later` 的文件夹。先取邮件元数据，只有需要提取链接或确认上下文时才读取完整正文。
2. 提取邮件中的所有候选链接，排除退订、偏好设置、隐私政策、跟踪、社交分享、图片、像素和纯跳转链接；保留仓库、issue、discussion、pull request、论坛、博客、文档、项目、视频和课程等内容。
3. 记录 `content_type`，例如 `article`、`repository`、`post`、`thread`、`documentation`、`project`、`video` 或 `other`。
4. 在比较 URL 前调用 `canonicalize`：保留原始 URL，移除片段和已知跟踪参数，保留有实际功能的查询参数。
5. 用 `upsert` 写入新增内容和邮件元数据。已有 URL 不要重复访问，除非它是新增 URL、从未检查过或用户明确要求重试。
6. 按规范化 URL 去重：保留收件时间最新的邮件，把较早的重复邮件移到 `Deleted Items`，记录被移除邮件的主题和时间，不要永久删除。

普通推荐排除 `archived`、`deleted`、`unavailable` 和 `unavailable_pending_confirmation` 等状态，不要因为内容类型不是 `article` 而排除。

## 3. 检查候选内容

使用网页或浏览器工具打开新增或需要重试的 URL：

- 文章、博客或新闻：读取正文、标题、发布时间和可读长度；
- 仓库或代码项目：查看描述、README、主要文档、最近更新或 release，不默认阅读全部代码；
- 帖子、讨论或 issue：读取主帖、背景、关键回复和更新时间；
- 文档或项目页：查看概览、目录、关键章节和适合的阅读入口；
- 视频或课程页：读取标题、简介、时长和字幕/文字稿可用性；没有可读文字时说明限制；
- 其他内容：根据页面结构判断可读范围，并说明判断依据。

记录标题、内容类型、最终 URL、创建/更新时间、长度依据、预计投入和付费墙、登录、robots、JavaScript 等访问限制。写入元数据后，用 `check` 命令记录 `last_checked_at`。页面被拦截、需要付费或登录、已经失效或无法可靠读取时，设为 `unavailable_pending_confirmation`，排除推荐并询问用户是否删除来源邮件。

## 4. 排序并推荐

依次考虑：

1. 当前明确请求；
2. 近期对话和已保存的正面/负面反馈；
3. 当前时间与预计投入窗口；
4. 实际用处、新鲜度和可读性；
5. 内容新旧程度和类型多样性。

不要编造精确分数。只推荐一项，并给出名称、类型、直接链接、来源邮件、投入时间及估算依据、适配当前情境的理由和重要不确定性。推荐后将记录标记为 `recommended`，保存邮件 ID、更新时间和推荐次数；用户确认完成前，邮件保持在 `Read Later`。

没有既能访问又适合当前情境的内容时，说明是队列为空、超出投入窗口、已跳过还是网页不可访问，不要为了凑数推荐不可访问内容。

## 5. 阅读、总结和翻译

用户要求阅读或总结时使用网页正文，不只依赖邮件摘要。文章关注论点和证据，仓库关注用途、入口和关键结构，帖子/讨论关注问题、观点和结论，文档关注导航和可执行信息。翻译全部可读正文；代码、命令、API 名称、路径和链接保持可执行标识不变。访问不完整时准确区分已读和未读内容，不补写缺失信息。

用户明确反馈后，把原文追加到 `feedback.csv`，并记录归一化信号、上下文和时间信息。

## 6. 后续动作

- **暂时跳过：** 邮件留在 `Read Later`，记录设为 `skipped`，保存原因，当前推荐周期不再推荐。
- **完成：** 找到当前 `recommended` 记录；只有一个来源邮件时，将它移动到 `Archive`，确认成功后再设为 `archived`。有多项活动记录时先询问用户。
- **永久排除：** 将指定来源邮件移到 `Deleted Items`，确认成功后设为 `deleted`，记录用户原因。
- **无法访问：** 不自动删除；若用户拒绝删除，保留邮件并设为 `unavailable`，除非用户明确要求，否则不重试。
- **重试：** 仅在用户明确要求后重新访问，并刷新网页检查时间和访问状态。

每次修改 Outlook 前都使用最新结果中的准确邮件 ID，报告具体修改；连接器确认成功前不要改变本地归档或删除状态。
