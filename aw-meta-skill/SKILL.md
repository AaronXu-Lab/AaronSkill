# AW Meta Skill

本 Skill 是 `skill-creator` 的增量包装，提供 AW 专属交付契约；通用创建规范由当前环境的基础 Skill 提供。仅咨询或执行现有 Skill 时，不启动创建流程。

## 交付契约

每个创建或更新的目标 Skill 必须包含：

- 非空的 `metadata.version`、`metadata.author`、`metadata.creation_context`。
- `docs/workflow.md`：执行事实源，独立描述关键判断、停止条件与产物。
- `docs/workflow.svg`：与文本语义一致的人类概览，保留必要分支。
- 入口中指向文本工作流的 Markdown 链接，以及带说明的 SVG 图片引用。

交付前通过基础和 AW 两项校验，完成与变更相关的检查，报告版本变化及未验证项。版本策略、资料读取范围和失败恢复统一按 [执行工作流](docs/workflow.md) 执行。

## 目标 Skill 编写准则

创建或更新其他 Skill 时，将以下原则落实到目标文件：

- **描述短且有区分度。** 用尽可能少的文字说明能力与触发场景；只有容易误触发时才加排除边界，不用宽泛主题词或强制措辞争抢无关任务。
- **按需提供资料。** 多工作流入口保留共同约束与选择条件，按情境链接到对应文档或脚本，并说明何时读取。简单 Skill 可直接写清，不为追求路由结构而拆文件；同一规则只维护一个事实源。
- **只补充任务所需知识。** 假设执行者具备通用能力，保留领域事实、项目约束和可复用操作。以结果及关键决策为主，仅在顺序、接口或风险确有要求时固定细节，避免泛化的思考教程和冗长步骤清单。
- **让读取与验证匹配范围。** 在目标 Skill 中按任务指定相关资料和检查，不要求每次小修通读全部文件或重复运行已通过的无关测试。依赖其他 Skill 或工具应有实际需要，不默认叠加能力包。
- **准确设置授权边界。** 明确哪些操作需要何种授权，将确认放在相应操作前，沿用完整会话中已有授权。已核实隔离、无生产访问的本地流程可说明允许继续修复与重验；不能因此扩大到外部写入或其他范围。
- **定义可观察的完成标准。** 写清产物、适用验证、失败恢复及真实停止条件，让执行者完成约定范围内的实现、检查与修复。除非用户要求阶段评审，不把第一版实现设为默认停止点；开放探索也应说明边界。
- **考虑不同执行模型。** 根据实际任务保留有依据的约束，不把某代模型的能力判断写成永久前提，也不因模型更强而删除用户明确的要求。

## 按需读取

- 创建或更新：读取执行工作流；本会话已读且仍适用的规范可复用。
- SVG 创建、修改或视觉审查：读取 [SVG 规范](references/workflow-svg.md)。单纯理解流程无需读取 SVG。
