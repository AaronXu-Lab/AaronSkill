# 派发判断回归场景

用于修订分档规则时的文本走查；只检查决策，不创建会话或改动业务项目。先判断请求是否需要实施，再根据当前任务定档，并核对历史上下文是否有显著收益。

| 请求与历史 | 预期判断 |
| --- | --- |
| 查询组件库有哪些展开收起行为及其实现 | 主会话自行只读调查并回答，不派发 |
| Field Container 曾由 Astra 跨组件抽取；现按明确方案移除 Gallery 的 `control` 属性轴、将 Preview 改为虚线 Slot 占位 | 当前是局部明确修改，派 Luna · high；不继承 Astra 档位 |
| Stat Card / Stat Trend 系列曾由 Sol 实现；现需协调两者的视觉规则及关联实现点 | 若原 Sol 的上下文能显著降低衔接风险且仍可用，可派 Sol · medium，并说明当前协调范围与复用收益 |
| 某组件曾由 Sol 修改；现仅需独立、明确的单处边缘裁切 | 从 Luna · high 起评；组件名称相同不足以锁定 Sol |
| Astra 正在修改同一实现，用户补充该修改的一个小要求 | 可继续交给正在执行的 Astra，以保留现场并避免重叠写入；不把这次例外延伸到后续独立任务 |
| 当前任务要抽象通用 Collapsible 并迁移多个组件，此前仅有 Luna 的局部样式历史 | 按当前结构性范围评高档；旧的局部历史不限制新档位 |
| 只有同项目、无同组件或同能力的历史任务 | 不视为关联；从低档起评并按当前任务升档 |

## 方案明确程度与单页设计判断

先看方向与授权边界是否足以派发，再判断执行中剩余的设计和协调。以下名称仅定位真实案例，不固定该组件或任务的档位。

| 请求、已定结论与剩余工作 | 预期判断 |
| --- | --- |
| Controls' Gap 文章的正文、插入位置和验收已明确，只需沿既有文档结构新增页面 | 低档 Luna · high：按已定内容落地；不是因为只有一页而判低档 |
| 窄屏侧栏修复：外部点击关闭，Topbar toggle 始终可见且可切换；行为、适用范围及验收已定，局部实现路径明确 | 低档 Luna · high：行为已定的局部交互修复；UI 任务或需要交互校验不自动升中档 |
| Button 页新增 Usage / Composition：仍需组织语义、判断相似组件边界、去重、建立组件链接及协调共享模板；方向与范围已讨论清楚 | 中档 Sol · medium：剩余内容设计与多点协调具有实质性；一页或少量文件不能将其降至低档 |
| Controls' Gap 交互化：用户仅说参考 Buttons' Gap、多一点交互，视觉区域 / 内缩 / gap 的表达、计算反馈及组合对照仍待设计 | 当前剩余设计判断评中档 Sol · medium；先由主会话澄清关键展示方向与验收边界，足以派发后由中档在该范围形成具体方案并实施；不能因单页、相似参考或派发提示详细判低档，也不直接派复杂未定方案 |
| 上述交互化任务的派发提示很长，列出参考页、文件和校验步骤，但关键表达方式与反馈方案仍待选择 | 仍按未解决的方案不确定性评中档；提示长度和实施清单不能替代设计结论，关键方向未定则先讨论 |
| 主会话已明确同类 Gap 页的区域 / 内缩 / gap 表达、计算反馈、对照布局、数据和验收；此次仅按可复用方案完成局部实现 | 可降为低档 Luna · high：重新评估当前剩余任务，不把 Gap 交互化或同组件永久锁中档 |
| Button 页 Usage / Composition 内容、去重结论、链接目标及模板使用均已明确；此次仅同步一个独立文案或链接 | 可用低档 Luna · high：不继承原任务的设计与协调复杂度 |
| 已定方案的局部样式或文案修复仍需常规参数选择、代码阅读和必要验证 | 低档起评：少量常规判断不等于实质性设计任务，不把所有 UI 修改一律升中档 |
| 即使改动代码少，任务仍需抽象通用展示能力并重构结构、协调广泛依赖 | 高档 Astra · low：按抽象、结构和依赖复杂度判断，代码量不构成降档理由 |

走查时分别说明已定结论、剩余不确定性、影响范围、协调复杂度与派发前讨论是否足够；用预期判断检查规则，不按案例名称背记档位。模型解析场景仍需单独走查。

Claude 使用对应的 Sonnet · high、Opus · medium、Fable · low；判断原则相同。所有档位自行完成必要校验，派发仍须一次性且自包含。

## 模型解析与持久会话回归

以下为模拟平台证据的文本决策场景，不代表实时模型目录；出现的准确 ID 仅用于对应场景。修订模型选择或恢复规则时逐项走查，检查选择、允许的操作和停止边界，不向真实会话发消息。Claude 使用平台返回的真实 ID；本文不设定其版本号。

| 平台证据、用户要求与会话状态 | 预期判断 |
| --- | --- |
| Codex 目录同时列出 Sol 的 `gpt-6.1-sol`（Latest workhorse）和 `gpt-6-sol`（Previous generation），两者均支持 medium；无覆盖 | 中档选 `gpt-6.1-sol` · medium，记录证据；不沿用旧固定 ID |
| 目标环境完整目录仅有 `gpt-6-sol` 可用，官方信息确认其 Sol 系列与版本关系且支持 medium；新版本未在该环境开放 | 选 `gpt-6-sol` · medium，说明这是该环境最新可用及可用性限制；不编造新 ID |
| 仅看到旧会话的 `gpt-6-sol`；没有当前完整候选与版本证据 | 不宣称最新、不派发；报告无法确认版本，等待证据或用户明确配置 |
| 目录含多个名称相近的 ID，但未提供系列归属、先后或 latest 状态 | 不按名称数字大小推断，不跨系列替换；停止受影响操作并说明缺口 |
| 新旧 Sol 均可用，用户明确要求继续 `gpt-6-sol` · medium | 验证支持后保留旧版本，记录用户指定及范围，不自动升级 |
| 用户只指定中档或 Sol，未锁版本 | 按当前平台证据选最新可用 Sol，保持 medium |
| 旧映射及实际会话为 `gpt-6-sol` · medium，无用户锁定；目录确认 `gpt-6.1-sol` 最新且支持 medium，平台可更新且已获授权 | 复用同一会话，更新并确认 `gpt-6.1-sol` · medium 生效，报告旧 → 新并刷新映射；不另建会话 |
| 同上，但平台仅支持本次发送覆盖，且可保证该任务使用传入配置 | 在获授权的派发调用显式传入新 ID 与 medium；记录单次覆盖，后续派发仍显式设置，不谎称持久默认已更新 |
| 同上，但更新不支持、未获必要授权，或无法确认本次使用何种配置 | 暂停该会话派发，报告限制与目标配置；不默用旧模型或另建替代会话 |
| 最新 Sol 不支持 medium，旧 Sol 支持；无用户强度覆盖 | 报告强度不支持，请用户明确配置；不自动降强度、退旧版本或跨系列 |
| 旧映射指向旧版本，但用户已手动把实际会话改为可用的新版本 · medium | 核对用户配置及范围后更新映射，不把旧映射写回会话 |
| 旧会话正在执行任务，平台出现同系列新版本 | 不中断任务升级；下次获授权派发前重新解析并处理配置 |
| 更新调用失败或超时，模型是否已切换未知 | 核对实际配置；未确认前不重发实施任务，不记录为升级成功 |
| Claude 目录明确提供某档位系列的两个真实 ID、最新关系及所需强度 | 选择该系列最新可用真实 ID；不把 Sonnet / Opus / Fable 显示名或猜测版本当 ID |
| Claude 缺少某系列或无法确认其版本、强度 | 仅停止该档位操作，说明缺失，不以别的系列顶替 |

验证范围：这些场景供文本走查；结构校验不证明平台运行结果。实际工具配置变更与持久会话回放需在另有授权的执行环境验证。
