# AW Wording Reviewer 文本工作流

本文是执行事实源，描述范围、判断与完成条件。`workflow.svg` 是面向人的概览，仅更新或视觉核对流程图时读取。具体文案标准由 [规则集](rules.md) 维护；只读本次相关章节，不默认通读全部资料。

## 1. 先确定范围与任务

沿用完整会话中的目标、规则选择和授权，按以下优先级确定范围：用户指定的文件、目录、页面路由或粘贴片段；当前工作区未提交改动中含中文文案的文件；用户点名业务域对应的页面与中文词条。已明确业务域时，以该范围为限，不借未提交改动扩大目标。

- 范围无法确定或没有可审查内容：说明缺口，必要时请用户指明目标。
- 目标仅含非简体中文、代码标识符或产品信息架构：说明不适用并结束，不先读取项目资料或运行扫描。
- 扩展到用户指定范围之外需要确认；先完成范围内可做的工作。
- 默认交付审查建议。用户已要求修改时，完成修改与相关验证后再交付，不在第一版报告处停下等重复许可。

## 2. 按任务读取与收集约束

| 任务 | 读取与执行范围 |
| --- | --- |
| 单句、粘贴片段、截图文案 | 根据角色和内容读取规则集对应章节，直接审查可见文案；不为此定位整个仓库、列全部规则或创建临时工程。截图不清晰的原文标记无法辨认 |
| 指定文件或只选部分规则 | 读取所选规则及其适用例外、目标源码和相关项目约束；可机械检查的源码使用扫描器，语义复核同样限于所选规则 |
| 目录、页面或项目批量审查 | 查看规则索引，覆盖范围内适用的规则族；读取相关项目约束，运行扫描并补充语义复核。范围未涉及时间或跨组件展示时，不加载对应实现 |
| 时间或跨组件展示审查 | 读取规则集 D 或 H 的相关条目；动态显示需要检查调用链或渲染。时间审查、接入的细节见 [时间审查与接入](time-integration.md) |

单句没有项目背景时，按内置默认规则给建议；不能声称已核对项目约定。已有项目背景时，不因任务小而忽略已知约束。

源码任务遵循已生效的项目指令，并按需读取目标路径适用的 `AGENTS.md` / `CLAUDE.md` / `AGENTS.design.md`、术语表与相关设计章节。收集会影响本次判断的命名禁令、状态词、占位约定和语气规范，不要求通读无关设计文档。命名禁令提取和选择参数见 [扫描器用法](scanner.md)。自动提取可能漏掉自然语言约束，需核对相关原文。

优先级：用户显式要求 > 项目成文约定 > 内置默认规则。没有项目约束时继续；事实不足时标记待确认，不编造状态含义、错误原因、保留内容或恢复动作。

预检告知与任务规模匹配：单句或明确规则不列整套规则清单；批量任务简述范围、适用规则族及影响结论的项目例外。禁令的来源、代码命名排除项等在用户要求完整预检、出现冲突或影响结论时展开。审查请求已授权指定范围内只读扫描，无需等待额外回复；只有用户仅要求预检或明确要求等待时，交付预检后停止。

## 3. 执行相应检查

**可机械检查的源码：** 按 [扫描器用法](scanner.md) 运行指定范围和规则，核实输出与原始源码。退出码 0 表示没有机械 error，1 表示发现 error，2 表示参数或读取失败。对本次范围内可修复的调用或环境问题修复后重跑；无法排除的失败说明具体原因，不能把空输出算作通过。未改扫描器且没有环境异常时，不因换了目标仓库而重复运行扫描器自检。

**语义复核：** 读取本次适用条目的例外与上下文要求。机械零命中不能替代语义判断；不支持的文件、未提取的文本、动态拼接或复杂模板需直接核对。单句与截图可直接按规则审查，不宣称运行过扫描器。

**实现与显示复核：** 仅当所选规则涉及拼接、时间、截断、大小换算、邮箱脱敏或周期显示时检查相关实现；有可运行页面且需要确认显示行为时核对渲染。区分源码可疑点与已证实违例，不能仅凭一个时间 prop 就断言页面显示了原始时间戳。

## 4. 按已有授权完成修改

先按实际改动区分字符串项与非字符串实现项，不按文件扩展名或代码中是否带引号判断：

- **字符串项：** UI 文本或简体中文 i18n value 的措辞、标点和空格等修改，保留插值、i18n key 和其他语言；其他语言同 key 的语义若受影响则说明，不代译。
- **非字符串实现项：** 为满足文案规范而需要改变的渲染、格式化、组件配置或调用逻辑。例如时间显示需要调整 formatter 及调用处；错误提示的标题与说明分行需要调整 toast 的 `type`、`title`、`description` 配置。新增或重分配标题与说明字段、改变组件类型等配置调整，即使配置值本身是字符串，也属于实现修改；仅改现有标题或说明的措辞仍是字符串项。不能用塞入换行符等字符串变通替代必要的实现调整。

用户只要求审查时不修改；用户已要求修改文案时，先完成已授权且可独立进行的字符串修改及相关验证。发现非字符串项后，按以下顺序处理：

1. 核对完整会话中的具体授权。已有明确授权的实现项直接完成并验证，不重复确认；一般的“审查文案”或“修改文案”不自动授权实现修改。
2. 没有授权的实现项单独保留，不擅自修改，也不阻塞独立的字符串修改。字符串改写若依赖待确认实现才能成立，则保留该依赖项并说明，避免留下不成立的显示结果。
3. 已授权字符串修改完成后，单独列出待确认实现项，每项说明真实位置、当前问题、建议修改、涉及的实现及影响范围（如共享组件的其他调用方），未知影响明确标记。给出可逐项批准的清单并明确请求用户同意，不能只在最终结果中写“未修改”或将确认变成可有可无的后续动作。仅审查任务在审查结论后执行同样的提案与确认步骤，不先修改字符串。
4. 用户明确同意后，只实施获准的具体项并完成相关验证；部分批准仅处理批准项，拒绝则保留未修状态。未回复时等待实现授权，清楚区分字符串已完成与实现待确认，不能推定同意或宣称全部修复。

时间工具函数与调用处的具体接入、测试按 [时间接入边界](time-integration.md) 执行。其他实现项验证受影响的配置、调用方和实际显示；不扩大到无关结构、样式、类型或接口。

- 对源码修改以相同范围、规则和禁令参数重扫，并复核受影响的语义项；只改粘贴文案则核对改写结果即可。涉及类型化源码时运行项目类型检查；接入时间格式化器时运行相应边界测试。
- 修复本次改动引入的问题并重验受影响项；已有未修项和无法完成的检查单独说明。不重复已通过且未受后续改动影响的检查。

## 5. 交付与完成条件

按 `error` → `warn` → 建议排序，每项包含真实位置、规则 ID、逐字原文、完整改写和依据；单句可用简短的“原文 → 建议”加规则说明，不为了套报告格式增加空栏目。源码使用真实 `file:line`，粘贴片段用片段行号或字段路径，截图用可识别的界面位置，不编造文件位置。个人偏好不列为 error，缺产品事实的建议明确待确认。

机械 JSON 的 `text` 是命中片段，`original_text` 是完整提取文本；结合源码核实插值后给改写。说明实际使用的证据及影响结论的未验证项；未涉及的调用链或渲染不必列空栏目，未执行的检查不得宣称通过。

仅审查以有依据的结论为完成；已授权修改以改动、相关验证及剩余问题说明为完成。存在未授权的必要实现项时，必须单独提出具体确认请求；它们不阻断审查结论或独立字符串结果的交付，但不能仅报告后略过。无法完成必要检查时明确部分完成及阻塞，不将第一版实现或脚本零命中当作全部完成。
