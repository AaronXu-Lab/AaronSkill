# 中文 UI 文案规则集

## 规则来源与级别

本规则集与具体项目无关。排版、标点、分隔符与微文案形状是简体中文界面的通用约定；日期时间的格式契约由本 SKILL 内置的 [assets/format-time.ts](../assets/format-time.ts) 定义。项目专有的命名禁令、术语表与占位约定在进入本规则集之前就已从目标项目读取，与这里的通用规则合并后一起执行。

**级别**（标在每条规则标题最前）

- 🔴 `error`：违反即需修改。
- 🟡 `warn`：真实但存在合理例外，需要判断后决定。
- 🔵 `人工`：无法机械判定，逐条读文案裁定。

标注 ⚙ 的规则由 `scripts/check_copy.py` 覆盖，ID 一致。

**可维护的对照表**（改表即生效，不用改脚本）

| 表 | 用途 | 谁在读 |
| --- | --- | --- |
| [name-casing.csv](name-casing.csv) | 品牌与产品实体名的官方写法与错写法 | 脚本 + 人工 |
| [proper-nouns.csv](proper-nouns.csv) | 不受混排空格约束的专有名词与单一记号 | 脚本 + 人工 |
| [terms.csv](terms.csv) | 同义词收敛到哪个词，以及差别 | 人工 |

**不在本规则集范围**：emoji 与 Unicode 装饰符、AI 生成腔、假数据与占位内容、无障碍名，各有专门的 SKILL 负责。

**扫描范围**：多语言项目只检查简体中文语料。脚本按路径中的 i18n 标记（`i18n` / `locale` / `locales` / `lang` / `translations` / `messages`）识别语言目录，跳过其中的非简体中文语言，包括繁体——它们的标点与空格惯例不同，应由各自的规范约束。

## A. 混排空格

### 🔴 ⚙ A1 `space-cjk-latin` — 中文与拉丁字母之间保留一个半角空格

```
✗ Stream不可用            ✓ Stream 不可用
✗ Future超时              ✓ Future 超时
```

**例外**：[proper-nouns.csv](proper-nouns.csv) 里的写法；文件名是业务内容而非文案（`GMV看板.xlsx`、`会议录音.mp3`）。

### 🔴 ⚙ A2 `space-cjk-digit` — 中文与阿拉伯数字之间保留一个半角空格

时长与数量一律带空格：`8 分钟前`、`12 天前`、`42 秒`、`最多 50 个文件`、`30 天内`。

**例外**：格式化后的日期与时钟**内部**不拆分——`2026-07-31`、`07-28`、`14:30`、`v1.2`；以及 [proper-nouns.csv](proper-nouns.csv) 里的单一记号。

注意边界：`年 / 月 / 日` 作为**内容词**而非日期格式时，本规则照常生效——`2026 年度报告`、`2019–2021 年的历史资料`、`2024 年大促` 都带空格。「日期除外」只指日期与时钟这两种格式化产物的内部。

### 🔴 ⚙ A3 `space-before-cjk-punct` — 全角标点前后不留空格

全角标点自带字宽，再加空格会出现视觉空洞。

```
✗ 由 Agent ，执行          ✓ 由 Agent，执行
```

## B. 分隔符与拼接

### 🔴 ⚙ B1 `middot-spacing` — 分隔符写作 ` · `，前后各一个半角空格

同一对象的多个并列事实用 ` · ` 串联。

```
✓ 成功 · 8 分钟前 · 生成价格异常表
✓ 启用中 · 下次运行 明天 09:00 · 最近成功 8 分钟前
✗ 正在执行「摘要」· 张三     ✓ 正在执行「摘要」 · 张三
```

**例外**：音译人名内部不加空格（`克里斯朵夫·李维`）；`·` 作为独立节点由 CSS 控制间距时（`<span className={styles.dot}>·</span>`），字符串本身不含空格是正确的。

### 🔴 ⚙ B2 `middot-dangling` — 分隔符只由拼接处写出

分隔符属于拼接逻辑，不属于任何一段文案。写进 i18n 词条会在缺少后续片段时留下悬挂的点。

```
✗ "docCount": "个文档 ·"
✓ "docCount": "个文档"
  拼接侧：[`${count}个文档`, extra].filter(Boolean).join(' · ')
```

词条**中间**出现 ` · `（两侧都有实义文案，如 `飞书 · 新消息 · {{eventFilter}}`）是允许的整句翻译。

### 🔴 ⚙ B3 `list-separator` — 并列事实之间用 ` · ` 串联

```
✗ 水平内边距 | 垂直内边距 | 图标尺寸
✓ 水平内边距 · 垂直内边距 · 图标尺寸
```

`—`（em dash）保留给两处用途：代码注释头（`/** FileTypeIcon — 说明 */`），以及独立出现时作为空值占位符（见 D5）。

### 🔴 B4 `max-three-segments` — 一条 ` · ` 链最多 3 段

需要表达更多事实时改用换行、独立 meta 行或字段列表，不追加第 4 段。

### 🔴 B5 `filter-empty-segments-before-join` — 拼接前过滤空段

`[a, b, c].filter(Boolean).join(' · ')`，避免产出 ` ·  · ` 或首尾悬挂。

## C. 标点

### 🔴 ⚙ C1 `fullwidth-punct` — 中文句子内使用全角标点

`, → ，`　`. → 。`　`; → ；`　`? → ？`　`: → ：`　`() → （）`

句内并列名词用顿号 `、`：`该文件可能已被移动、归档或删除。`

括号内是拉丁词或数字时也保持全角：`（可选）`、`（占位）`、`（Linux）`。

**例外不算违例**：` · ` 分隔符；表示择一的斜杠（`读写/只读`、`日历/联系人`）；代码、路径、URL、查询参数、文件名、纯英文句子里的 ASCII 标点；CSV 数据行；技术单位标注。

### 🔴 ⚙ C2 `fullwidth-colon-space` — 全角冒号后不加空格

```
✗ 下次运行： 明天 09:00     ✓ 下次运行：明天 09:00
```

标签独立成元素时冒号仍写在标签末尾：`时区：`、`连接器：`。

### 🔴 ⚙ C3 `ellipsis-three-dots` — 省略号固定写作三个半角点 `...`

`...` 标记**这句话还没结束**，有两种用法：

- **动作还会进入下一步交互**——点击后打开对话框、选择器或后续步骤，而不是当场完成。
- **状态正在进行中**——过程尚未结束，界面稍后会给出结果。

```
✓ 新增凭证...        点击后打开凭证对话框
✓ 移动到...          点击后打开目录选择器
✓ 加载中...          过程未结束
✓ 正在生成节点...
✗ 新增凭证…          单个 … 是半个省略号，不使用
✗ 任务规划中。。。
```

当场完成、不进入下一步的动作不加 `...`：`保存`、`删除`、`归档`。已经结束的状态也不加：`已创建`、`运行失败`。

### 🔴 ⚙ C4 `no-exclamation` — 界面文案不使用感叹号

成功、完成、欢迎类提示用陈述句收尾：`创建成功！` → `已创建`。

### 🔴 ⚙ C5 `cjk-quote-style` — 引号按被引对象选择

| 引号 | 用途 | 示例 |
| --- | --- | --- |
| `「」` | 界面对象、目录名、状态名、用户输入的短语 | `已归档「${name}」`、`可在设置的「已归档」中恢复` |
| `《》` | 协议、政策与正式文件名 | `《用户协议》`、`《隐私政策》` |
| `“”` | 整句引文：人说的原话、外部来源的原文、消息正文的转述 | `他回复：“这批数据下周补。”` |
| `‘’` | 只用于 `“”` 内部的二层引用 | `他说：“系统提示‘凭证已失效’。”` |

界面对象与整句引文的区别是**被引的东西是不是一段话**：状态名、按钮名、文件名是对象，用 `「」`；有主语谓语、能独立成句的内容是话，用 `“”`。

```
✗ 可在“已归档”中查看       ✓ 可在「已归档」中查看
✗ 当用户提到"约会议"时      ✓ 当用户提到「约会议」时
```

半角 `"` 与 `'` 不作为中文文案的引号，它们只是代码里的字符串定界符。脚本只判 `“”` 与 `"` 包裹的短语式引用，整句引文不会被误报。

### 🔴 ⚙ C6 `trailing-period` — 句末句号按停顿数判定

判断依据是**停顿数**，不是长度，也不是「像不像一句话」。停顿只算 `，` 与 `；`；顿号是并列，不计入。

- **短句（停顿 ≤ 1）不加 `。`**
- **含两处以上停顿的成句说明用 `。` 收尾**

`label` / `name` / `title` / `message` / `confirmText` / `cancelText` / `actionLabel` 走同一条判定。按钮与标签几乎都是短句，实际表现就是不加句号——**G1 的「句末不加标点」已并入本条**，G1 只保留句式要求。

```
✗ title="没有需要重新配置的连接器。"
✓ title="没有需要重新配置的连接器"
✗ message="归档后项目只读，历史记录与文件仍会保留，可随时恢复"
✓ message="归档后项目只读，历史记录与文件仍会保留，可随时恢复。"
✓ label="支持 PDF、Word、Excel 三种格式"
```

**例外**：疑问式标题是确认弹窗的既有句式，`？` 不算违例——`取消这次运行？`、`停用「X」？`。以 `...`、`：`、`，`、右引号右括号或插值结尾的片段不判「缺句号」。

**机械覆盖范围**：脚本只判上列名词性与动作性角色。`description` 的成句与否要读语义，留给人工复核——单句说明结尾加不加 `。` 往往是项目的既有惯例而非笔误，机械改写会伤到大量正确文案。

### 🟡 C7 `slash-alternatives` — 斜杠表示择一而非并列

`读写/只读` 表示择一；陈述并列事实用顿号或 ` · `。

### 🟡 C8 `percent-attached` — 百分号紧贴数字

`42%` 而非 `42 %`。

## D. 日期与时间

**格式契约的事实源是本 SKILL 内置的 [assets/format-time.ts](../assets/format-time.ts)**，审查时按它判定，不需要读目标项目的实现。产品中所有时间戳都应经统一的格式化函数输出，不在页面里手写格式。

目标项目没有统一格式化器时，可以把该文件整份迁移进去——**迁移前必须取得用户许可**，流程见 SKILL.md。

### 🔴 ⚙ D1 `date-format` — 字面格式

| 场景 | 格式 | 示例 |
| --- | --- | --- |
| 绝对日期 | `YYYY-MM-DD` | `2026-07-31` |
| 绝对日期 + 时间 | `YYYY-MM-DD HH:mm` | `2026-07-31 14:30` |
| 融合时间，同年 | `MM-DD` | `07-28` |
| 融合时间，跨年 | `YYYY-MM-DD` | `2025-11-04` |
| 时钟 | 24 小时制 `HH:mm`，补零 | `09:00`、`14:30` |

```
✗ 2026年7月31日 / 2026/07/31 / 2026.07.31
✓ 2026-07-31
```

日期与时钟之间恰好一个半角空格。12 小时制只在用户偏好开启时由格式化器输出 `2:30 PM`，不在文案里硬写。

### 🔵 D2 `datetime-three-modes` — 模式选择

三种模式对应用户要回答的两类问题——「距离基准时间多久」与「具体何时发生」：

- **Relative（相对）**：`刚刚`、`3 分钟前`、`12 天前`。用户首先关心新旧与是否需要立即处理时用——消息列表、活动动态。不单独承担需要精确引用的时间证据。
- **Absolute（绝对）**：`2026-07-31 14:30`。需要准确定位、跨人沟通、回溯复核时用——交易记录、审计日志。
- **Hybrid（融合）**：前天到后天窗口内用自然日称谓 `昨天 14:30`，超出后切绝对日期 `07-28`。通用记录的默认候选。

**同一信息流中的同类时间点必须用同一模式**，不按页面局部偏好变化。

### 🔴 D3 `relative-vocabulary` — 相对时间措辞

`刚刚`（<1 分钟，过去）、`即将`（<1 分钟，未来）、`前天 / 昨天 / 今天 / 明天 / 后天`、`N 分钟前`、`N 小时前`、`N 天前`。数字与中文单位之间按 A2 加空格。**当天用「今天」**。

### 🔴 D4 `schedule-copy-format` — 调度文案

`每天 09:00`、`每周一 10:00`、`每 10 分钟`。

### 🔴 ⚙ D5 `empty-value-em-dash` — 字段值缺失时显示 `—`

全角破折号 U+2014，单独占据该字段。en dash `–`（U+2013）留给区间（`1–32 个字符`、`2019–2021 年`）。

**注意语义分层**：列表或区块的**空状态**是另一回事，用「暂无 X」或「还没有 X」（见 G4）。字段空值与空状态各用各的形态，不互相代替。

## E. 用词与命名

### 🔴 ⚙ E1 `name-casing` — 品牌与产品实体名使用官方写法

对照表在 [name-casing.csv](name-casing.csv)：第一列是官方写法，第二列是需要报错的错写法，`|` 分隔。**新增一行即生效，不用改脚本。**

表里既有品牌名，也有被当作产品实体名使用的普通英文词（如 `Skill`）——它们在中文文案里只有首字母大写一种正确写法，全大写往往是标识符或文件名的写法漏进了文案。

**这张表是参考，不是全集。** 脚本只能命中表里登记过的错写法，表外的品牌照样可能写错——人工复核时仍要逐个看文案里出现的品牌名，发现新的错写法就补进表里。

中文句子里有中文官方名的产品用中文名（`飞书`、`钉钉`、`企业微信`、`豆包`），这类也记在同一张表里，第一列写中文名。**`Lark` 不是错写法**——它是飞书海外版的正式名称，面向海外的文案里用 `Lark` 是对的。

只在含中日韩字符的文案里按单词边界匹配。全小写形式只能作为 ID、枚举值或资源文件名（`connectorId: 'github'`），不进入展示文案。

### 🔵 E2 `terminology-convergence` — 同义词收敛

同一概念在一个产品里只用一个词。收敛到哪个词、近义词之间差在哪，见 [terms.csv](terms.csv)。

目标项目有成文术语表时以项目为准，`terms.csv` 只作缺省参考。两处都没覆盖的组，在项目文案里统计各写法的出现次数，跟随占优的一方；两方接近时标记为待用户裁定，不自行定案。

## F. 语气与人称

### 🟡 ⚙ F1 `anthropomorphism` — 不把 AI 拟人化

用「系统分析」「Agent 执行」「关键节点由人确认」「执行过程可追踪」这类可验证的行为描述。

```
✗ 我来帮你收集这个品牌的图标资源。
✓ 正在收集该品牌的图标资源，并行检索多个来源。
```

**例外**：会话消息气泡内**模拟的 Agent 回复正文**允许第一人称。

### 🔴 F2 `no-hype-words` — 紧凑理性的陈述句

禁止铺垫、形容词堆叠与炒作话术：一键、赋能、极致、无缝、颠覆、革命性、黑科技、秒级、强大的。

### 🔴 ⚙ F3 `personal-pronoun` — 人称代词

| 人称 | 规则 | 示例 |
| --- | --- | --- |
| 第二人称单数 | 用「你」，不用敬语「您」 | `你的凭证已失效` |
| 第二人称复数 | 不用「你们」「大家」「咱们」 | 面向多人时仍写「你」或省略主语 |
| 第一人称单数 | 只用于物主表达 | `我的文件`、`与我共享`、`我的空间` |
| 第一人称复数 | 产品不自称「我们」 | ✗ `我们会尽快处理`　✓ `稍后自动重试` |
| 第三人称 | 指代对象时写对象名，不用「它 / 他 / 她」 | ✗ `它已归档`　✓ `该项目已归档` |

界面文案的默认视角是「对你说话」，主语能省则省——`先完成授权` 比 `你需要先完成授权` 更短也更清楚。系统以「我」自称属于拟人化，归 F1。

**机械覆盖范围**：脚本判「您 / 您们 / 咱 / 咱们」。「我们」「它」这类要看是产品自称还是引文转述，留给人工复核。

## G. 微文案形状

### 🔴 G1 `button-verb-first` — 按钮

2–6 个汉字，不用「请」，不写成带逗号的整句。执行动作用动词开头；导航链接与模式选择可用名词短语。会进入下一步交互的动作按 C3 加 `...`。句末标点由 C6 判定，本条不再重复。

```
✓ 取消　删除　归档　解绑　新增凭证...
```

### 🔴 G2 `confirm-button-repeats-verb` — 确认按钮重复标题动词

不用「确定」「确认」「好的」「是」作主操作文案。

```
✓ title="永久删除「X」"   主按钮「永久删除」
✓ title="停用「X」？"     主按钮「停用」
```

**例外**：单按钮通知型对话框用「知道了」；编辑表单型对话框用「保存」「创建」「完成」。

### 🔴 G3 `confirm-body-consequence` — 确认弹窗正文

以「<动词>后……」开头写清会发生什么，并补一句说明**哪些东西不受影响或仍会保留**；不可逆操作显式写「无法恢复」或「无法撤销」；正文成句以 `。` 收尾。

```
✓ 归档后项目只读，不能承接新任务；历史记录与文件仍会保留。
✓ 知识库及其处理结果将被永久删除。原文件不会删除。此操作无法撤销。
```

### 🔴 G4 `empty-state-two-registers` — 空状态两种语域不得互换

- **从未产生过内容**：`暂无 X` 或 `还没有 X`
- **筛选或搜索后无结果**：`没有符合条件的 X` 或 `没有匹配的 X`

```
✓ title={filtering ? '没有符合条件的设备' : '还没有设备'}
```

判据必须真的是「是否处于筛选态」，不能绑到别的开关上。空状态标题不加句号，描述句加句号。

### 🔴 G5 `error-names-object-and-action` — 错误点名对象与动作

写成 `<具体对象><具体动作>失败`；对象在上下文中自明时可省略。禁止裸的「操作失败」「未知错误」「系统错误」「请求失败」，不把 HTTP 层概念暴露给用户。

```
✓ Workflow 删除失败　凭证保存失败　解除关联失败
```

校验类错误必须点名出错的节点或字段。

### 🔴 G6 `error-fix-clause-in-description` — 出路放 description

可恢复的失败必须带 `description`，把下一步动作放在其中；不把出路塞进 title（title 因此不含逗号），也不只给 title 不给出路。

```
✓ title: '项目读取失败'  description: '请稍后重试'
✗ title: '复制失败，请手动选择复制'（无 description）
```

### 🔴 G7 `toast-perfective` — 成功反馈用完成体

`已<动词>`、`<对象>已<动词>` 或 `<动作>完成`，说已经发生的事实。不用「成功」，不用进行时。

```
✓ 已复制　已创建「X」　已生成草稿
✗ 正在创建中
```

已在界面上直接可见结果的操作不再补 toast。

### 🔴 ⚙ G8 `placeholder-qing-prefix` — 输入框占位符

用裸动词短语，「请输入 X」只用于表单**校验错误提示**。

```
✓ 输入名称　搜索任务　搜索成员、部门或成员组
✗ 请输入项目名称　请选择
```

格式有讲究时给具体示例更有效：`例如：每天 09:00、每周一 10:00、每 10 分钟`。

### 🔴 G9 `title-noun-no-punct` — 标题与表头

名词短语，不加标点。
