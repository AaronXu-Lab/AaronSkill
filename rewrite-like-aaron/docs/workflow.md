# Aaron 文风改写工作流

本文档是执行 Aaron 文风改写 Skill 时优先读取的文本工作流，也是 `workflow.svg` 的语义事实源。SVG 是与本文档同步的可视化投影。

## 输入与产物

- 输入：AI 中文草稿、通用表达稿或 Aaron 的零散笔记，以及可选的体裁与改写要求。
- 产物：保留事实、立场、经历、不确定性和 Markdown 结构，同时去除通用 AI 痕迹与表面模仿的可直接使用终稿。

## 执行步骤

1. 完整读取声音模型和反 Slop 规则；按体裁读取模式参考，必要时再读取示例。
2. 建立不可改动清单，区分事实、作者亲历、明确判断、推测、外部观点和原稿未提供的信息。
3. 选择主文章模式和语气强度，不把语气提高到原稿证据无法支持的程度。
4. 找出真实触发点、核心矛盾、观察与解释的边界，以及文章希望读者形成的判断。
5. 先重建论证：删除聊天残留、宏大开场、假权威、模板结构和重复总结，让抽象判断由细节、机制、成本或边界支撑。
6. 再克制地校准声音；第一人称、口语、短句、反问、英文和类比只在承担逻辑或情绪功能时保留。
7. 完成两轮反 Slop 审计：先检查通用 AI 痕迹，再检查是否过度表演 Aaron 风格；本地文件同时运行审计脚本。
8. 默认只交付终稿；只有用户要求过程说明，或原稿存在事实缺口、立场风险时才附简短说明。

## 停止条件

- 关键事实、立场或引用身份无法判断且会影响正文时，用明确占位或向用户确认，不自行补写。
- 不得把推测写成事实、外部观点写成亲历，也不得编造场景、情绪、对话、数字或失败经历。
- 如果改写稿比原稿更像在表演人格，回退声音特征并重新审计。
- 原稿已自然且符合作者声音时少改，不为证明 Skill 生效而重写。

## 最终交付

交付保留原有信息边界和有效 Markdown 结构的终稿；确保论证可追溯、语气匹配体裁、无明显 AI 模板，也无口头禅式 Aaron 模仿。
