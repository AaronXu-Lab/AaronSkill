# 文章模式

先选主模式，再决定是否需要少量借用辅模式。不要把所有模式拼进一篇文章。

## 1. 实践复盘与技术教程

适用于工具配置、开发记录、设计流程和踩坑。

优先结构：

1. 为什么开始做。
2. 原本的设想或目标。
3. 实际怎么做。
4. 哪一步与预期不符。
5. 原因如何被定位。
6. 当前解法、限制和下一步。

语气：

- 直接、具体，中等或偏低情绪。
- 用第一人称标记操作和判断。
- 保留工具名、参数、数字和失败现象。
- 可以承认暂时没有解决。

避免：

- 把教程升级成行业革命。
- 每一步都插入感想。
- 用“简单三步”掩盖真实复杂度。
- 在末尾重复一遍全文。

## 2. 产品体验与设计分析

适用于产品评测、交互建议和体验报告。

优先推理单元：

```text
具体场景 → 用户当时想完成什么 → 现状造成什么摩擦
→ 摩擦背后的机制 → 建议 → 如何判断建议有效
```

一篇文章可以多次使用这个单元，但不要让每个问题拥有完全相同的标题和篇幅。

语气：

- 站在真实使用者和设计实践者的交界处。
- 先描述实际体验，再调用理论。
- 建议应包含取舍，不把个人偏好包装成通用规律。
- 对未亲自走完的流程明确说明。

避免：

- 为每个问题强配“期望、现状、方案”三件套。
- 滥用“认知负荷”“心智模型”等术语。
- 只凭漂亮截图推断完整业务。

## 3. 观点评论与趋势分析

适用于 AI 工作流、行业变化和产品方向判断。

优先结构：

1. 从具体变化或争议进入。
2. 找出最值得讨论的矛盾。
3. 用产品、流程或组织案例展开。
4. 讨论成本、适用条件和反例。
5. 给出带边界的当前判断。

语气：

- 允许更鲜明，但仍以机制支撑。
- 可以使用真正的问题作为章节转轴。
- 可以留下未解决的张力。

避免：

- “时代正在发生巨变”的宏大开场。
- 先写结论，再找三个例子证明。
- 把预测写成必然。
- 用金句替代机制。

## 4. 个人随笔与文化评论

适用于成长、工作经历、漫画、影视和生活记录。

优先结构：

1. 从具体时刻、记忆或即时反应进入。
2. 保留作者真实的困惑、好恶和前后变化。
3. 从作品或经历中的细节生长出解释。
4. 在情绪真正抵达的位置结束。

语气：

- 可以更口语、更不规则。
- 允许短句、括号、俚语或少量 emoji，但必须得到原稿支持。
- 不必把所有矛盾解决干净。

避免：

- 把私人感受学术化。
- 为增加灵魂而编造回忆和身体感受。
- 连续制造电影预告式短句。
- 把作品评论写成“主题思想分析”。

## 5. 资讯整理与发布解读

适用于模型发布、功能更新和外部资料摘要。

优先结构：

1. 先交代发生了什么。
2. 保留来源、关键数字和原话。
3. 解释读者可能不熟悉的概念。
4. 只对作者确实有依据的部分给出反应。

语气：

- 事实优先，速度感可以较强。
- 允许少量吐槽或判断调节密度。
- 对价格、指标和发布日期保持精确。

避免：

- 为每个 bullet 都补一句意义。
- 把官方宣传原样扩写。
- 以“未来可期”收尾。

## 6. 推荐、清单与轻度推广

适用于工具、网站、软件或作品推荐。

优先信息：

- 谁适合用。
- 真实价格、限制和使用门槛。
- 为什么作者自己会选它。
- 与相近选项相比的具体取舍。

语气：

- 可以轻松，但不要像带货文。
- 允许简短评价，不需要每项都完整成段。

避免：

- 五星、emoji、粗体和感叹号同时堆叠。
- “必备神器”“闭眼入”等无条件推荐。
- 把自家产品伪装成中立结论。

## 混合模式

只在内容确实跨体裁时组合，例如：

- 实践复盘为主，产品分析为辅。
- 文化评论为主，个人随笔为辅。
- 资讯整理为主，观点评论为辅。

让主模式决定结构，辅模式只影响局部。不要平均分配。
