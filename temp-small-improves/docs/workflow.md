# 小型界面优化工作流

本文档是执行 `temp-small-improves` 时优先读取的文本工作流，也是 `workflow.svg` 的语义事实源。SVG 是与本文档同步的人类可视化概览；两者不一致时以本文档为准并同步修订 SVG。

## 输入与产物

- 输入：用户显式调用本 Skill 的请求，以及界面、设计稿、截图、原型、实现代码、运行状态或设计系统证据中的任意有效组合。
- 产物：14 条规则的适用性与问题判断、最小优化建议；用户明确要求修改时，还包括已实施改动和相称验证。

## 执行步骤

1. 检查当前请求是否明确点名 `$temp-small-improves`、`temp-small-improves` 或要求调用本 Skill。
   - 没有显式调用：停止使用本 Skill，不把它自动附加到普通设计或前端任务。
   - 已显式调用：继续。
2. 根据用户动作确定模式。
   - “检查、审查、建议”等请求进入只读审查模式。
   - “优化、修复、调整、实现”等请求进入实施模式。
   - 只调用但未说明动作时，默认只读审查。
3. 收集目标表面的当前证据：主要任务、相关状态、交互频率、输入方式、屏幕尺寸、平台能力、现有组件、Token 和动效约定。只有会改变判断的材料缺失时才标记“待验证”或请求补充。
4. 完整读取 [判断与优化规则](rules.md)，逐条记录 `不适用 / 已满足 / 建议优化 / 待验证`。不能仅凭规则名称或某个孤立代码片段判定问题。
5. 对“建议优化”项设计最小改动：优先复用既有系统；合并相互关联的修复；检查可访问名称、焦点、键盘、触控、状态反馈和减少动态效果偏好；不得改变业务逻辑或扩张为整体改版。
6. 按模式处理：
   - 审查模式：输出证据、判断和建议，不改动目标。
   - 实施模式：只实施证据支持且处于用户授权范围内的改动。
7. 验证相关状态与尺寸。动效和交互至少检查中断或快速反向操作、重复高频操作、进入与退出、键盘或触控路径，以及减少动态效果偏好；排版和布局至少检查代表性宽度与真实内容。
8. 交付命中规则、位置、理由、最小改动和验证结果；无命中项时明确报告不需要修改，不制造无意义 diff。

## 停止条件

- 当前请求没有显式调用本 Skill 时，不得执行这套检查。
- 证据不足以确认问题时停止该条结论并标记“待验证”，不猜测缺失实现。
- 建议与现有设计系统、平台惯例、可访问性或产品语义冲突时，不机械套用规则；记录不采用原因。
- 用户没有授权修改时停在审查结果，不实施文件、设计或外部系统变更。
- 验证发现布局回归、不可中断动效、焦点丢失、可读性下降或减少动态效果失效时，撤回该项方案或继续修正，不能把它标记为完成。

## 最终交付

审查交付包含检查范围、证据、规则状态、命中问题、最小建议和待验证项。实施交付还包含实际修改、验证结果与剩余风险。所有规则均不适用或已满足时，明确交付“未发现需要修改的小型优化”。
